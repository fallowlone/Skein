<Explanation>

## Two jobs, not one

A running app does one job well: handle one thing at a time, fast. Add a user, record a purchase, update a like count. These are tiny, frequent writes — and the app's database is tuned for exactly that.

Asking questions across *all* the data is a completely different job: scan millions of rows, group them, add them up, compare last week to this week. If you do that on the live database, you fight with the real users for the same machine. So data engineering builds a **second place** for the heavy questions, and a **path** to keep it filled with fresh data.

## Events in, tables out

Think of it as a small factory:

- **Events in** — raw facts as they happen: "user 7 bought item 42 at 9:01am". Messy, repetitive, one at a time.
- **Reshape** — clean it up, drop duplicates, join in extra facts (item 42 is "coffee", costs $4), and bucket it the way analysts ask: by day, by country, by product.
- **Tables out** — tidy tables built for questions, sitting in a separate analytics store so heavy queries never touch the live app.

The pipe that carries data from "in" to "out" is called a **pipeline**. Building, running, and trusting that pipeline is the heart of the job.

## Why a separate place at all

It would be simpler to keep everything in one database. But the live app needs to stay fast for users, and analysts need to run slow, sweeping questions. Those two needs collide on one machine. Splitting them — fast writes here, heavy reads there — is the single idea this whole pillar is built on. The rest of the climb is *how*: how to move data (ELT and ETL), how to store it cheaply for scanning (Parquet), how to keep answers fresh (materialized views), and how to search and match it (search and vectors).

<Recap lang="en">
A running app is tuned for tiny fast writes; answering questions across all the data is a different job that would choke the live database. Data engineering solves this by moving and reshaping data — raw events in, a pipeline cleans and buckets them, and tidy tables come out in a separate analytics store. The rest of this pillar is how: ELT and ETL, Parquet, materialized views, search, and vectors.
