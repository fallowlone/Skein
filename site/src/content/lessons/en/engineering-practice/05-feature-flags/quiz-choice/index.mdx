  choices={[
    { label: "The rollout is not sticky. Each request re-rolls the bucket instead of hashing a stable key (userId plus a groupId) into a fixed 0–99 bucket, so the same user lands on different variants across requests — flickering UI and garbage experiment data.", correct: true },
    { label: "25% is too low; bumping to 50% will stop the flicker.", misconception: "Widening the rollout changes how many users are in, not whether a given user stays in. A non-sticky 50% rollout flickers just as badly — the fix is deterministic per-user bucketing, not a higher percentage." },
    { label: "The SDK is evaluating against stale config and needs a shorter poll interval.", misconception: "Poll interval controls how fast a flag change propagates, not per-request consistency. Even with instant propagation, a non-sticky hash re-rolls each evaluation and flickers." },
    { label: "The CDN is caching the old UI for some requests.", misconception: "Caching could explain a stale asset, but the symptom is a user flapping between variants on live evaluations — the signature of non-deterministic bucketing, which is exactly what a stable hash key fixes." },
  ]}

  choices={[
    { label: "A flag is checked many times per request path. A network round-trip per check would add latency and make the flag service a hard dependency — if it is down, your app is down. <Recap lang="en">
The through-line: deploy and release are separate events, and a flag is the switch between them — ship dark, release by toggle. The four types (release, ops/kill-switch, experiment, permission) have opposite correct lifespans, so type is recorded, never guessed. Rollout must be sticky (hash a stable key into a fixed 0–99 bucket) or variants flicker and experiment data rots; evaluation is a local hash lookup so a flag-service outage degrades gracefully. And every live flag is a branch in production — N flags mean 2^N configurations — so the discipline is lifecycle: expire release flags, label kill-switches permanent, and delete stale flags before one becomes the next Knight Capital.
</Recap>
