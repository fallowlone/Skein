You are not paying once per step — you pay to re-read the whole transcript on every step. If each step adds ~k tokens, step N reads ~N·k tokens and the run total is 1+2+…+N, quadratic in N. So a 15-step task is ~8–9× a 5-step task, not 3×, and latency climbs too because each call waits on a bigger prompt; a ten-cycle reflexion loop has been measured at ~50× a single pass. But the cap is a seatbelt, not a steering wheel: if the agent routinely hits it, that is hiding a real bug, and even a cap of 25 lets a quadratic loop run up a serious bill. So a senior adds independent exits: a wall-clock or token budget that actually caps the dollar figure regardless of step count; a progress/dedup check that breaks the loop when the last few steps repeat the same tool with the same arguments; and per-tool retry limits so a failing tool can't be hammered forever. With no dedup or progress check that is an infinite loop made of perfectly valid calls — the classic $12 trace. The fix is structural: cap retries per tool, detect identical consecutive calls and break or inject a 'you are repeating yourself, stop' message, and make 'I cannot find this, here is what I tried' an acceptable terminal answer rather than a failure the model must keep fighting." },

An open-ended agent lets the model decide the steps at runtime, which is necessary only for tasks you cannot enumerate in advance; it costs nondeterminism, quadratic token growth, higher latency, and a large surface for the loop to thrash or run away. The tradeoff is autonomy against control, cost, and predictability — so give the model freedom only where it earns its keep.
