The frames are a typed lifecycle, not raw text. message_start carries the envelope (id, role, empty content) — open the assistant bubble and start the TTFT timer. content_block_start opens a block and tells you its type, text or tool_use, so you decide whether to render or buffer. content_block_delta arrives many times carrying a text_delta or input_json_delta — append each to the accumulator. content_block_stop closes the block, the point where tool JSON is safe to parse. Calling JSON.parse on any intermediate buffer throws a syntax error, so the contract is: append every delta into a string buffer and parse exactly once, after content_block_stop, when the document is guaranteed complete. You may display the partial string as a 'calling tool…' hint but must not act on the arguments before then. The classic production bug is a proxy or SDK adapter (LiteLLM has shipped such regressions) that drops or misroutes the input_json_delta frames: the tool call still arrives but its input is an empty {} and your function runs with no arguments. If a tool fires with empty args, suspect a layer between you and the model swallowing the deltas before blaming your own accumulator." },

Compare full Last-Event-ID resume against the pragmatic default, and say which you'd ship.", a: "SSE is built to reconnect: the server can attach an id: to each event, and on a dropped connection the browser reissues the request with a Last-Event-ID header so the server can resume after the last delivered event. The pragmatic and honest senior default is to treat a dropped stream as a repeatable whole-turn retry: design for the stream dying at token 200 of 400, make a fresh request safe to repeat via idempotency, and re-ask the turn. You ship the retry-the-turn approach for almost everything; you build Last-Event-ID resume only when re-running a turn is genuinely too expensive or non-idempotent to repeat." },

For a normal page that is an optimization; for SSE it is fatal — the client receives zero bytes until the model finishes, so TTFT collapses back into total time and the spinner hangs for the full generation. The same trap appears in CDNs, serverless platforms with response buffering or size/time limits, and any gzip layer that waits for enough bytes to compress. The signature is unmistakable: streaming works on localhost but batches all-at-once in staging/prod. The fixes live in the path config, not the app: on nginx set proxy_buffering off, proxy_http_version 1.1, clear Connection, raise proxy_read_timeout; when you can't edit the proxy, send X-Accel-Buffering: no and Cache-Control: no-cache on the SSE response and disable compression on that route." },
