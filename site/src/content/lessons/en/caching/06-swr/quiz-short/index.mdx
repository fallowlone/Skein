    { q: "What is the background-refresh stampede, and how do you prevent it?", a: "A naive edge fires one background revalidation per request that finds an entry stale. If a popular key expires while it is taking thousands of req/s, the edge launches thousands of simultaneous refreshes at an origin that expected one — a self-inflicted thundering herd. The user does not wait, but the origin still receives every refresh, so its latency and 5xx rate climb just like a foreground stampede. The fix is single-flight: the first stale request triggers exactly one refresh, everyone else is served the stale value until it lands (Cloudflare marks the key UPDATING). Add jitter to refresh timing so many keys do not expire and revalidate in lockstep, which would just move the herd to the next instant." },

The discipline is a hard ceiling: a finite SWR window and a finite stale-if-error window. Bounded staleness is the contract that makes the whole pattern safe; without the bound, 'serve stale' degrades into 'serve wrong, forever.'" },
