<Explanation>
<strong>The syscall cost problem</strong>
Every read(), write(), recv(), send() syscall requires a user→kernel→user context switch. On Linux 6.x, this costs ~0.5-2 μs per syscall. At 100k ops/sec, that's 50-200 ms/sec spent just on syscall overhead — one full CPU core saturated on switching, not actual work.

<strong>Syscall batching solutions</strong>
1. **Vectored I/O**: readv()/writev() and recvmsg()/sendmsg() handle multiple memory ranges in one syscall
2. **Message batching**: sendmmsg()/recvmmsg() send/recv multiple UDP packets in one syscall
3. **io_uring**: Linux's modern async I/O interface that submits N operations to a shared ring, amortising the entry/exit cost

<strong>io_uring in detail</strong>
io_uring uses two mmap'd ring buffers:
- Submission Queue (SQ): user submits operation descriptors (read, write, etc.)
- Completion Queue (CQ): kernel posts results
In default mode: one io_uring_enter() syscall processes all SQ entries
In polled mode (IORING_SETUP_SQPOLL): kernel thread polls SQ → zero syscalls per op
Result: at 1M ops/sec, traditional syscalls burn ~1 ms/sec on context switches; io_uring polled mode brings this to near zero.

<strong>Observability for batching systems</strong>
Production batching needs four key metrics:
1. **Batch size histogram**: are batches actually filling (size-limited) or timing out (time-limited)?
2. **Batch wait time**: how long did items wait in buffer before shipping? (p50, p99, max)
3. **Buffer depth gauge**: current items in-memory; spikes indicate downstream backpressure
4. **Drop count**: items dropped due to buffer overflow; should be 0, >0 is backpressure signal

Dashboard: time series of all four with alerts on drop count > 0 and buffer depth > 80% cap.
Without these, batched systems are opaque; with them, they're debuggable in production.

</Explanation>

<Recap lang="en">
Syscall batching (readv/writev, sendmmsg/recvmmsg, io_uring) amortises the fixed cost of context switches. Observability is critical: track batch size histogram, wait time, buffer depth, and drop count to tune the window and detect backpressure. Senior engineers treat syscall overhead as a first-class performance metric.
</Recap>
