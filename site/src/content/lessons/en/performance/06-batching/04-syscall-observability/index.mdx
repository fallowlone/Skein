<Explanation>
Traditional POSIX I/O is one syscall per operation: read(), write(), recv(), send(). Each costs ~1-5 μs context switch. For a service doing 100k I/O ops/sec, that's 100-500 ms/sec spent in syscall transitions alone. Batched syscalls reduce this overhead.

<strong>io_uring fundamentals</strong>
io_uring (Linux 5.1+) uses two ring buffers, mmap'd shared between user and kernel:
- Submission Queue (SQ): user pushes operation descriptors here
- Completion Queue (CQ): kernel posts results here
In polled mode (IORING_SETUP_SQPOLL), a kernel thread polls the SQ continuously — user can submit operations with zero syscalls. Result: at 1M ops/sec, traditional read/write would burn ~1 ms/sec on syscalls alone; io_uring polled mode brings this to near zero.

<strong>Per-runtime batching primitives</strong>
Every major runtime ships batching APIs:
- Node.js: stream.cork()/uncork() for batched writes, setImmediate/process.nextTick for micro-batching
- Go: bufio.Writer for buffered writes, channels + ticker for time-windowed batching
- Java: BufferedOutputStream, async-profiler's writer queue
- Python: asyncio.Queue with batched consumers
- Rust: tokio mpsc channels with batching adaptors
Each provides bounded buffer, max-size + max-wait, explicit flush.

<strong>Observability for batching</strong>
Production-grade observability tracks four per-batch metrics:
1. Batch size histogram — are batches actually filling or hitting timer? p50/p99 in records/bytes
2. Batch wait time — how long items waited before shipping
3. Buffer depth gauge — current items in in-memory buffer (spikes = downstream backpressure)
4. Drop count — items dropped due to buffer overflow (should be 0; non-zero = backpressure signal)
Dashboard: time series of all four with alerts on drop count > 0 and buffer depth > 80% cap.

<strong>Why io_uring matters</strong>
Beyond raw performance, io_uring enables new patterns:
- Linked operations: next SQE runs after previous completes
- Buffer selection: kernel picks from registered buffer pool (avoids per-op buffer registration)
- Fixed files: skip per-syscall file descriptor lookup
Adoption: PostgreSQL 17 added io_uring backend, Ceph has experimental support, Netflix async-profiler reports 5-15% CPU reduction on TLS proxies.
Security note: io_uring has had CVEs (CVE-2023-2598, CVE-2024-0582); some container runtimes disable it by default via seccomp.
</Explanation>
