<Explanation>
The core batching insight is timeless: when fixed cost per operation dominates (headers, syscalls, ACKs), group operations to pay that cost once instead of N times. The only design question is the window size — how long to wait or how big to grow.

<strong>Nagle's algorithm: the original batching tradeoff</strong>
John Nagle's RFC 896 (1984) introduced what's now called Nagle's algorithm: TCP buffers small outbound segments until either an ACK is received or the buffer fills to Maximum Segment Size (MSS) bytes.
  • Motivation: 1-byte telnet keystrokes → 40-byte TCP/IP header per byte of data → 97.5% overhead
  • Mechanism: delay small writes, hoping more arrive to fill the segment
  • Tradeoff: interactive apps wait for next write or ACK, hurting tail latency
  • Escape hatch: TCP_NODELAY socket option disables Nagle; modern protocols (HTTP/2, gRPC) typically set TCP_NODELAY and do application-level batching instead

<strong>The latency-throughput Pareto frontier</strong>
Every batching system traces a curve: x-axis = batch wait time, y-axis-1 = throughput, y-axis-2 = latency.
  • No batching: lowest latency, throughput limited by fixed cost
  • Infinite batching: max theoretical throughput, latency = ∞ for first item
  • Senior workflow: define SLO latency ceiling → find largest batch window under it → throughput-maximizing operating point
  • Adaptive systems track this curve dynamically; static systems tune once

<strong>Batch coalescing and request deduplication</strong>
Specialized pattern for cache/lookup workloads: when concurrent requests ask for same key, coalesce into one batch.
  • Classic example: cache miss handling
  • Worker A misses cache for key K, starts loading from DB
  • Worker B also misses for K → joins A's pending request instead of duplicating work
  • Returns same result to both
  • Implementations: singleflight (Go), Caffeine's AsyncLoadingCache (Java), request collapsing in Varnish/CDN
  • Production impact: hot cache miss with 100 concurrent requests → 1 DB query instead of 100 → prevents thundering-herd
  • Combined with batch loading (DataLoader): "all requests in this 10ms window for any combination of keys → one batched DB query"

<strong>Why this matters today</strong>
The lineage from Nagle 1984 → Kafka linger.ms (2011) → io_uring submission queues (2019) is one continuous pattern:
  • Fixed cost: TCP header → network round-trip → syscall transition
  • Lever: amortize fixed cost across N operations
  • Question: what window size maximizes throughput without breaking SLO tail latency?
  • Answer: measure fixed vs variable cost, tune window to latency SLO ceiling
</Explanation>
