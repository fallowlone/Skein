Instead you ask the KMS to generate a data key; the KMS returns it both in plaintext and wrapped (encrypted under a key-encryption key that never leaves the KMS). You encrypt your payload locally with the plaintext data key, then discard the plaintext data key and store only the wrapped data key beside the ciphertext. To decrypt, you send the wrapped data key back to the KMS, get the plaintext data key, and decrypt locally. This scales because the KMS only ever processes tiny fixed-size keys, never your multi-megabyte payloads, so you do not hit its request size or rate limits, and your plaintext never crosses the network to a third party. Rotation also gets cheaper: rotating the key-encryption key only requires re-wrapping data keys, not re-encrypting every payload." },

That changes incident response in two ways. First, blast radius: a stolen reporting credential cannot do damage outside its scope, so a compromise is contained to what that one role could already do.
