    { label: "Nothing — HttpOnly cookies are immune to every web attack.", misconception: "HttpOnly blocks JS reads (XSS theft) but not the browser auto-sending the cookie cross-site. That's exactly the CSRF surface a localStorage token didn't have." },

  lang="en"
  question="A breach dumps your users table. Which storage choice means 'they'll get a few trivially weak passwords and then give up,' rather than 'everything common is cracked by Monday'?"
  choices={[
    { label: "Argon2id (or bcrypt cost 12+) with a unique per-user salt, tuned to a few hundred ms per hash. A slow, memory-hard, salted KDF makes offline guessing economically impossible at scale.", correct: true },
    { label: "SHA-256 with a per-user salt.", misconception: "The salt defeats rainbow tables but SHA-256 is still fast — a single GPU does ~22 billion/s, so dictionary and common passwords fall in hours. Speed is the bug for passwords." },
    { label: "SHA-256 with a server-wide pepper kept in env.", misconception: "A pepper helps only while it stays secret, and SHA-256 is still GPU-fast. If the pepper leaks (it's a secret you must manage), you're back to fast unsalted-style cracking." },
    { label: "AES-encrypt the passwords with a key in the app config.", misconception: "Encryption is reversible and the key tends to leak with the breach (often in the same repo/config). Passwords must be hashed with a slow KDF, never encrypted." },

<Recap lang="en">
The through-line of the whole track is one threat model: a single sensitive request passes through transport, authentication, authorization, input handling, secrets, and supply chain — and the breach lives in the seam, not inside any one layer. AuthN proves who; AuthZ decides what they may touch (A01). An OIDC ID token identifies the user while the access token authorizes the API, validated by signature, iss, aud, exp. A JWT is trustworthy only when you pin the algorithm. Moving a token to an HttpOnly cookie trades XSS theft for CSRF, closed with SameSite plus a token. Passwords need a slow, salted, memory-hard KDF. And the install step is your real attack surface — scope packages, pin a registry, enforce lockfile integrity.
</Recap>
