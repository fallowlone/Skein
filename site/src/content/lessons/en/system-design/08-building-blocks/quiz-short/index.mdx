UUIDv4: 122 random bits, decentralized and unguessable, but random keys fragment a clustered B-tree (page splits, lost cache locality). Snowflake: 64-bit, high-bit ms timestamp + 10-bit machine ID + 12-bit sequence — compact, sortable, ~4M ids/sec/node. UUIDv7: 128-bit, high-bit ms timestamp + random — standardized (RFC 9562), universally supported, sortable, no machine-ID.     { q: "State the bloom filter's guarantee, the mechanism, and where it must not be used.", a: "Guarantee: 'definitely absent' is always correct (no false negatives); 'maybe present' carries a tunable false-positive rate. Mechanism: an m-bit array + k hashes; add sets k bits, query checks them — any 0 means absent, all 1 means maybe. ~10 bits/element gives ~1% false positives; size for n or the array saturates. It can't delete (shared bits → use a counting or cuckoo filter). Use it as a fast pre-check in front of ground truth (skip a certain-miss DB read); never as the sole authority for a harmful 'yes' (already-used coupon), where a false positive wrongly rejects a legitimate action." },

Length = precision; a shared prefix usually means physical proximity, so a prefix range scan on an ordinary index returns a neighbourhood. Boundary problem: because it cuts fixed global ranges (and follows a Z-order curve that jumps at seams), two points a few metres apart across a cell edge can get unrelated codes — a single-cell query misses a close neighbour. Fix: query the cell PLUS its 8 neighbours (3×3 grid), then rank by exact distance. S2 (Hilbert curve) and H3 (equidistant hexagons) refine locality and neighbour math." },

Split-brain is two leaders at once, from a network partition or a GC pause/VM stall that outlasts the lease — a frozen node wakes up still acting as leader. No timeout fixes this (none tells dead from frozen). A fencing token does: a monotonically increasing number per grant that the protected resource enforces by rejecting any lower token, so a revived stale leader's writes are structurally refused." },

<Recap lang="en">
If you could reconstruct each answer from memory, you hold the unit's spine. The **rate limiter**: token/leaky bucket smooth bursts, fixed windows spike 2× on the boundary, sliding windows fix it, and the distributed-counter **race** needs an **atomic** increment-and-check (fail open, reject with 429). **ID generation**: auto-increment fails at scale (central bottleneck or per-shard collisions), so use a **time-ordered** scheme — Snowflake (64-bit) or UUIDv7 (128-bit) — which is sortable and index-friendly but leaks time and depends on the clock. The **bloom filter**: no false negatives, a tunable false-positive rate, ~10 bits/element for ~1%, no deletion (counting/cuckoo), and never the sole authority for a harmful 'yes.' **Geohashing**: prefix ≈ proximity for an indexed scan, but the **boundary problem** forces querying the cell plus its 8 neighbours. **Leader election**: consensus or a lease, with **split-brain** defeated only by a **fencing token** at the resource — never a longer timeout. The thread: reach for the right block, then get its subtle correctness core right.
