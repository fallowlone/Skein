## Snippet 1 — nested calls and stack depth

```typescript
function inner(): void {
  let c = 3;          // inner's only local
}

function outer(): void {
  let b = 2;          // outer's only local
  inner();            // pushes inner's frame
}

function main(): void {
  let a = 1;          // main's only local
  outer();            // pushes outer's frame
}

main();
```

## Snippet 2 — parameter passing (pass-by-value)

```typescript
function bump(x: number): void {
  x = x + 100;        // reassigns bump's own copy of x
}

function main(): void {
  let v = 1;
  bump(v);            // argument 1 copied into bump's x
  // what is v here?
}
```

  choices={[

    { label: "v is 101, because bump added 100 to it.", misconception: "bump added 100 to its own copy x, not to v. With pass-by-value the argument is copied into the callee's frame, so the caller's variable is never modified by reassigning the parameter." },
    { label: "v is undefined, because bump consumed it.", misconception: "Passing a value as an argument does not consume or remove the caller's variable. main's v keeps its original value 1 throughout." },
    { label: "v is 100, because x is reset to 0 in the new frame before adding 100.", misconception: "x is initialised to a copy of the argument (1), not 0, so x becomes 101 inside bump — but that lives in bump's frame and never flows back. main's v stays 1." },
  ]}

## Snippet 3 — recursion depth

```typescript
function sumTo(n: number): number {
  if (n === 0) return 0;        // base case
  return n + sumTo(n - 1);      // recursive case
}

sumTo(4);
```

    { label: "One frame, reused for each recursive call; returns 10.", misconception: "Each recursive call pushes a new independent frame holding its own n; the n = 4 frame is suspended at 4 + sumTo(3) until the whole chain returns. Five frames coexist at the deepest point." },
    { label: "Four frames; returns 10.", misconception: "The base-case call sumTo(0) also pushes a frame before returning 0, so the peak is five frames, not four — even though it adds nothing to the sum." },
    { label: "Five frames; returns 0 because the base case returns 0.", misconception: "The base case contributes 0, but each suspended frame adds its own n as the chain unwinds: 0 + 1 + 2 + 3 + 4 = 10. The base case only stops the descent." },
  ]}
/>

## Snippet 4 — missing base case

```typescript
function blow(n: number): number {
  return n + blow(n + 1);   // no base case: n only grows
}

blow(0);
```

<Quiz

  question="What happens when blow(0) runs, and what is the underlying cause?"
  choices={[
    { label: "It crashes with a stack overflow. blow always recurses with a larger n, so no call ever satisfies a stopping condition; frames pile up until the fixed stack region (1-8 MB) is exhausted and the OS terminates the program.", correct: true },
    { label: "It returns a very large number once n gets big enough.", misconception: "There is no base case and n only increases, so no call ever returns a plain value to start the unwind. Nothing is ever summed — the program crashes before returning anything." },
    { label: "It loops forever without crashing, like a while(true).", misconception: "Unlike a loop, each recursive call consumes a new stack frame. The stack is finite, so it overflows and crashes within milliseconds rather than spinning indefinitely." },
    { label: "The compiler refuses to build it because the recursion is infinite.", misconception: "Compilers generally do not prove a base case is reachable; this builds fine. The failure is a runtime stack overflow, not a compile error." },
  ]}
/>

<Recap lang="en">
Every snippet is read by running the stack in your head: nested calls keep all callers' frames live below the active one; a copied argument means reassigning a parameter never touches the caller's variable; a recursive call pushes a new frame per level so peak depth is the number of nested live calls (including the base case); and a recursion with no reachable base case grows the stack without bound until it overflows. Trace push-on-call, pop-on-return, and the answers fall out.
</Recap>
