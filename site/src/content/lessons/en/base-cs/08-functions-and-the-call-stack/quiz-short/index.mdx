    { q: "What is a function at the machine level, and what exactly does a CALL instruction do?", a: "A function is a named block of consecutive instructions starting at a fixed address in memory; the name is a convenience the compiler resolves to that address. A CALL is a special jump: it saves the return address — the address of the instruction right after the call site — and then sets the program counter to the function's first instruction. When the function finishes, RET reads that saved return address and jumps back, so control resumes exactly where the caller left off. Because the return address is saved per call, one body at one address can serve callers from anywhere and return correctly to each." },
    { q: "What does a stack frame contain, and when is it pushed and popped?", a: "A stack frame (activation record) is the block of cells the runtime reserves for one function call. It holds the return address and all of the function's local variables (and its parameters). It is pushed when the function is called — the stack pointer moves to reserve space — and popped when the function returns — the stack pointer moves back, freeing those cells for reuse. At any moment the stack holds exactly one frame per active call." },
    { q: "Why is the call stack LIFO, and what does that imply about which frame finishes first?", a: "The call stack is last-in-first-out because of how calls nest: the most recently called function must finish before its caller can continue. If main calls outer which calls inner, inner's frame is on top and is popped first; outer resumes and is popped next; main resumes last. A caller's frame is never popped while it has an active callee above it — it sits suspended below, waiting. So the newest frame is always the next to go." },
    { q: "How do parameters get into a function and how does a return value get out, and why is pass-by-value safe?", a: "At the CALL, the caller's arguments are copied into the new frame as the parameters, where they behave like pre-filled local variables. When the body reaches return, the value is placed in a CPU register; RET fires, the frame is popped, and the caller reads the value from that register. Pass-by-value (the default for primitive numbers) copies the argument, so the callee has a private workspace — reassigning a parameter changes only the callee's cell and never the caller's variable. Parameters carry data in at CALL; the return value carries one value out at RET." },
    { q: "What is the difference between a local variable's scope and its lifetime, and what happens to it when the function returns?", a: "Scope is where in the code a name is visible — a local's scope is its own function body, so no other function can name it. Lifetime is how long it exists in memory — a local is created when its frame is pushed and destroyed when its frame is popped. On return the frame is popped and the cells are freed for reuse, so the local ceases to exist as a named value; reaching those cells afterward would be a use-after-free bug. This is why two functions can both declare x with no conflict: each x is a separate cell in a separate frame." },
    { q: "What is recursion in terms of the stack, what are its two parts, and what causes a stack overflow?", a: "A recursive function calls itself; each self-call is just another CALL to the same address that pushes a new, independent frame with its own parameters. It has two parts: the base case (a condition that returns a value without recursing — the bottom of the descent) and the recursive case (a self-call on an input closer to the base case). The chain grows downward until the base case fires, then unwinds as frames pop. If the base case is never reached, frames accumulate without bound until the fixed stack region (about 1-8 MB) is exhausted and the OS terminates the program with a stack overflow — within milliseconds, since each call costs nanoseconds." },
