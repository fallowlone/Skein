## Everything is bits, and the loop never stops

Deep down, a computer only knows two states: on and off, written as **1** and **0**. A single one of these is a **bit**. Numbers, text, images, your code — all of it is just long patterns of bits. There is nothing else down there.

The computer keeps these bits in **memory**: a huge row of numbered slots, each holding a small value. Some of those slots hold **instructions** — single, dead-simple orders like "add these two numbers" or "copy this value over there." The processor runs one endless loop: read the instruction at the current spot, do it, move to the next. That loop is the whole machine.

- **Bit** — one on/off value (1 or 0); the smallest piece of everything.
- **Memory** — a long row of numbered slots holding bits.
- **Instruction** — one tiny order the processor can carry out.
- **Program** — a list of instructions sitting in memory, run in order.

## Why a programming language exists at all

Writing raw instructions in 1s and 0s is unbearable for humans. So we write in a **programming language** — words like `if`, `print`, `repeat` — that read almost like a recipe. But the computer cannot run those words directly. Another program (a translator) turns your language into the tiny bit-instructions the processor actually understands. Your friendly code and the machine's loop are two ends of the same thing: the language is for you, the instructions are for the machine.

This is why this track is worth it. Once you know that every program is just instructions over bits in memory, run in a loop, the rest of computing — variables, loops, files, even bugs — stops being a list of facts to memorize and becomes obvious consequences of that one simple picture.
