    { q: "What is a variable, in terms of a name, a binding, and a cell?", a: "A variable is a human-readable name bound to a memory cell. The name (like 'score') is a source-code label; it carries no value and is never stored in the cell. The cell is the physical location in memory that holds the value. The binding is the link between the two, kept in the runtime's symbol table: when code mentions the name, the runtime looks up the bound address and reads or writes there. The name and the value are different kinds of thing — the name is fixed once declared, the value in the cell can change many times. Declaring a variable reserves a cell and records the name-to-address binding." },
    { q: "Explain assignment as a machine operation, and why '=' should be read as 'gets' rather than 'equals'.", a: "Assignment is a store operation with two ordered steps: first evaluate the right-hand expression to a concrete value, then write that value into the cell bound to the name on the left, overwriting and destroying whatever was there. The left name is never read as a value — it is resolved to a destination address. Reading '=' as 'equals' is wrong because 'x = x + 1' is not an equation (it would be impossible); it is the command 'x gets x + 1' — read the current x, add 1, write the result back into the same cell. The right side is fully evaluated before any write happens, so self-referential assignments are safe." },
    { q: "What is mutation, and how does state differ from the history of mutations?", a: "Mutation is an in-place change to a cell: an assignment overwrites the bit pattern at an existing address, leaving the address unchanged and the previous value gone. State is the complete snapshot of the current values held by all live variables at one instant — a photograph of every cell right now. State is the cumulative result of all prior mutations, not the list of those mutations: a counter can reach 10 by one big step or ten small ones, giving different histories but identical state. Every assignment changes exactly one cell, so the rest of the snapshot is unaffected." },
    { q: "Contrast copy (value) semantics with reference semantics. What sits in the cell in each case?", a: "Primitives — number, string, boolean, null, undefined — are small enough to sit directly in the cell as their value bits. Assigning one to another copies those bits, so each variable holds an independent value and changing one never affects the other. Objects and arrays are compound values that live on the heap; the variable's cell holds only a reference — the heap address of the object. Assigning an object to another variable copies that address, not the object, so both cells end up pointing at the single underlying object. The deciding question for any bug is always: does this cell hold a value or a reference?" },
    { q: "What is aliasing, why does it cause surprising bugs, and how do you avoid it?", a: "Aliasing is two (or more) variable names holding the same reference, so they point at one shared object on the heap. It bites because a mutation through one name (obj2.field = x) is immediately visible through every other alias (obj1.field reads it back) — code that 'never touched obj1' appears to have changed it. The fix is to make an explicit copy when you want independence: a shallow copy like { ...obj } or [...arr] gives a new top-level object, though nested objects inside are still shared (that needs a deep copy). Recognising that assignment shares rather than copies objects is what turns these from mysteries into expected behaviour." },
    { q: "What exactly does const protect, and what does it NOT protect?", a: "const seals the binding after the single initial assignment: the cell can never be re-pointed, so 'x = somethingElse' throws. That is all it does. const does not freeze the value behind the binding. For a primitive there is nothing more to change anyway. But for an object, const only fixes which reference the cell holds — the object on the heap is fully mutable, so 'obj.field = 1' and adding properties are allowed. To make the contents immutable you need a separate mechanism such as Object.freeze; const alone guards the binding, not the object." },
