```js
const sum = 0.1 + 0.2;
console.log(sum);            // ?
console.log(sum === 0.3);    // ?
```

## Snippet 2 — the integer that stops counting

```js
const big = 9007199254740991;   // Number.MAX_SAFE_INTEGER
console.log(big + 1);           // ?
console.log(big + 1 === big + 2); // ?
```

  question="What does this print, and what is the underlying cause?"
  choices={[
    { label: "9007199254740992, then true. Above 2^53 a 64-bit double has no spare mantissa bits for consecutive integers, so big + 1 and big + 2 round to the same representable value — integer precision is lost.", correct: true },
    { label: "9007199254740992, then false — every integer is still distinct.", misconception: "Beyond MAX_SAFE_INTEGER the double's 52 mantissa bits cannot separate consecutive integers, so big + 1 and big + 2 collapse to the same value and the comparison is true, not false." },
    { label: "It overflows and wraps around to a negative number, like a fixed-width C integer.", misconception: "JS numbers do not wrap; the single double type has no fixed integer width to overflow. Instead the value loses precision — large integers round to the nearest representable double." },
    { label: "A RangeError, because the number is too large to store.", misconception: "The value stores fine — doubles reach ~1.8e308. What fails above 2^53 is integer exactness: the result is silently rounded, not rejected. Use BigInt when you need exact large integers." },
  ]}

## Snippet 3 — the plus sign that changes its mind

```js
console.log(5 + "5");   // ?
console.log(5 - "5");   // ?
console.log("5" * 2);   // ?
```

    { label: "10, 0, 10 — JS always converts strings to numbers for arithmetic.", misconception: "The + operator is overloaded: if either side is a string it concatenates, so 5 + '5' is '55', not 10. Only - and * (no string meaning) force numeric coercion." },
    { label: "All three throw TypeErrors, because you cannot mix a number and a string.", misconception: "JS is dynamically typed and coerces rather than throwing here.     { label: "'55', '5', '52' — strings always win and everything becomes text.", misconception: "Strings win only for +. For - and *, which have no string definition, JS coerces the string to a number, giving 0 and 10. The operator decides the coercion direction." },

## Snippet 4 — the type that lies

```js
console.log(typeof null);        // ?
console.log(typeof undefined);   // ?
console.log(null === undefined); // ?
```

<Recap lang="en">
Every surprise here is the same unit idea in a JS costume. Float rounding (0.1 + 0.2) and the safe-integer limit (above 2^53) both come from the single 64-bit IEEE 754 double having finite precision — there is no separate integer type to fall back on. The + operator concatenates with strings but coerces to numbers for - and *, so dynamic typing silently picks a type rule for you. And typeof null returns 'object' — a frozen historical bug. Read the operator and the storage format, and the output stops being a mystery.
</Recap>
