The bits are passive: the hardware stores and retrieves them without caring what they represent. The byte 01000001 is just eight off/on states. Meaning is not in the bits — it arises only when a program reads them with a chosen interpretation. Two programs reading the same byte under different rules will legitimately see different values." },
    { q: "What is a type, and what two pieces of information does it supply?", a: "A type is the interpretation rule a program applies to a bit pattern to turn it into a usable value. It supplies two things: size — how many bytes the value occupies — and interpretation — how to decode those bytes (place-value for an integer, a table lookup for a character, the sign/exponent/mantissa split for an IEEE 754 float). Knowing the address tells you where the bits are; only the type tells you how many to read and what they mean. Crucially, the type lives in the program, compiler, or runtime — never as a label inside the cell." },
    { q: "Show how one bit pattern produces different values under different types.", a: "Take the single byte 01000001. As an unsigned 8-bit integer, binary place-value gives 64 + 1 = 65. As an ASCII character, code 65 maps to the letter 'A'. As the red channel of an RGB pixel, it is a red intensity of 65 out of 255. The physical bits never change between these readings — only the rule applied to them changes. This is not a bug; it is the mechanism that lets one physical memory represent numbers, text, colours, and everything else." },
    { q: "Name the everyday JS/TS primitive types and the one fact about how numbers are stored.", a: "The five everyday primitives are number, string, boolean, null, and undefined. (The full spec adds symbol and bigint, for seven total.) The key storage fact: every JS number — whether 42 or 36.6 — is a single 64-bit IEEE 754 double. There is no separate integer type, which is why 0.1 + 0.2 is not exactly 0.3 and why integers above 2^53 lose precision. A string is a structured sequence of code points; a boolean is one of exactly two states." },
    { q: "Distinguish null from undefined, and state what typeof null returns.", a: "Both are absence values, but the kind of absence differs. null is deliberate absence — a programmer writes it to mean 'nothing here, on purpose'. undefined is automatic absence — a declared-but-unassigned variable, or a missing property, that the runtime supplies. They are distinct primitives; TypeScript strict mode tracks them as separate types. A famous quirk: typeof null returns 'object', a frozen bug from the original implementation, so you test for null with x === null, not typeof." },

A type error is a detected mismatch between the stored type and the applied type. Static typing (TypeScript) detects it before the program runs, eliminating the whole class for type-correct code; dynamic typing (JavaScript) detects it only when the bad line executes — or, with permissive coercion, may not flag it at all.
