    { q: "What is the difference between an address and a value, and why is it easy to confuse them?", a: "An address is the fixed position number of a cell in memory's long row of cells, starting at 0; it is how you find the cell. A value is the data currently stored in that cell, which can change at any time with a write. They are easy to confuse because both are just numbers — a cell at address 42 might hold the value 42, but the equality is coincidence. The address tells the machine where to look; the value is what it finds. A write changes only the value; the address is permanent." },
    { q: "Why is memory byte-addressed rather than bit-addressed, and what is a byte?", a: "A byte is 8 bits grouped and treated as one unit; it can hold 256 distinct values (0 to 255). Memory is byte-addressed, meaning each address names one whole byte, not one bit. Bit-addressing would be impractical: it would need eight times as many addresses, and every useful operation would require reassembling several single-bit reads into a character or number. The byte is the right granularity — large enough to hold a character or small number, small enough not to waste much space. A multi-byte value (like a 32-bit integer) occupies several consecutive byte addresses." },
    { q: "What does random access (the RA in RAM) actually mean?", a: "Random access means the CPU can reach any cell directly by naming its address, in roughly the same amount of time, regardless of where that cell sits in the row. It does not scan through cells one by one looking for data. To read, it puts the address on the address bus and gets the cell's value back; to write, it sends an address plus a new value. There is no traversal cost to reach a distant cell versus a nearby one — that direct, position-independent reach is what random access names." },
    { q: "What is a pointer, and how does dereferencing one work?", a: "A pointer is a cell whose value is intentionally used as an address — it stores the location of some other cell rather than ordinary data. Because addresses and values are both just numbers, nothing special in the hardware marks a value as a pointer; the program decides to treat it as an address. Dereferencing means following the pointer: read the pointer cell to get the address it holds, then perform a second read at that address to get the actual data. So a dereference costs two memory reads instead of one — the extra read is the price of the indirection." },
    { q: "Why is indirection through pointers worth its extra cost?", a: "Indirection costs one extra memory read per access, but it buys two things almost every program needs. First, sharing without copying: many cells can hold the same address, so multiple parts of a program reference one piece of data without duplicating it. Second, one-place updates: if the data moves, you change only the pointer's value to the new address and every reference through it follows automatically. Without indirection you would have to find and update every copy. Those two benefits are why pointers and references appear nearly everywhere." },
    { q: "How do the stack and the heap differ in management and lifetime, given they are the same physical memory?", a: "Both are regions of the same flat byte-addressed RAM; the difference is management and lifetime. The stack is managed automatically: each function call pushes a frame holding its locals and parameters, and the frame is discarded when the function returns, in last-in-first-out order — the most recently called function's frame is the first removed. Stack data lives exactly as long as its function. The heap holds data that must outlive a single call; it is explicitly allocated and freed (or garbage collected), with no fixed order, so its objects persist until released regardless of which function created them." },
