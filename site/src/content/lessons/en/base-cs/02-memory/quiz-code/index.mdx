## Snippet 1 — a memory diagram

```
addr:   0    1    2    3    4    5
value: 25   30    3    0   99   12
```

    { label: "3 — the value stored in the pointer cell is the answer.", misconception: "The value 3 in the pointer cell is an address, not the final data. Dereferencing reads address 3 next, which holds 0. The answer is 0." },
    { label: "25 — dereferencing always starts from address 0.", misconception: "Dereferencing starts at the pointer cell (address 2), not at address 0. Read address 2 to get 3, then read address 3 to get 0." },
    { label: "99 — the largest value in the row is returned.", misconception: "Dereferencing follows the stored address, it does not scan for a maximum. Address 2 holds 3, and address 3 holds 0, so the result is 0." },
  ]}

## Snippet 2 — address arithmetic

```
A 32-bit integer array starts at address 200.
Each element is 4 bytes (32 bits) wide.
Elements are laid out back-to-back with no gaps.
```

<Quiz
  id="02-memory-code-2"
  lessonSlug="02-memory"
  lang="en"
  question="At what byte address does element index 3 (the fourth element) begin?"
  choices={[
    { label: "212 — element i starts at base + i * elementSize = 200 + 3 * 4 = 212. Index 3 is the fourth element because indices start at 0.", correct: true },
    { label: "203 — add the index 3 to the base address 200.", misconception: "Each element is 4 bytes wide, so you advance by index * 4, not by index * 1. The offset is 3 * 4 = 12, giving 200 + 12 = 212." },
    { label: "216 — element index 3 is the third element, at 200 + 4 * 4.", misconception: "Index 3 is the fourth element (indices start at 0), and its offset is 3 * 4 = 12. That gives 212, not 216. Using 4 * 4 would be index 4." },
    { label: "200 — the array always begins at its base address regardless of index.", misconception: "Only index 0 sits at the base. Index 3 is three elements further along: 200 + 3 * 4 = 212." },
  ]}
/>

## Snippet 3 — stack vs heap placement

```c
int* make_counter() {
    int local = 0;        // line A
    int* shared = malloc(sizeof(int));  // line B
    *shared = 0;
    return shared;        // returns a heap pointer
}
```

<Quiz
  id="02-memory-code-3"
  lessonSlug="02-memory"
  lang="en"
  question="After make_counter returns, which of local (line A) and the malloc'd int (line B) still safely exists, and why?"
  choices={[
    { label: "Only the malloc'd int (line B) survives: it lives on the heap, which outlives the call. local (line A) lives in this function's stack frame and is discarded when the frame is popped on return.", correct: true },
    { label: "Both survive because both are integers created inside the function.", misconception: "Being an integer is irrelevant to lifetime; placement is. local sits in the stack frame and dies with it. Only the heap allocation from malloc outlives the call." },
    { label: "Only local survives, because it was declared first.", misconception: "Declaration order does not set lifetime. local is in the stack frame and is gone after the return; the heap allocation (line B) is what persists." },
    { label: "Neither survives — returning from a function frees all memory it touched.", misconception: "Returning frees the stack frame, but heap memory from malloc is independent of the call and persists until explicitly freed. The line B allocation survives." },
  ]}
/>

## Snippet 4 — a write trace

```
Start:  addr 10 -> 7,  addr 11 -> 0
Op 1: write value 4 to address 11
Op 2: write value 9 to address 10
Op 3: write value 0 to address 10
```

<Quiz
  id="02-memory-code-4"
  lessonSlug="02-memory"
  lang="en"
  question="After all three writes, what values are at addresses 10 and 11?"
  choices={[
    { label: "Address 10 holds 0 and address 11 holds 4. Each write overwrites the prior value (last write wins per cell), and writing to one address never touches another.", correct: true },
    { label: "Address 10 holds 9 and address 11 holds 4 — Op 3 only adds to the cell.", misconception: "A write overwrites; it does not add or stack values. Op 3 replaces the 9 with 0, so address 10 ends at 0, not 9." },
    { label: "Address 10 holds 0 and address 11 holds 0 — the last write clears everything.", misconception: "A write affects only its target address. Op 3 sets address 10 to 0 but leaves address 11 at 4, the value Op 1 wrote." },
    { label: "Address 10 holds 7 and address 11 holds 0 — the original values, since writes are temporary.", misconception: "Writes are destructive and permanent until the next write to that cell. The originals are gone: address 10 ends at 0 and address 11 at 4." },
  ]}
/>

<Recap lang="en">
Every problem here is solved by reading the diagram literally: a value can be an address, so dereferencing means a second read at that address; an array element's byte address is base + index * elementSize; a value's survival after a function returns depends on whether it sat on the stack frame (gone) or the heap (persists); and a write overwrites exactly one cell, last-write-wins, touching no other address. Trace cell by cell and the answer is forced.
</Recap>
