The one thing that determines it is the value the program counter (PC) holds at each fetch: whatever address the PC contains is the instruction the CPU runs next. The bytes are fixed and inert; the flow is dynamic. The same bytes can produce different flows depending on which jumps are taken, because each jump rewrites the PC." },
    { q: "Why is sequential (straight-line) execution the default, and how does the PC produce it?", a: "After any non-jump instruction, the PC is updated by adding the size of the current instruction (e.g. +4 on a 4-byte architecture), so it advances to the next instruction in memory. This needs only an adder — the simplest possible circuit — so 'advance to the next instruction' is the do-nothing-special default that emerges from the hardware. The CPU therefore sweeps top-to-bottom through memory, running each instruction once in order, until an instruction overrides the PC with a different address. Sequential execution is the baseline; every branch and loop is a deviation from it." },
    { q: "Explain how an if statement becomes a compare plus a conditional jump at the machine level.", a: "The CPU has no circuit that understands '>' as an idea. Instead a compare (CMP) instruction subtracts one operand from the other, throws away the numeric result, and records the relationship as single bits in the flags register — most importantly the Z (zero) flag (set when the values are equal) and the N (negative) flag (set when the result is negative). A conditional jump (e.g. JZ, JNE, JL) then reads one of those flag bits: if the condition holds it jumps to a target address; if not, it falls through. So an if is exactly: set a flag, then steer the PC on that one bit." },
    { q: "What does 'fall through' mean, and why does an if/else need an unconditional jump after the if-true block?", a: "Fall through means the conditional jump did nothing to the PC, so the PC advances normally to the immediately following instruction — it is the absence of a jump, not a separate operation. In an if/else, the if-true block sits right after the conditional jump and the else block sits after that. Once the if-true block finishes, the PC would keep advancing straight into the else block, running both. So the compiler places an unconditional JUMP at the end of the if-true block that skips over the else block to the merge point. The else block is reached only when the condition was false and the conditional jump took the branch into it." },
    { q: "What makes a loop, and why are while and for the same thing to the CPU?", a: "A loop is a backward jump: a jump whose target address is earlier in memory than the jump itself, so the CPU re-fetches and re-runs instructions it already executed. Paired with a conditional test at the top, it becomes controlled repetition — test the condition, fall through into the body if true, run the body, then unconditionally jump back to the test. A while loop is exactly this. A for loop adds an init block before the loop top and an update block just before the backward jump, but the test-body-backjump pattern is identical, so the compiled code is indistinguishable to the CPU. There is no special loop instruction — just jumps and a flag test." },
    { q: "Why does an infinite loop happen, and can the CPU detect it?", a: "A loop repeats as long as the test before its backward jump stays true. It never ends in two cases: the backward jump is unconditional (a while(true) with no test, common in deliberate server/event loops), or the test exists but the body never changes the value being compared, so the flag never flips (often a bug, like forgetting to decrement the counter). The CPU cannot detect either case: each pass it just re-tests the condition and makes one jump/fall-through decision, with no memory of how many times it has looped. It runs the backward jump indefinitely until the OS or an interrupt stops it. An infinite loop is the machine faithfully obeying the program, not a hardware fault." },

<Recap lang="en">
If you could reconstruct each answer from memory, you hold the unit's spine: execution flow is the order instructions actually run, set entirely by the program counter; the PC advances by default, giving straight-line code; a compare sets a flag and a conditional jump reads it to make a branch; an if/else is two PC destinations with a skip-jump on the boundary; a backward jump plus a top-of-loop test makes a loop, identical for while and for; and a loop runs forever when the tested value never changes — something the CPU can neither count nor detect.
