    { q: "Define expand-contract and explain why it is what makes the rollout strategy and a database migration safely composable.", a: "Expand-contract (parallel change) splits one schema change into separate deploys so every intermediate state is compatible with both the running code and the next version — the N-1 rule. To rename a column: (1) Expand — add the new column, keep the old; both versions work. (2) Migrate — backfill into the new shape and dual-write from the app. (3) Contract — only after every pod confirms it runs the new code reading the new column, drop the old column in a separate later deploy. This matters because a rollout strategy promises reversibility: blue-green flips the LB back instantly, rolling updates run old and new pods side by side. A destructive migration breaks that promise — drop a column in the same release that flips traffic and a rollback lands on code querying a column that no longer exists, 500ing on every request. The LB flip was reversible; the schema change was not; composed, they yield a non-recoverable state. Expand-contract keeps the schema reversible at every step. The cost is three deploys plus temporary dual-write code instead of one migration — the explicit price of zero-downtime reversibility." },

For a brief window the LB may still route requests to the dying pod. An L4 balancer routes by IP/port and cannot drain at the request layer, so it can cut connections mid-response; an L7 balancer reads HTTP, stops sending new requests, and waits a configurable drain timeout (a good default is 1.5–2× p99 request time) for in-flight ones to finish. The application must cooperate: catch SIGTERM, stop accepting new work, finish in-flight requests, then exit — all within terminationGracePeriodSeconds (default 30s) — with a preStop sleep to cover the endpoint-removal race so the LB has stopped routing before the process begins shutting down. L7 draining handles the front; SIGTERM handling handles the back; together they keep requests alive across the cutover." },

IaC works by diffing declared desired state against a recorded state file to compute a plan — that file is both source of truth and hazard. Closing the loop means making IaC authoritative: every change goes through version control, CI runs plan on a schedule and alerts on any diff, and out-of-band edits are forbidden.
