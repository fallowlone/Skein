## Why "it runs on my machine" is not enough

Your laptop is one specific computer with your tools, your settings, and an address only you can reach. Real users need the app on a computer that is always on, reachable from the internet, and set up the exact same way every time. Deployment is the work of getting it there: packaging the code so it carries everything it needs, putting that package on a server, and starting it so requests from the outside actually arrive and get answered.

## The three steps: build, release, run

A reliable deployment splits into three stages. Keeping them separate is what makes the process repeatable instead of a 2am scramble.

- **Build** — turn your source code into one fixed package (dependencies included). This package does not change after this point.
- **Release** — combine that package with the settings for *where* it will run (the database address, secret keys). Each release gets its own version number.
- **Run** — start the released package on a server so it listens for and answers user requests.

## The promise: same result every time, and a way back

The reason to do this carefully is a guarantee: the same build, released and run the same way, behaves the same way — on your machine, on the server, today and next month. And because each release has its own version, if a new release breaks, you switch back to the last good one. The rest of this track is how each step actually works: packaging code into images, choosing where it runs, rolling out new versions safely, and rolling back when they go wrong.

<Recap lang="en">
Your code running on your laptop is not a service: a laptop is not always on, not reachable by users, and set up only for you. Deployment is the repeatable path that fixes this — build turns source into one fixed package, release pairs it with settings and a version, and run starts it on an always-on server users can reach. Because each release is versioned, you can roll back when one breaks. The rest of this track unpacks each step: images, where it runs, safe rollouts, and rollbacks.
</Recap>
