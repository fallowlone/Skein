<Recap lang="en">
The through-line is one decision: weigh blast radius (canary smallest, recreate total) against resource cost (blue-green doubles) against rollback speed (blue-green and canary near-instant, rolling backward, recreate a second downtime). Then the prerequisites that make any choice real — maxSurge/maxUnavailable plus a readiness probe for zero-downtime rolling, an automated metric gate for canary, and expand-contract migrations so rollback survives a schema change. Observability decides which strategy you can actually trust. Now when you face the next release decision, run the three-axis check before reaching for a default — blast radius, resource cost, rollback speed — and make sure the prerequisites are in place before the deploy goes out.
</Recap>
