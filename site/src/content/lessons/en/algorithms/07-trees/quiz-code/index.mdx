## Snippet 1 — traversal order

```js
function walk(node) {
  if (node === null) return;
  walk(node.left);
  console.log(node.value);
  walk(node.right);
}

//        5
//       / \
//      3   8
//     / \   \
//    2   4   9
walk(root);
```

## Snippet 2 — the BST validator bug

```js
function isBST(node) {
  if (node === null) return true;
  if (node.left && node.left.value >= node.value) return false;
  if (node.right && node.right.value <= node.value) return false;
  return isBST(node.left) && isBST(node.right);
}

//        5
//       / \
//      3   8
//         /
//        4      // 4 < 5, but sits in the RIGHT subtree of 5
```

## Snippet 3 — recursive height

```js
function height(node) {
  if (node === null) return 0;       // note: returns 0, not -1
  return 1 + Math.max(height(node.left), height(node.right));
}

// single leaf node
console.log(height(leaf));
```

## Snippet 4 — tree-DP path sum

```js
function maxPathSum(root) {
  let best = -Infinity;
  function gain(node) {
    if (node === null) return 0;
    const left = Math.max(gain(node.left), 0);   // drop negative branches
    const right = Math.max(gain(node.right), 0);
    best = Math.max(best, node.value + left + right);  // path THROUGH node
    return node.value + Math.max(left, right);          // path the parent can extend
  }
  gain(root);
  return best;
}
```

<Quiz
  id="07-trees-code-4"
  lessonSlug="07-trees"
  lang="en"
  question="Why does gain() return node.value + max(left, right) while best is updated with node.value + left + right?"
  choices={[
    { label: "A path that bends through a node can use both children (node + left + right), but that bent path cannot be extended upward — a parent can only attach to one downward branch. So gain returns the single-branch value the parent can reuse, while best records the best bend seen anywhere. Same tree-DP split as the diameter problem.", correct: true },
    { label: "It is a bug; both lines should add left + right.", misconception: "If gain returned left + right, the parent would build a path that forks at this node and then forks again above — not a simple path. A path enters a node from one side only, so the upward return must use a single branch." },
    { label: "The max(..., 0) clamps are the real logic; the two formulas are otherwise equivalent.", misconception: "The clamps only discard negative branches; they do not make the two formulas equal. Through-node (both branches) and upward-extendable (one branch) are genuinely different quantities." },
    { label: "best should be returned from gain instead of read from the closure.", misconception: "best must be a single shared accumulator across the whole traversal, which is exactly what the closure variable provides. Returning it from gain would conflate the local return value with the global answer — the bug the pattern avoids." },
  ]}
/>

<Recap lang="en">
Reading tree code comes down to a few reflexes: locate the visit line relative to the two recursive calls to name the traversal (and remember in-order on a BST is sorted); never trust a BST validator that only checks parent-against-child — correctness needs a propagated (min, max) bound; read the null base case to know whether height is counted in nodes (return 0) or edges (return -1); and in tree DP, watch for the deliberate gap between what a node returns to its parent (one extendable branch) and what it contributes to the global answer (the full bend through it).
</Recap>
