    { q: "Why is recursion the natural way to process a binary tree?", a: "A binary tree is defined recursively: it is either empty, or a node with a left subtree and a right subtree, each of which is itself a binary tree. The data's structure is self-similar, so an algorithm with the same shape fits perfectly — handle the node, then recurse on the left subtree, then the right. The base case is the empty subtree (null). This 'solve the subtrees, then combine with the node' template covers almost every tree problem: height, node count, search, validation, and tree DP all instantiate it with different base values and combine steps." },
    { q: "Name the three depth-first traversal orders and what each is for.", a: "Pre-order (node, left, right) visits a parent before its children — used for copying a tree or any top-down propagation where a node needs its ancestors' context. In-order (left, node, right) visits the node between its subtrees — on a BST it emits values in ascending sorted order. Post-order (left, right, node) visits a node only after both children — used for bottom-up computation like freeing a tree or computing subtree results (heights, sums). All three are O(n) time and O(h) stack space; they differ only in WHEN the node is visited relative to its subtrees." },
    { q: "State the BST invariant and what it buys you.", a: "For every node, all values in the left subtree are strictly less than the node's value and all values in the right subtree are strictly greater (the invariant holds recursively for every subtree). This lets search, insert, and delete follow a single root-to-leaf path: at each node one comparison tells you to go left or right, so you never explore both sides. The cost is O(h) — the path length. In-order traversal of a BST yields sorted order, which is the same invariant read out as a sequence." },
    { q: "Why does O(h) not always mean O(log n) for a BST, and what is the worst case?", a: "O(h) is logarithmic only when the tree is balanced, i.e. h ~ log n. The BST invariant says nothing about shape. If you insert keys in sorted (or reverse-sorted) order, every new key goes to the same side and the tree degenerates into a chain of height n-1, so search and insert become O(n) — no better than a linked list. That is the classic worst case and the entire motivation for self-balancing trees (AVL, red-black), which restructure on insert to keep h ~ log n." },
    { q: "When do you choose level-order (BFS) over a depth-first traversal, and what makes it work?", a: "Choose BFS whenever the answer depends on depth or distance from the root: grouping nodes by level, finding the minimum depth, computing a right-side view, or shortest unweighted distance. It works because a FIFO queue holds the current frontier: you dequeue a node, enqueue its children to the back, so all nodes at depth d are processed before any at depth d+1. To get nodes grouped per level, snapshot the queue's size at the start of each round and process exactly that many. Space is O(w), the maximum level width (up to ~n/2 in a balanced tree)." },
    { q: "Describe the tree-DP pattern and why the return value differs from the answer.", a: "Tree DP solves a problem in one post-order pass where each node returns local information to its parent while a side variable accumulates the global answer. The return value and the answer differ because what a parent can reuse is not the full local result. Classic example: diameter — a node's longest internal path uses both subtrees (leftHeight + rightHeight), but a parent can only extend ONE branch upward, so the node returns its height and updates a shared max with the through-node path. Same shape for max-path-sum. This avoids two passes and is O(n) time, O(h) space." },
