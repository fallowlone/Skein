    { q: "State the two properties that define a binary heap, and explain why they let you store it as a flat array with no pointers.", a: "A binary heap is (1) a complete binary tree — every level full except possibly the last, which fills left-to-right with no gaps — and (2) it satisfies the heap property: every parent ≤ both children (min-heap) or ≥ (max-heap). The completeness is what enables the array encoding: laying nodes out in breadth-first order leaves no holes, so for a node at index i the parent is at ⌊(i−1)/2⌋, the left child at 2i+1, the right at 2i+2. No pointers are needed because position in the array implies position in the tree. The root (min or max) is always at index 0, giving O(1) peek." },
    { q: "Walk through push and pop, and state why each is O(log n).", a: "Push appends the new value at the end of the array (the next leaf, preserving completeness) and calls sift-up: compare with the parent and swap upward while the heap property is violated, stopping at the root. Pop removes the root (the answer), moves the LAST element to the root to keep the tree complete, shrinks the array by one, and calls sift-down: swap with the smaller child (min-heap) while the property is violated, stopping at a leaf. Both are O(log n) because the tree has height ⌈log₂ n⌉ and each does at most one swap per level — sift-up touches one parent per level, sift-down at most two children per level." },
    { q: "Why is build-heap O(n) while inserting n elements one-by-one is O(n log n)?", a: "build-heap sift-downs every non-leaf, starting from the last non-leaf at ⌊n/2⌋−1 and moving up to the root, so each node's subtrees are already valid heaps when it is processed. The cost of sift-down from a node is proportional to its HEIGHT, not the tree height. About n/2 nodes are leaves (height 0, no work), n/4 are height 1, n/8 height 2, and so on; the total Σ (n/2^{h+1})·h converges to ≤ 2n = O(n). Inserting one-by-one instead sift-UPs each element through its full DEPTH, and most elements live near the bottom where depth ≈ log n — so that path is O(n log n)." },
    { q: "Distinguish the priority-queue ADT from the binary heap, and name when the distinction changes a design.", a: "A priority queue is an abstract data type — a contract of operations: insert, extractMin (or extractMax), peek, plus isEmpty/size. A binary heap is one IMPLEMENTATION of that contract; others include a sorted array (O(1) peek, O(n) insert), a balanced BST (O(log n) all round, larger constants), and a Fibonacci heap (O(1) amortized decrease-key). The distinction matters when the workload needs an operation the plain heap does poorly. The classic case is Dijkstra's shortest path, which leans on decrease-key: a binary heap has no efficient decrease-key, so an indexed binary heap or a Fibonacci heap changes the asymptotics. Naming the contract separately is what lets you swap implementations without touching client code." },
    { q: "Explain the size-k heap pattern and how the same idea solves both top-k and k-way merge.", a: "The shared idea is: never hold more than k candidates in the heap, so every operation is O(log k). For top-k LARGEST over n elements, keep a MIN-heap of size k; push each element and, when the heap exceeds k, pop the root (the current smallest of the top-k). The survivors are the k largest, the root is the k-th largest, total O(n log k) time and O(k) space — beating sorting's O(n log n) when k ≪ n. For k-way merge of k sorted lists (n elements total), the heap holds exactly one candidate from each list (the current head); pop the minimum, append it, then push the NEXT element from that same list (tracked via listIndex/position). Each pop/push is O(log k), so the merge is O(n log k) versus the naive O(nk) head-scan." },
    { q: "How does heap-sort fall out of the heap operations, and what are its time and space costs?", a: "Heap-sort is two phases built from operations you already know. Phase 1: build-heap turns the array into a (max-)heap in O(n). Phase 2: repeatedly swap the root (the max) with the last unsorted element, shrink the heap by one, and sift-down the new root to restore the property — this places the largest element at the end each time, so after n−1 pops the array is sorted ascending in place. Each of the n sift-downs is O(log n), so the total is O(n) + O(n log n) = O(n log n) worst, average, and best case. Space is O(1) auxiliary because everything happens in the same array. The trade-off versus quicksort: heap-sort has guaranteed O(n log n) (no bad pivots) but worse cache locality and constant factors, so it is not always the fastest in practice." },
