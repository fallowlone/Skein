Each iteration: save next = current.next, then reverse with current.next = prev, then advance prev = current and current = next. When current is null, prev is the new head. The move you must never skip is saving next before the line current.next = prev — once you overwrite current.next you have lost the only link to the rest of the list, and the traversal either stops early or loops. Cost: O(n) time (one pass, each node touched once) and O(1) space (just three pointers, no recursion stack and no new nodes). The recursive version is elegant but costs O(n) stack space." },
    { q: "Explain the fast-and-slow (tortoise-and-hare) technique. Why must the pointers meet inside a cycle, and why exactly two steps for the fast pointer?", a: "Run slow one node per iteration and fast two nodes per iteration from the head. If fast reaches null, the list is acyclic. If there is a cycle, fast enters it and, since it gains exactly one node on slow per iteration, the gap shrinks by one each step until it hits zero — so they must collide inside the loop; they can never meet outside it because once slow enters the cycle it never leaves and fast is already inside. The same technique finds the middle: when fast falls off the end, slow has taken half the steps and sits at the middle. Fast must move by two: a step of one never catches up, and a step of three or more can leap over slow without ever landing on it, so convergence is no longer guaranteed. The whole thing is O(n) time and O(1) space — the space win over a visited-set, which is O(n)." },
    { q: "A stack and a queue can both be backed by an array or a linked list. So what actually distinguishes them, and how do you choose between them for a problem?", a: "They are disciplines, not data structures: each restricts where you may insert and remove. A stack is LIFO — push and pop both happen at one end (the top), so the most recently added element comes out first. A queue is FIFO — enqueue at the rear, dequeue at the front, so the oldest element comes out first. You choose by the order the problem needs. Most-recent-first problems take a stack: bracket matching (innermost open bracket must close first), undo/redo, expression parsing, depth-first traversal, the call stack. Arrival-order / fairness problems take a queue: breadth-first / level-order traversal, job scheduling, message buffers. The backing structure (array, linked list, circular buffer) is an implementation detail chosen for memory and performance; the discipline is what makes it a stack or a queue." },
    { q: "What is a deque, and why does dequeuing a FIFO queue with a naive array shift quietly destroy performance?", a: "A deque (double-ended queue) supports insertion and removal at both ends — pushFront, pushBack, popFront, popBack — each in O(1) when backed by a doubly linked list or a circular buffer. A plain queue is the special case using only one end for each operation. The performance trap: implementing dequeue with JavaScript's array.shift() (or removing index 0) forces the runtime to reindex every remaining element down one slot, so each dequeue is O(n). Over N enqueue+dequeue pairs that sums to O(N^2) — correct output, catastrophic latency under load. The fix is to keep front and rear pointers/indices and never shift: a linked-list queue (head and tail) or a circular buffer that wraps the indices with modulo so dequeued slots are reused. Both make every operation O(1)." },

For next-greater-element you keep a decreasing stack of indices: scan the array, and for each element pop every index whose value is less-or-equal (they can never be the next-greater for anything still to come), then the new top — if any — is the answer for the popped indices, and finally push the current index.
