<Idea>
We’ll look at four small but important algorithms:

1. **Linear search** – scan a list from start to finish until you find the target (or reach the end).
2. **Binary search** – repeatedly split a sorted list in half to zero‑in on the target.
3. **Bubble sort** – repeatedly swap adjacent out‑of‑order elements until the list is sorted.
4. **Factorial (recursive)** – compute n! = n × (n-1) × … × 1 using a function that calls itself.

For each we’ll write the pseudocode, trace a small example, and analyze complexity.
Seeing multiple patterns side‑by‑side helps you choose the right tool later.
</Idea>

<Code>
**1. Linear search**
```
algorithm linearSearch(list, target):
    for i from 0 to list.length - 1:
        if list[i] == target:
            return i
    return -1
```

**2. Binary search** (requires sorted list)
```
algorithm binarySearch(list, target):
    left ← 0
    right ← list.length - 1
    while left <= right:
        mid ← (left + right) // 2
        if list[mid] == target:
            return mid
        else if list[mid] < target:
            left ← mid + 1
        else:
            right ← mid - 1
    return -1
```

**3. Bubble sort**
```
algorithm bubbleSort(list):
    n ← list.length
    repeat n - 1 times:
        swapped ← false
        for i from 0 to n - 2:
            if list[i] > list[i + 1]:
                swap list[i] and list[i + 1]
                swapped ← true
        if not swapped:
            break
```

**4. Factorial (recursive)**
```
algorithm factorial(n):
    if n == 0:
        return 1
    else:
        return n × factorial(n - 1)
```
</Code>

<Trace>
Let’s trace each algorithm with a tiny input so you can see the steps.

**Linear search** for target 7 in `[3, 5, 7, 2]`:
- i=0: 3==7? no
- i=1: 5==7? no
- i=2: 7==7? yes → return 2

**Binary search** for target 6 in sorted `[1, 3, 5, 7, 9]`:
- left=0, right=4 → mid=2 → list[2]=5 &lt;6 → left=3
- left=3, right=4 → mid=3 → list[3]=7 &gt;6 → right=2
- left=3, right=2 → loop ends → return -1 (not found)

**Bubble sort** pass on `[3, 1, 4, 2]`:
- Compare 3 and 1 → swap → `[1, 3, 4, 2]`, swapped=true
- Compare 3 and 4 → no swap
- Compare 4 and 2 → swap → `[1, 3, 2, 4]`, swapped=true
- End of pass (swapped true, so another pass)
Second pass:
- 1 and 3 → no swap
- 3 and 2 → swap → `[1, 2, 3, 4]`, swapped=true
- 3 and 4 → no swap
Third pass:
- 1 and 2 → no swap
- 2 and 3 → no swap
- 3 and 4 → no swap
- swapped stays false → break

**Factorial(4)**:
- factorial(4) → 4 × factorial(3)
- factorial(3) → 3 × factorial(2)
- factorial(2) → 2 × factorial(1)
- factorial(1) → 1 × factorial(0)
- factorial(0) → 1
Now unwind: factorial(1)=1×1=1, factorial(2)=2×1=2, factorial(3)=3×2=6, factorial(4)=4×6=24.
</Trace>

<Complexity>
Let’s state the complexity for each algorithm.

1. **Linear search**
   - Time: worst case we check every element → O(n)
   - Best case (target at first index) → O(1)
   - Space: only a few variables → O(1)

2. **Binary search** (sorted list)
   - Time: each step halves the search space → O(log n)
   - Space: iterative version uses O(1) extra space

3. **Bubble sort**
   - Time: worst and average case O(n²) because of nested loops
   - Best case (already sorted) we can break early → O(n)
   - Space: only a few variables → O(1)

4. **Factorial (recursive)**
   - Time: we make n recursive calls → O(n)
   - Space: each call adds a stack frame → O(n) (tail recursion not assumed)
   - Note: an iterative loop would give O(1) space.
</Complexity>

<Recap lang="en">
Studying these four algorithms reinforces the problem‑solving loop: understand, pseudocode (or code), trace, and analyze complexity.  
Linear search is simple but scans the whole list; binary search is much faster on sorted data but requires sorting first.  
Bubble sort is easy to understand but inefficient for large lists; factorial shows how recursion expresses a mathematical definition cleanly, though it uses extra stack space.  
Recognizing these patterns helps you pick the right approach when you face a new problem.
</Recap>
