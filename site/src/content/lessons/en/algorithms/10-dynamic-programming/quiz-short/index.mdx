Missing the first means caching does not help (divide and conquer territory); missing the second means the recurrence is wrong no matter how you store it." },
    { q: "Contrast memoization and tabulation. When would you pick each?", a: "Memoization is top-down: write the natural recursion, add a cache keyed by the subproblem arguments, check the cache before computing and store after. It only computes states actually reached and is closest to the recurrence you wrote. Tabulation is bottom-up: allocate a dp array, fill base cases, then iterate from small states up to the goal in an order where every cell reads cells already filled — no recursion, no call stack. Both compute each distinct state once, so the asymptotic time is identical. Pick memoization for sparse state spaces or when the order is hard to reason about; pick tabulation when recursion depth would overflow the stack, when you want a rolling-window space cut, or when the per-access constant of recursion and hashing matters." },
    { q: "How do you design the state for a DP problem, and what makes a state correct?", a: "The state is the minimal set of variables that fully determine the answer to a subproblem — change any of them and the answer can change; everything else is irrelevant. A correct state is sufficient (it captures every constraint the future decisions depend on) and minimal (no redundant dimension, which would inflate the table). House Robber needs one index i because the only constraint is adjacency. Knapsack needs (item index, remaining capacity) because the choice depends on both. LCS and edit distance need two indices (i, j), one per string. Interval DP needs an interval [i, j] because the cost depends on which contiguous range remains. If two distinct situations would give different answers but map to the same state, the state is missing a dimension." },
    { q: "What is a transition, and why must the iteration order respect it?", a: "The transition is the recurrence that expresses dp[state] in terms of strictly smaller (already-solved) states — it enumerates every choice available at that state and combines the resulting subanswers, usually with min, max, or a sum. The iteration order must guarantee that every state a transition reads is already filled before the current state is computed. In 1D that is usually left to right; in 2D it follows the row/column dependencies; in interval DP it is by increasing interval length, because dp[i][j] depends on shorter intervals dp[i][k] and dp[k+1][j]. Get the order wrong and the transition reads uninitialized cells, returning a confidently wrong answer with no crash." },
    { q: "Explain how space optimization (the rolling array) works and when it is safe.", a: "Space optimization drops a dp table to a few rows or variables when each cell depends only on a bounded, recent window of other cells. Fibonacci-style 1D recurrences (dp[i] from dp[i-1] and dp[i-2]) need only two rolling variables, giving O(1) space. A 2D table where dp[i][j] reads only the previous row and the current row's left neighbor (LCS, edit distance) needs just two rows, giving O(m) space. It is safe exactly when you never overwrite a value that a later cell in the same pass still needs to read — which is why 0/1 knapsack's 1D form runs capacity downward, to avoid reading an already-updated cell from the same item. The catch: rolling arrays discard the history needed to reconstruct the actual solution path, so keep the full table if you must recover the sequence, not just its value." },

O(n log n): maintain a 'tails' array where tails[k] is the smallest tail value of any increasing subsequence of length k+1; for each value binary-search the first tail it cannot extend and overwrite it (or append if it extends everything). The answer is the LENGTH of tails. The trap: the tails array is NOT a valid increasing subsequence — its stored values can be a mix that never appears in that order in the input. Only its length is meaningful; reconstructing the actual subsequence needs extra parent pointers." },
