When does the order matter, and what does each give you?", a: "DFS uses a stack (the call stack when recursive) and dives deep along one branch before backtracking; BFS uses a FIFO queue and explores level by level, all vertices at distance d before distance d+1. The order is what differs. BFS's level order means the first time it reaches a vertex is via the fewest edges, so BFS solves unweighted shortest paths; DFS does not. DFS's depth-first structure naturally exposes finish order (post-order), which drives topological sort and cycle detection via back edges. Both need a visited set on a cyclic graph or they loop forever. Pick BFS for fewest-edge distance and levels, DFS for depth, ordering, and cycle structure." },
    { q: "What is a topological order, when does it exist, and how do the two algorithms detect a cycle?", a: "A topological order lists every vertex of a directed graph so that for each edge u -> v, u appears before v. It exists if and only if the graph is a DAG (no cycle) and is usually not unique. Kahn's algorithm computes in-degrees, enqueues all in-degree-0 vertices, then repeatedly pops one into the output and decrements its neighbors, enqueuing any that reach 0; if fewer than V vertices come out, the leftovers are trapped in a cycle and no order exists. The DFS variant pushes each vertex on exit (post-order) then reverses; a back edge to a vertex still on the recursion stack flags a cycle. Both run in O(V + E) time and O(V) space and double as cycle detectors." },
    { q: "State Dijkstra's settle invariant and explain exactly why it fails with a negative edge.", a: "Dijkstra keeps a tentative dist[] (source 0, rest infinity) in a min-priority-queue. The settle invariant: when a vertex u is popped as the heap minimum, dist[u] is final, because any alternative route to u must leave the settled region through some unsettled vertex whose tentative distance is at least dist[u], and since edges only add cost, that route costs at least as much. A negative edge breaks the 'edges only add cost' premise: a route discovered after u is settled could include a negative edge that lowers u's true distance below the value Dijkstra locked. So Dijkstra can commit a wrong distance. The fix is Bellman-Ford, which relaxes every edge V-1 times (O(V*E)) and detects negative cycles." },
    { q: "Why is union-find's amortized cost O(alpha(n)) and not true O(1) or O(log n)?", a: "Union-Find stores a parent[] forest; find walks to the root, union links one root under another. With union by rank/size alone, trees stay O(log n) tall. Adding path compression (repointing nodes toward the root during find) drops the AMORTIZED cost per operation to O(alpha(n)), the inverse Ackermann function, which is below 5 for any n that fits in the universe — near-constant. It is better than O(log n) because the two optimizations compound. But it is provably not true O(1) per call: Tarjan proved an alpha(n) lower bound for this style of structure, and the bound is amortized over a sequence, not guaranteed for every single call. Drop both optimizations and find degrades to O(n) on a degenerate chain." },

Use union-find when connectivity is DYNAMIC: edges arrive over time and after each one you must answer 'same component?' immediately. DSU merges incrementally with union and answers find(a) === find(b) in amortized O(alpha(n)) with no re-traversal, whereas re-running BFS after every edge costs O(V + E) per edge. DSU also powers undirected cycle detection (an edge whose endpoints already share a root closes a cycle) and Kruskal's MST." },
