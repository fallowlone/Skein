## Snippet 1 — the nested loop on sorted data

```python
def has_pair_with_sum(a, target):   # a is sorted ascending
    n = len(a)
    for i in range(n):
        for j in range(i + 1, n):
            if a[i] + a[j] == target:
                return True
    return False
```

## Snippet 2 — the recursion that recomputes

```python
def ways(n, coins):
    if n == 0: return 1
    if n < 0 or not coins: return 0
    # use coins[0] again, or drop it
    return ways(n - coins[0], coins) + ways(n, coins[1:])
```

    { label: "Replace it with a greedy largest-coin-first pass.", misconception: "Greedy counts at most one way, not all distinct ways, and can be wrong for non-canonical denominations. Counting combinations needs summing over subproblems, which is DP — greedy answers a different question." },
    { label: "Use two pointers over the coins array.", misconception: "Two pointers solves relationship-on-sorted-sequence problems, not counting over a recursive choice space. The overlapping (remaining, index) states are the unmistakable cue for memoisation or tabulation." },

## Snippet 3 — the running k-th element

```python
import heapq

def stream_kth_largest(stream, k):
    h = []                       # what kind of heap?
    for x in stream:
        heapq.heappush(h, x)     # Python heapq is a MIN-heap
        if len(h) > k:
            heapq.heappop(h)     # pops the smallest
    return h[0]                  # the k-th largest seen so far
```

  question="This keeps a running k-th largest with a size-k min-heap. Why is a MIN-heap (not a max-heap) the correct structure here?"
  choices={[
    { label: "To keep the k LARGEST, you must cheaply evict the smallest of your current k whenever a bigger one arrives — that smallest sits at the root of a min-heap. The root is then exactly the k-th largest. O(n log k) time, O(k) space.", correct: true },
    { label: "A max-heap would be correct and faster.", misconception: "A max-heap puts the largest at the root, so evicting the right element (the smallest of your kept k) would cost an O(k) scan each time. The min-heap makes the eviction O(log k). Mirror logic gives a max-heap for the k smallest." },
    { label: "Either heap works; the choice is arbitrary.", misconception: "The choice is forced by which element you must evict cheaply. Keeping the k largest means dropping the current smallest, so the smallest must be at the root — a min-heap. The orientation is not arbitrary." },
    { label: "A sorted list would be just as efficient here.", misconception: "Maintaining a sorted list costs O(k) per insertion (shifting elements), giving O(n*k) overall, versus O(n log k) for the heap. For a streaming top-k the heap is the right structure precisely because insert and evict are both O(log k)." },
  ]}

## Snippet 4 — the unbounded window

```python
def longest_unique_substring(s):
    seen = set()
    best = 0
    for r in range(len(s)):
        while s[r] in seen:
            seen.add(s[r])       # BUG: should shrink from the left
        seen.add(s[r])
        best = max(best, len(seen))
    return best
```

<Recap lang="en">
Reading code for its pattern is the same flow run in reverse: a nested loop over sorted data should be two pointers (O(n)); a recursion that recomputes identical states is screaming for memoisation or tabulation (DP); a running k-th element forces a specific heap orientation by which element must be cheaply evicted; and 'longest contiguous range satisfying a condition' is a sliding window whose left pointer only moves forward. Name the pattern, check the data structure against the dominant operation, then change the one thing that moves the complexity.
</Recap>
