    { q: "Explain the recursive leap of faith and why it makes recursive code easier to write.", a: "The recursive leap of faith is trusting that the recursive call returns the correct answer for the smaller input, without mentally tracing every nested call. When writing factorial(n) you assume factorial(n - 1) already returns (n-1)! correctly, so you only have to write n * factorial(n - 1). It works because each call passes a strictly smaller input, so the chain must reach the base case, and induction guarantees that if the base case is right and each step combines the smaller answer correctly, the whole thing is right. It lets you reason about one level at a time instead of the entire call tree." },
    { q: "How does the call stack determine the space complexity of a recursive function, and what is a stack overflow?", a: "Each function call pushes a stack frame holding its parameters, local variables, and return address; the frame is popped when the call returns. During recursion, frames for all the calls on the current root-to-leaf path are live at once, so the peak number of frames equals the maximum recursion depth. That makes the space complexity O(maximum depth): factorial(n) is O(n) space because it nests n deep. The stack has a fixed size (typically a few megabytes). If recursion goes deeper than that fits, a stack overflow occurs and the program crashes. This is why recursion that scales its depth with untrusted input is risky." },
    { q: "How do you read the time complexity of a recursive function from its recursion tree?", a: "Draw the tree where each node is one call and its children are the calls it makes. Two numbers drive the cost: the branching factor b (recursive calls per invocation) and the depth d (levels until the base case). The number of nodes is roughly b^d, and total time is the node count times the work per node. So factorial (b = 1, d = n) has about n nodes and is O(n); naive fibonacci (b = 2, d = n) has about 2^n nodes and is O(2^n) even though both nest only n deep. Crucially, depth sets space (the stack), but the node count sets time, so a function can be cheap in space yet catastrophic in time." },
    { q: "State the backtracking template and explain why the undo step is mandatory.", a: "Backtracking is a depth-first walk of all partial solutions following choose-explore-undo: if the partial solution is complete, record a copy of it and return; otherwise, for each available choice, make the choice, recurse to explore it, then undo the choice before trying the next one. The undo (e.g. current.pop() after current.push(item)) is mandatory because the partial solution is shared mutable state across sibling branches. Without it, leftover choices from one branch leak into the next, so later branches build on stale state and the outputs are corrupted. You must also record a copy of the partial solution, not a reference, or every stored result points at the same mutated array." },
    { q: "What is pruning in backtracking, and how do subsets, permutations, and combinations differ within the same template?", a: "Pruning means checking, before recursing, whether the current partial solution can still lead to a valid complete one; if not, you skip the entire subtree. That is what turns backtracking from brute force into something practical (e.g. N-Queens skips placements that already conflict). The three classic problems share the choose-explore-undo skeleton but differ in their choice and stopping rule. Subsets branch include/exclude on each element and stop at depth n, giving 2^n outputs. Permutations pick which unused item (tracked by a used array) goes next and stop when length equals n, giving n! outputs. Combinations walk forward from a start index, never revisiting earlier items, and stop at size k, giving C(n, k) outputs and a natural prune when too few items remain to reach k." },
