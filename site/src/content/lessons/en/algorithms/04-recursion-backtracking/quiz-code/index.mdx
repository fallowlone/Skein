## Snippet 1 — the missing progress

```js
function sumDigits(n) {
  if (n === 0) return 0;       // base case
  return (n % 10) + sumDigits(n / 10);   // recursive case
}

sumDigits(123);
```

## Snippet 2 — the recursion tree

```
fib(4)
├─ fib(3)
│  ├─ fib(2)
│  │  ├─ fib(1)
│  │  └─ fib(0)
│  └─ fib(1)
└─ fib(2)
   ├─ fib(1)
   └─ fib(0)
```

## Snippet 3 — the leaked state

```js
function subsets(arr) {
  const result = [], current = [];
  function go(i) {
    if (i === arr.length) { result.push(current); return; }
    current.push(arr[i]);
    go(i + 1);
    current.pop();
    go(i + 1);
  }
  go(0);
  return result;
}
```

<Quiz
  id="04-recursion-backtracking-code-3"
  lessonSlug="04-recursion-backtracking"
  lang="en"
  question="The choose-explore-undo structure looks right. Why does this return an array of empty (or identical) subsets?"
  choices={[
    { label: "result.push(current) stores a reference to the one shared array, not a copy. Every push records the same object, and later pop calls mutate it, so all stored subsets end up identical (empty at the end). Fix: push a copy, result.push([...current]).", correct: true },
    { label: "The undo (current.pop()) is in the wrong place.", misconception: "The pop is correctly placed between the include and exclude branches; the choose-explore-undo order is fine. The bug is storing a live reference instead of a snapshot copy." },
    { label: "go(i + 1) should be go(i) in one of the branches.", misconception: "Both branches must advance to i + 1 to move through the elements; calling go(i) would not make progress. The defect is the missing copy when recording a complete subset." },
    { label: "It needs a used array like permutations do.", misconception: "Subsets branch include/exclude per index and need no used array. The only fault is pushing the shared current by reference instead of copying it." },
  ]}
/>

## Snippet 4 — the pruning question

```js
function combine(arr, k) {
  const result = [];
  function go(start, current) {
    if (current.length === k) { result.push([...current]); return; }
    for (let i = start; i < arr.length; i++) {
      current.push(arr[i]);
      go(i + 1, current);
      current.pop();
    }
  }
  go(0, []);
  return result;
}
```

  choices={[
    { label: "It prunes branches that can no longer reach k items, cutting wasted recursion when too few elements remain; the output set is identical, only fewer dead-end calls are made.", correct: true },
    { label: "It changes the result to include shorter combinations.", misconception: "The base case still only records when current.length === k, so the output is unchanged. The check only skips branches that provably cannot reach size k." },
    { label: "It introduces duplicate combinations.", misconception: "The start index already prevents duplicates by walking forward only. The prune cannot add duplicates; it just avoids exploring branches with too few remaining items." },
    { label: "It is incorrect because it can skip valid combinations.", misconception: "If current.length plus all remaining items is still below k, no completion of this branch can ever reach k, so nothing valid is skipped. It is a sound prune." },
  ]}

<Recap lang="en">
Every recursive bug is read the same way: confirm the base case can actually be reached (Snippet 1's float division never hits 0), watch for overlapping subproblems that make the tree exponential (Snippet 2's repeated fib calls), copy the partial solution when you record it instead of storing a shared reference (Snippet 3), and add pruning that skips provably dead branches without changing the output (Snippet 4). Trace the calls, fix the progress or the state, then re-check.
</Recap>
