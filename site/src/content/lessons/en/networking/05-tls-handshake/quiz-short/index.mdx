TLS 1.2's optional RSA key transport broke this: the client encrypted the session secret under the server's long-term public key, so a stolen private key decrypted every recorded past session. TLS 1.3 mandates ephemeral exchange, making PFS the default with no configuration." },
    { q: "What is the transcript hash and how does it make the handshake tamper-evident, including downgrade attempts?", a: "Every handshake byte is fed into a running SHA-256/384 digest, the transcript hash. The Finished message is an HMAC over that transcript using a derived finished key. If any handshake byte was flipped, replaced, or reordered — by a bug or a man-in-the-middle — the recomputed HMAC will not match and the connection aborts before application data flows. This catches downgrade attacks because the originally proposed version and parameters are recorded in the transcript: a middlebox forcing TLS 1.2 or stripping ALPN h2 changes the transcript and breaks Finished on both sides." },
    { q: "PSK resumption and 0-RTT both reuse a cached secret. What is the security difference between them?", a: "PSK resumption still costs one RTT: the client presents the ticket in ClientHello, the server recognizes the PSK and derives keys from it, skipping certificate validation — but the ClientHello-to-response round-trip still happens, so the data is not replayable any more than normal 1-RTT data. 0-RTT goes further: the client encrypts the first request under the PSK and attaches it to ClientHello, before the handshake completes. That early data has no per-connection handshake nonce protecting it, so an attacker can capture and replay it. Hence 0-RTT is restricted to idempotent requests, and servers must return 425 Too Early for mutating routes." },

(3) Application-layer idempotency: only safe methods cross into early data, and frameworks return 425 Too Early for any handler that mutates state, so even a replay slipping past the first two layers cannot cause a harmful mutation." },

SNI is a separate problem: it is sent in plaintext in ClientHello so a shared-IP server can select the right certificate before it can decrypt anything, which leaks the visited hostname to on-path observers.
