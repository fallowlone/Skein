## Snippet 1 — the response headers

```
HTTP/2 200
cache-control: public, max-age=3600
vary: User-Agent, Accept-Encoding, Cookie
cf-cache-status: MISS
age: 0
```

## Snippet 2 — the Cache-Control line

```
Cache-Control: public, max-age=60, stale-while-revalidate=600, stale-if-error=86400
```

  lang="en"
  question="A product-listing endpoint sends this. Describe what the shared CDN cache does at second 0, second 120, and during an 8-minute origin outage at second 300."
  choices={[
    { label: "0–60 s: fresh, served from cache. At 120 s (past max-age, within SWR): serve the stale copy instantly to every request and fire exactly one background revalidation. During the outage past expiry: stale-if-error keeps serving the last good copy for up to 1 day instead of a 503.", correct: true },
    { label: "The response is uncacheable on the CDN because max-age is only 60 s.", misconception: "60 s is a perfectly valid shared-cache freshness window; public makes it CDN-cacheable. SWR and SIE then extend useful serving well past it." },
    { label: "At 120 s every request goes to origin because max-age expired.", misconception: "That is exactly what stale-while-revalidate=600 prevents: past max-age it serves stale to all and sends one background revalidation, so the herd never hits origin." },
    { label: "stale-if-error makes the CDN ignore 5xx forever and never refresh.", misconception: "stale-if-error only serves stale while origin is failing, for up to its window; on the next successful revalidation the CDN caches the fresh 200 and resumes normal behaviour." },
  ]}
/>

## Snippet 3 — the edge worker

```js
export default {
  async fetch(req, env) {
    const page = await fetch(req);                 // cacheable chrome + body
    const price = await fetch(env.PRICING_URL);    // per-user, never cached
    return new HTMLRewriter()
      .on("#price", { element(e) { e.setInnerContent(price.statusText); } })
      .transform(page);
  },
};
```

    { label: "The worker will exceed the 50 ms CPU wall-time because of the rewrite.", misconception: "A single innerContent rewrite is sub-millisecond of CPU, and I/O wait does not count against the wall-time budget. The defect is serialised I/O, fixed by parallelising the fetches." },
    { label: "Edge workers cannot call external services, so PRICING_URL fails.", misconception: "Edge workers routinely fetch external and regional services; that is a core use case. The real issue is doing the two fetches sequentially on the critical path." },

## Snippet 4 — the CDN trace

```
$ curl -sI https://example.com/article/42 | grep -iE 'cache|age|via'
cf-cache-status: HIT
age: 7200
cache-control: public, max-age=86400
```

Issue a CDN purge for the URL (or its cache-tag); it propagates to all POPs in 1–5 s, and wire that purge into the deploy pipeline so it happens automatically.", correct: true },
    { label: "age: 7200 means the entry already expired, so just wait a few seconds.", misconception: "age 7200 is well under max-age 86400, so the entry is still fresh and will serve for ~22 more hours. Only a purge (or TTL expiry) clears it now." },
    { label: "cf-cache-status: HIT proves the browser cache is stale; hard-refresh fixes it for everyone.", misconception: "HIT is the CDN edge cache, not the browser, and one user's refresh fixes nobody else. A CDN purge is what invalidates the shared edge copy for all users." },
    { label: "Lower max-age to 60 and redeploy; that releases the cached copy.", misconception: "Changing max-age only affects responses cached after the change; the already-cached entry keeps its original 86400 s window. You must purge to evict it now." },
  ]}
/>

<Recap lang="en">
Every CDN incident is read in headers and traces: a Vary header listing User-Agent or Cookie fragments the cache key per request and collapses hit rate; max-age plus stale-while-revalidate and stale-if-error define a freshness window, a stampede-safe stale window, and an outage fallback; an edge composition worker must parallelise its fetches and bound the volatile one with a timeout and fallback; and a HIT with age below max-age means a stale deploy that only a purge will clear. Diagnose from the artefact, apply the highest-leverage fix, then re-check the same header to confirm.
</Recap>
