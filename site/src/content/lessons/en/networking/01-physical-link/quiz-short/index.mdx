So chasing bandwidth (wider channels, mmWave's 400–800 MHz) beats chasing modulation order at high signal quality — 1024-QAM to 4096-QAM adds just 2 bits/symbol and demands a near-pristine RF environment. On a 10 Gbps / 160 ms path BDP = 200 MB. TCP can only have one receive-window's worth of bytes unacknowledged at a time; if the window is smaller than the BDP, the sender transmits a windowful then stalls a full RTT waiting for ACKs, and the link runs far below capacity. The legacy 64 KB window is ~3000× too small here, capping throughput near 3 Mbps on a 10 Gbps pipe. Window scaling (RFC 1323) lets the window grow into the MB–GB range so a sender can fill the pipe; modern kernels auto-tune buffers, and BBR models BDP explicitly to pace sends." },

Loss-based TCP like CUBIC only learns the link is full when a packet is dropped; an oversized buffer absorbs packets instead of dropping them, so TCP keeps inflating its window until the buffer is hundreds of ms deep. The symptom: idle ping is 20 ms, but the moment a bulk transfer saturates the uplink every interactive packet sits behind that queue and ping jumps to 300–500 ms — while throughput tests still read green. A faster uplink only raises the saturation ceiling; the same oversized buffer still fills under any bulk transfer, so ping still balloons. The fix is AQM (CAKE/fq_codel/PIE) shaped below line rate, which drops/marks early and caps queueing delay." },
