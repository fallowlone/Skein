    { q: "Why does GraphQL get N+1 when a REST controller over the same data usually does not?", a: "GraphQL resolvers are isolated by design: Post.author receives one post at a time and knows nothing about its siblings or how the parent was fetched, so there is no global query plan and no natural place to write a JOIN. The engine calls the author resolver once per post, producing one query per parent — 1 list query plus N per-item queries. A REST controller owns the whole response shape in one place, so the developer naturally writes a single JOIN. Isolation is what makes GraphQL composable, and it is also the direct cause of N+1." },
    { q: "When does DataLoader fire the batch, and why is the tick boundary better than a fixed timer?", a: "DataLoader queues every .load(key) call and dispatches the batch on the event-loop tick boundary — after the current synchronous frame and its microtasks, scheduled via enqueuePostPromiseJob (process.nextTick in Node, Promise.resolve().then in browsers). This is the earliest moment GraphQL has finished resolving one level and queued all its IDs, so the single WHERE id = ANY(...) fires with zero added latency. A fixed 5 ms timer would either wait unnecessarily on every request or fire before all IDs for the level were queued, splitting the batch." },
    { q: "Why must a DataLoader be instantiated per request, and what specifically breaks with a module-scope instance?", a: "A DataLoader instance is a cache, so its lifetime must be the request, not the process. A module-scope loader shares that cache across all requests: it returns stale rows (Request A loads user 7, the row updates, Request B reads the pre-update cached row) and leaks across tenants (Tenant B receives Tenant A's cached row for the same ID). Both are data-correctness bugs. Instantiate loaders inside the context factory so each request gets a clean, isolated cache that GC reclaims when the request ends." },
    { q: "State the batchLoadFn ordering contract and how you satisfy it, including missing rows.", a: "batchLoadFn(keys) must return an array of the same length as keys, with the value for each key at the matching position. Databases do not guarantee row order from WHERE id = ANY(...), so you build a Map keyed by id and walk the input keys: ids.map(id => map.get(id) ?? null). Return null for a nullable missing field, or an Error in that slot to reject only that key's .load() while the rest resolve. Throwing from the batch function instead rejects every pending .load() in the batch. For one-to-many loaders, return an empty array (never undefined) for parents with no children." },
    { q: "In a federated graph, what does the router batch for free, and what do you still owe inside the subgraph?", a: "When a query crosses subgraph boundaries, the supergraph router gathers all entity references (e.g. 50 User refs from the posts subgraph) and sends one _entities call with all 50 representations to the owning subgraph — the cross-subgraph network batch is automatic and free. Inside the subgraph, __resolveReference is still called once per representation. If each call hits the database directly, you get 50 SQL queries inside that single _entities call, so you still need a per-request DataLoader in __resolveReference to batch them into one." },
    { q: "DataLoader is live. List the query-shape defences it cannot replace, and what each stops.", a: "DataLoader only collapses DB trips during resolution; it cannot touch query shape. Depth limiting (7–10 levels) rejects recursive bombs at validation, before any resolver fires. Multiplicative complexity scoring sums field weights times list-argument size (cost = weight + sum(child.first × cost(child))), catching the 100^5-row expansion that field-count and depth checks miss. Persisted/trusted documents only execute pre-registered query hashes, closing the entire arbitrary-inline-query surface (APQ, by contrast, only saves bytes and does not constrain shape). Alias caps (≤20 root aliases) and operation-batch caps (≤5–10) stop resolver-count amplification that bypasses per-request rate limits. Each layer fails closed." },
