  question="Why does DataLoader batch on the event-loop tick boundary rather than a fixed 5 ms timer, and what does that buy you?"
  choices={[
    { label: "The tick boundary is the earliest moment every key for the current query level has been queued — so the batch fires with zero added latency, unlike a timer that either waits unnecessarily or fires before all IDs arrive.", correct: true },
    { label: "Node.js cannot implement a 5 ms timer for batching.", misconception: "Node supports setTimeout and setImmediate; DataLoader could use them. It chooses the microtask boundary specifically to avoid added latency." },
    { label: "A timer would use more memory than the tick boundary.", misconception: "Memory is set by batch size, not dispatch timing. The reason is latency: the tick boundary fires the instant the level's loads are all queued." },
    { label: "The tick boundary guarantees resolver execution order.", misconception: "Dispatch timing does not change resolver ordering. The benefit is firing at the earliest complete moment with no wait." },
  ]}

  choices={[

    { label: "Module scope disables batching, so each load fires its own query.", misconception: "Module scope does not disable batching within a tick; it shares the cache across requests. The leak and staleness are the defects, not lost batching." },
    { label: "The fix is to set cache:false on the loader.", misconception: "Disabling cache hides staleness but the instance is still shared across tenants. The real fix is per-request instantiation in the context factory." },

<Recap lang="en">
The unit's through-line is one pipeline: resolver isolation creates N+1, DataLoader collapses the DB trips at the tick boundary but only with per-request scope and a correct same-order batch contract, federation hands you the network batch while you still owe the DB batch in __resolveReference, and query-shape defences (depth, multiplicative complexity, persisted/trusted documents, alias and batch caps) stop the attacks DataLoader cannot touch. DataLoader fixes how many DB trips a query makes; the defence layers govern what query shapes are even allowed to run.
</Recap>
