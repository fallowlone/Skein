<Hook>
You have heard that Go powers Docker, Kubernetes, and half the servers you use every day — and that it is famously boring. Boring is the compliment: Go was designed so that a program written by a stranger is readable on first sight, compiles in seconds, and runs as a single file with no interpreter to install. This lesson is the map: what Go is for, how you run anything at all, and where this track goes next.

## What Go is for

Go was built at Google for one job: network services and command-line tools written by large teams that must stay readable for years. Three consequences follow, and they explain nearly every design choice you will meet:

## The one command that runs anything

Every Go journey starts the same way. Install the toolchain from go.dev, then:

```text
go run hello.go
```

That is the whole ceremony: `go run` compiles the file and executes the result in one step. When you are ready to ship, `go build` does the same thing but keeps the binary instead of running it. Modules (`go.mod`, created by `go mod init`) record which external packages your program needs — think of them as the project file. You will touch exactly three commands for the first half of this track: `run`, `build`, and `test`.

## Where this track goes

Unit `01-language-core` starts with the one idea Go is most opinionated about: values, not references, by default — and then errors as ordinary return values, which get their own junior lesson next door before the senior units assume them. Concurrency (`02`), HTTP services (`03`), and testing (`04`) build on that base in order. Nothing ahead assumes you have written Go before; everything ahead assumes you can run it.

<Inset kind="why" lang="en">
Why start a programming track without writing a program first? Because Go's toolchain IS the first lesson: in Python or JavaScript you can guess-and-run in a REPL, but Go programs live in files, in modules, built by commands. Learners who skip this page lose their first hour to "where do I put the file and how do I run it" — the two junior lessons after this one make sure that never happens to you.
</Inset>

<Recap lang="en">
Go is a compiled language for servers and tools: plain code in, one binary out, nothing to install where it runs. Its small surface plus strict tooling (`gofmt`, `go vet`) keeps strangers' programs readable, and servers, JSON, testing, and concurrency arrive in the standard library. Your loop is `go run` to develop, `go build` to ship, `go test` to verify. Next door: your first real program, then the one Go habit — errors as values — that every senior unit assumes before unit 01 teaches you types.
</Recap>
