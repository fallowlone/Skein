Open is the tripped state: every call is rejected instantly as an exception or fallback without touching the dependency at all; when the cooldown expires it transitions to half-open. Half-open is the probing state: a limited number of trial calls are allowed through to test recovery, and if they all succeed the breaker returns to closed and resets its counters, while if any fails it goes straight back to open and restarts the cooldown. So the four transitions are closed-to-open on too many failures, open-to-half-open on the timer, half-open-to-closed on success, and half-open-to-open on failure — and each transition is a decision about how much load to send a dependency whose health is uncertain. The window is either count-based (the last N calls, resilience4j defaults to 100) or time-based (the last T seconds in buckets, Hystrix uses 10 s split into ten one-second buckets), and it slides so only recent health counts. The minimum-volume floor (Hystrix requestVolumeThreshold 20, resilience4j minimumNumberOfCalls 100) requires the breaker to see at least that many calls before it can trip, because at low volume a rate is statistical noise — one failure out of one is 100% but tells you nothing. It is the single most important guard against a breaker flapping on a one-off blip, and the cost is asymmetric: a false trip is a self-inflicted outage while waiting a few more calls costs almost nothing." },

A bulkhead (named for a ship's watertight compartments) caps concurrency per dependency, giving each its own bounded allowance so a slow downstream can pin at most its own share while the rest stay available, containing failure to one compartment. The implementation is a real tradeoff. Thread-pool isolation gives each dependency a dedicated pool (Hystrix coreSize 10) and the caller waits with its own timeout, so it can walk away from a hung call even if the pool thread stays stuck — at the cost of a hand-off and context switch per call. Semaphore isolation is a near-zero-overhead counter (resilience4j maxConcurrentCalls 25) that runs on the caller's own thread but can only count: it cannot interrupt a call already blocking, so if the dependency hangs the calling thread hangs with it. The timeout (Hystrix defaults to 1 s) converts a hang into a countable failure; a breaker over an un-timed-out dependency silently does nothing. Once the breaker is open, calls are rejected instantly, but into what? The fallback is the answer, best to worst: a degraded-but-correct response that drops the broken feature and keeps the page, a last-known-good cache, a static default, queue-for-later via the outbox for writes, and a clean fail-fast 503 with Retry-After when no fallback is meaningful — chosen per call site, since a missing carousel must never fail the page while a missing payment authorization must fail the order. The real fleet danger is retries beneath the breaker, which multiply along a chain — Google's canonical 4×4×4 = 64 — into a retry storm; the fixes are to retry at one layer only, cap the absolute retry rate with a per-process budget like 60 per minute, use exponential backoff with jitter, and keep the breaker above the retries so an open circuit short-circuits the whole stack.
