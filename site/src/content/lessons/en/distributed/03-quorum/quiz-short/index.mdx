That shared node received the write and carries its (newest) version, so a read that takes the highest version across its R responses is guaranteed to see the latest committed write. The inequality must be STRICT: at R + W = N the sets can be perfectly disjoint (e.g. nodes {1,2} write and {3,4} read at N=4), and the read can legally miss the write. There is no leader, log, or consensus involved — just two subsets of N forced to intersect." },

The difference is failure tolerance. W=3 (write-ALL) fails every write the moment a single replica is down — a routine deploy, GC pause, or slow disk takes writes offline. Symmetrically R=3 (read-ALL) blocks every read on one slow node. QUORUM needs only 2 of 3 on EACH path, so it tolerates a single node down on both reads and writes while still guaranteeing overlap. That single-node-failure tolerance on both sides is why quorum, not ALL, became the default mental model. It generalises as floor(N/2)+1: 2 at RF=3, 3 at RF=5." },
    { q: "What does 'tunable consistency' mean operationally, and what does choosing R and W trade off?", a: "Tunable consistency means R and W are knobs you set per operation, often per query, not a single global mode. The same N=3 cluster can serve a W=1 fire-and-forget metrics write and a W=2/R=2 strongly-consistent balance read in the same process. Each choice slides you along the consistency/availability/latency triangle: higher R and W (up to ALL) buy stronger consistency and survive more divergence but reduce availability (more nodes must be up) and raise latency (you wait for more replicas); lower values buy speed and availability at the cost of possibly stale or lost data. The senior move is to set R and W per workload — strong where correctness matters, relaxed where loss is tolerable — and to know precisely which guarantee each choice keeps or forfeits." },
    { q: "Describe sloppy quorum plus hinted handoff, and state precisely what guarantee it suspends and when.", a: "Strict quorum requires W acks from the DESIGNATED replicas (the key's preference list); if too few are reachable, the write fails — downtime during a partition or multi-node outage. Sloppy quorum instead routes the write to the next healthy nodes on the ring, which store it as a HINT tagged 'this belongs to node X.' When X recovers, the holder replays the hint to it (hinted handoff) and deletes its copy. This keeps writes flowing through failures — the entire reason it exists. What it suspends: those hint-holders are NOT in the normal read set, so during the failure window a strict read of the home replicas can miss the hinted write entirely. R + W > N overlap is guaranteed only against the canonical replica set, and the write is temporarily off that set — so sloppy quorum does not satisfy overlap precisely while a designated node is down, which is exactly when you most want it." },

Both sides look healthy because no replica is faulty — the data is simply elsewhere. (3) R + W <= N drift: a sub-overlap mix like R=1,W=2 (sum 3 at N=3) lets a read pick the one lagging replica intermittently. Their relationship to overlap: they are the EVENTUAL-consistency backstop that pays back the consistency debt sloppy quorum and low R+W incur, converging divergent replicas after the fact.
