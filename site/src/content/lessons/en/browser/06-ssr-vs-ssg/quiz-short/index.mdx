When a node disagrees, React discards that subtree and re-renders it client-side — a visible content flash and a CLS spike. Common causes are all non-determinism between the two environments: reading Date.now()/new Date(), Math.random(), window/localStorage (undefined on the server), or Intl/timezone-sensitive formatting during render. The determinism rule: the first client render must be a pure function of the same inputs the server had — defer any environment-dependent value to a useEffect that runs after hydration, so both renders produce the same first-pass DOM." },

The fix is to embed the server's exact data snapshot in the HTML and reuse it for the first client render. Frameworks do this with the dehydrated query cache (React Query, Apollo, SWR): serialize the server's data into the HTML, rehydrate it on the client, render the first pass from that cache, and only then allow fresh fetches. The trade-off is document size — a large response inflates parse time, so sometimes you embed only above-the-fold data and refetch the rest post-hydration." },

<Recap lang="en">
If you could reconstruct each answer from memory, you hold the unit's spine: WHEN the HTML is produced spans SSG → ISR → SSR → streaming, trading freshness against server cost on the critical path; hydration is the ~2× re-render that runs on the user's device and gates interactivity (INP); the hydration contract breaks on any non-deterministic value read during render and on a data snapshot that differs from the server's; RSC is an orthogonal axis that removes server-only components from the client bundle entirely; and the right answer is always per-route, chosen by freshness, interactivity, and data latency.
</Recap>
