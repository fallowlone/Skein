Each property addition follows or creates an edge in a transition tree, so the resulting class depends on the sequence of additions, not just the final set. {x:1, y:2} walks empty → x → x+y; {y:2, x:1} walks empty → y → y+x and lands on a different leaf.     { q: "Describe the IC state machine and what triggers each transition.", a: "An inline cache is a per-call-site stub recording the hidden class V8 saw and the property offset for it. Uninitialized → monomorphic on the first call (one class, ~5–10 cycle direct read). Monomorphic → polymorphic when a second distinct class appears (the IC holds 2–4 class/handler pairs, a short branch chain, still fast). Polymorphic → megamorphic at the 5th distinct class: V8 abandons per-class tracking and installs a generic runtime lookup at ~50–100 cycles — 10–50× slower. Transitions are one-way; V8 never demotes a site from megamorphic back to polymorphic, so you fix the problem upstream by feeding the site one shape." },
    { q: "Name V8's four JIT tiers in order and the niche each fills.", a: "Ignition (bytecode interpreter): zero compile cost, ~10× slower than optimised code, and it writes type feedback into the FeedbackVector. Sparkplug (baseline JIT, V8 9.1/2021): a single linear bytecode-to-machine-code pass, no specialisation, ~1 ms/kB, ~1.5–2× over Ignition for fast warm-up. Maglev (mid-tier, 2023): SSA-based specialisation on observed types in ~10 ms, ~50–70% of TurboFan quality, for medium-hot code. TurboFan (heavy optimiser): sea-of-nodes IR, inlining, escape analysis, speculative guards, ~100 ms compile, fastest code — reserved for hot, type-stable functions. Profile-guided tiering promotes a function up the ladder only when its FeedbackVector is stable enough to justify the compile cost." },
    { q: "What distinguishes a one-time deopt from a deopt-loop, and why is the loop catastrophic?", a: "TurboFan installs a guard before each speculation ('this is a Smi', 'this object has hidden class HCx'). A one-time deopt: a guard fails once, V8 discards the optimised code and falls back to Ignition, the function re-warms with feedback that now includes the exception case, and re-optimises stably — cost is a few microseconds plus one recompile. A deopt-loop: the guard-failing condition is present on every call, so V8 deopts, immediately re-promotes (the function is still hot), recompiles with the same wrong assumption (~100 ms), and deopts again. Per cycle that is ~12 µs of bookkeeping plus a 100 ms compile plus time spent in the slower tier — orders of magnitude worse than never optimising. Fix: route the pathological value to a slow path before the hot loop so the fast path stays type-stable." },
    { q: "How does Orinoco split GC work, and why does concurrent marking need a write barrier?", a: "Orinoco is generational. The young generation (~1–8 MB) is collected by a parallel copying Scavenger with work-stealing — pauses under ~1 ms because the live set is small; survivors of two minor GCs are promoted. The old generation uses Mark-Compact with concurrent marking: a background thread traces the live graph while JS runs, cutting the main-thread pause from hundreds of ms to single-digit ms. Because the mutator can rewire references mid-mark, V8 uses a snapshot-at-the-beginning write barrier: when the main thread overwrites a reference, the barrier shades the overwritten (white) referent grey so the marker still visits it. Without it, a black object could hold the only link to a white object that never gets marked and is wrongly collected — silent heap corruption. The barrier costs ~3–5 cycles per reference write." },

It is the right tool for numeric-heavy hot loops (particle systems, 3D, audio, ML), for pre-allocated buffers that avoid per-frame allocation and therefore GC pressure, and for any workload where even a monomorphic object IC is still the bottleneck. The cost is ergonomics: a fixed element type, no named properties, less idiomatic code. For a 10M-entity-per-frame animation loop, parallel TypedArrays remove both the megamorphic-IC and the per-frame-GC problems simultaneously." },
