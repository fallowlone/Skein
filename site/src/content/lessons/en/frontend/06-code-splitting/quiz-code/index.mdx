## Snippet 1 — where the boundary sits

```jsx
// A: import at module top — bundled into the parent chunk
import { HeavyEditor } from "./HeavyEditor";

function EditPanel({ open }) {
  if (!open) return null;
  return <HeavyEditor />;
}

// B: dynamic import inside the gate
const HeavyEditor = React.lazy(() => import("./HeavyEditor"));

function EditPanel({ open }) {
  if (!open) return null;
  return (
    <Suspense fallback={<Spinner />}>
      <HeavyEditor />
    </Suspense>
  );
}
```

## Snippet 2 — nested Suspense boundaries

```jsx
const Dashboard = React.lazy(() => import("./Dashboard"));
const Chart = React.lazy(() => import("./Chart"));

function Page() {
  return (
    <Suspense fallback={<PageSkeleton />}>
      <Dashboard>
        <Suspense fallback={<ChartSpinner />}>
          <Chart />
        </Suspense>
      </Dashboard>
    </Suspense>
  );
}
```

## Snippet 3 — prefetch on hover

```jsx
const Settings = React.lazy(() => import("./Settings"));

function NavLink() {
  return (
    <a
      href="/settings"
      onMouseEnter={() => import("./Settings")}
    >
      Settings
    </a>
  );
}
```

    { label: "It is a no-op — calling import() twice on the same module downloads it twice.", misconception: "import() caches the module promise; the second call resolves from the same in-flight or completed request. The hover call warms the cache so the click does not pay the round trip." },
    { label: "It eagerly bundles Settings into the parent chunk, defeating the split.", misconception: "import() is still a split point — Settings stays a separate chunk. The handler only changes when that chunk is requested (on hover) without merging it into the parent." },
    { label: "It blocks navigation until the chunk fully downloads.", misconception: "The handler fires a fetch and returns immediately; it does not block. It is a low-cost speculative prefetch that flattens the click-time waterfall." },
  ]}

<Recap lang="en">
Three things decide splitting behaviour in code: a static top-level import is always bundled into the parent chunk, so only import() creates a split point — and a runtime condition does not change that. Nested React.lazy boundaries are discovered sequentially, so each level adds a round trip on a high-RTT link. And firing import() early (on hover or idle) warms the chunk cache so the eventual mount skips the waterfall and the spinner. Read where the boundary sits and when the fetch is triggered, then move the trigger earlier rather than merging the chunk back in. Now when you review a PR with nested React.lazy components, your first check is whether those boundaries are sequential on the critical path — if they are, ask for a preload hint or a flattened boundary before the code ships.
</Recap>
