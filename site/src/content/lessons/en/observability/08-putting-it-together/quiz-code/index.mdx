## Snippet 1 — the multi-window burn-rate alert

```yaml
# SLO: 99.9% availability over 30 days. Error budget = 0.1%.
- alert: CheckoutFastBurn
  expr: |
    (
      sum(rate(http_requests_total{job="checkout",code=~"5.."}[5m]))
      / sum(rate(http_requests_total{job="checkout"}[5m]))
    ) > (14.4 * 0.001)
    and
    (
      sum(rate(http_requests_total{job="checkout",code=~"5.."}[1h]))
      / sum(rate(http_requests_total{job="checkout"}[1h]))
    ) > (14.4 * 0.001)
  for: 2m
```

## Snippet 2 — the traceparent header

```
traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01
```

  choices={[
    { label: "Keep the trace-id (4bf9...4736) unchanged, treat the parent-id (00f0...02b7) as its parent span, generate a NEW span-id for its own work, and propagate trace-flags (01 = sampled) downstream. Reusing the same span-id would collapse two spans into one.", correct: true },
    { label: "Generate a fresh trace-id for its own work and link back via tracestate.", misconception: "A new trace-id breaks the trace into two disconnected trees — the whole point of propagation is that the trace-id is constant across every hop. Only the span-id changes." },
    { label: "Reuse all four fields verbatim so the trace stays consistent.", misconception: "Reusing the incoming span-id as your own span-id merges your span with the caller's, destroying the parent/child causal graph. You inherit the trace-id and parent-id but mint a new span-id." },
    { label: "Drop the header because 01 means the trace is already complete.", misconception: "01 in trace-flags is the sampled bit (keep this trace), not a completion flag. Dropping the header severs propagation and orphans every downstream span." },
  ]}

## Snippet 4 — the correlated log line

```json
{"level":"error","ts":"2026-05-29T02:14:07Z","service":"inventory",
 "msg":"marshal failed: schema v3 field overflow","trace_id":"4bf92f3577b34da6a3ce929d0e0e4736",
 "span_id":"00f067aa0ba902b7","http.route":"/inventory/lookup"}
```

<Recap lang="en">
Four artefacts, one chain. The multi-window burn-rate query fires the alert (short window for speed, long window for confirmation, 14.4x = 2-day budget burn). The traceparent header keeps the trace-id constant while minting a new span-id at each hop. The flame graph names the widest leaf as the self-time hotspot — optimise the leaf, not the ancestor. And the structured log carries the same trace_id, so it joins precisely to that request. Read in sequence, these are the funnel made concrete.
</Recap>
