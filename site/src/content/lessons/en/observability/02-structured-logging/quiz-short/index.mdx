Convention names — http.response.status_code, not status; http.route, not path — matter because they are shared across services, languages, and vendors: one dashboard or alert rule works uniformly everywhere without per-service translation.     { q: "What does each rung of the level ladder mean, and how does it drive alert routing? Why is misclassification dangerous?", a: "TRACE/DEBUG are off in production (DEBUG via dynamic flag only). INFO is the success path — state changes that let you reconstruct normal behaviour. WARN is recoverable issues (retry succeeded, fallback taken) and routes to dashboards/Slack. ERROR is unrecoverable work left undone (5xx, dead-letter, rollback) and pages on-call. FATAL is imminent process death and pages immediately. The level is a contract about the action implied, so routing follows directly. Over-classification (recoverable issue logged as ERROR) floods on-call and causes alert fatigue — the most dangerous outcome because real errors get buried. Under-classification (unrecoverable issue logged as WARN) makes failures invisible until they escalate." },
    { q: "Describe the three sampling strategies and why sampling belongs at the collector, not the application.", a: "Success-path sampling keeps 1-in-N (N=10-100) INFO lines while keeping 100% of WARN/ERROR — the first lever, cutting INFO ~90% without touching failure forensics. Pattern-based sampling keeps each distinct message template at full rate and samples the chatty duplicates (Vector/Fluent Bit hash the template). Tail sampling buffers a request's logs and decides on outcome — keep everything for failed requests, sample successes — guaranteeing zero failure loss but requiring a stateful buffer. All belong at the collector tier: it keeps application code simple, lets the platform team manage one central policy across the fleet, and is the only place tail sampling (which needs cross-request buffering) is practical. Pair with retention tiering (hot 7-15d, warm 30-90d, cold S3 ~$0.023/GB-mo) to keep the audit trail without indexed-storage cost." },
