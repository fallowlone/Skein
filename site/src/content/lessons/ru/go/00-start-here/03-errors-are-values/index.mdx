<Hook>
В большинстве языков, когда что-то идёт не так, код бросает исключение, летящее вверх по стеку вызовов, пока что-то его не поймает, — возможно далеко, возможно никогда. Go удалил весь этот механизм. Нет `try`, нет `catch`, нет `throw`. Вместо этого функция, которая может упасть, просто возвращает свою ошибку рядом с результатом, и ты на неё смотришь. Прямо там. Каждый раз.

<Crux>Ошибки — обычные возвращаемые значения: падающая функция возвращает <code>(result, err)</code>, а вызывающий проверяет <code>if err != nil</code> немедленно, — без исключений, без скрытого управления.</Crux>

<Explanation>

## Двухстрочный if

Функция чтения файла возвращает не только содержимое. Она возвращает две вещи:

      <tr class="bg-surface-2">

      </tr>
    </thead>

        <td class="border border-border px-3 py-2">Вызываем. Получаем данные И значение ошибки — <code>err</code> равен <code>nil</code> (ничему), когда всё прошло хорошо.</td>
      </tr>
      <tr class="bg-surface-2">
        <td class="border border-border px-3 py-2"><code>if err != nil &#123;</code></td>
        <td class="border border-border px-3 py-2">Если что-то пошло не так (ошибка — не ничто)…</td>
      </tr>
      <tr>
        <td class="border border-border px-3 py-2"><code>return err &#125;</code></td>
        <td class="border border-border px-3 py-2">…останавливаемся и отдаём ошибку СВОЕМУ вызывающему. Готово — три строки, без драмы.</td>
      </tr>
    </tbody>

Этот паттерн — вызов, проверка, ранний возврат — примерно треть всего когда-либо написанного Go-кода. Ты наберёшь его тысячу раз, а после пятидесятого он станет невидимым: глаза будут скользить мимо рамок `if err != nil` прямо к строкам, где реально что-то происходит.

## Три правила вместо исключений

**Первое: обрабатывай там, где случилось.** Проверка стоит рядом с вызовом, а не десятью фреймами выше по стеку. Читая Go, каждый сбой обработан ровно на строке, которая могла упасть, — нет археологии «а где это ловилось?».

**Второе: `nil` значит порядок.** Значение ошибки `nil` значит: ничего не случилось. Это единственная конвенция: никаких булевых флагов, никакой ловли по типам. `err != nil` — полная проверка, везде.

**Третье: возвращай, если не твоё.** Большая часть обработки ошибок в Go — просто передача проблемы выше: `return err`. Только слой, знающий, что делать — повторить, откатиться, сказать пользователю, — превращает ошибку в действие. Всё между пересылает её без изменений. Юнит `01-language-core` строит поверх этой привычки настоящие механизмы; сама привычка не меняется никогда.

<Inset kind="why" lang="ru">
Не чудовищно ли многословно писать `if err != nil` после каждого вызова? Так кажется ровно неделю. Затем случаются две вещи: выровненные `gofmt` рамки ошибок становятся визуально беззвучными, и ты понимаешь, что купила многословность, — каждая функция документирует свой отказ в сигнатуре (`string, error`), и ни один отказ не может молча телепортироваться мимо тебя, как непойманное исключение. Go обменял три сэкономленные строки на ноль невидимого управления, и команды, поддерживающие код годами, считают сделку выгодной.
</Inset>

<Recap lang="ru">
В Go нет исключений: падающие функции возвращают <code>(result, err)</code>, а ты проверяешь <code>err != nil</code> немедленно. <code>nil</code> значит порядок — бери результат. Всё остальное значит отказ — обработай здесь или <code>return err</code> тому, кто знает что делать. Обрабатывай там, где случилось, пересылай остальное, никогда не доверяй данным рядом с не-nil ошибкой. С тулчейном, первой программой и этой привычкой ты владеешь всем, что предполагает юнит 01: дальше он учит типам, а каждый тип в Go несёт ошибки ровно так."
</Recap>
