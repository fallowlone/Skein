## Артефакт 1 — CPU-профиль

```
(pprof) top5 -cum
      flat  flat%   sum%        cum   cum%
         0     0%     0%      8.10s 92.0%  net/http.(*conn).serve
     0.02s  0.2%   0.2%      7.40s 84.1%  app.(*Handler).Search
     0.05s  0.6%   0.8%      6.90s 78.4%  app.scoreAll
     6.10s 69.3%  70.1%      6.40s 72.7%  app.cosineSim   <-- flat
     0.30s  3.4%  73.5%      0.55s  6.2%  encoding/json.Marshal
```

`flat%` — доля времени, которую функция тратит сама (без вызовов вниз); `cum%` (cumulative) — суммарная доля вместе со всем, что она вызывает. Именно `flat%` показывает, где работа реально делается.

## Артефакт 2 — hot path

```go
// app.scoreAll — вызывается раз на поисковый запрос, ~10k кандидатов
func scoreAll(q []float32, candidates []Doc) []Result {
    var results []Result                    // nil slice
    for _, d := range candidates {
        v := append([]float32{}, d.Vector...) // свежая копия на кандидата
        results = append(results, Result{d.ID, cosineSim(q, v)})
    }
    return results
}
```

SELECT name FROM customers WHERE id = $1   -- params: 11

SELECT name FROM customers WHERE id = $1   -- params: 13
... (ещё 47 запросов той же формы) ...
-- итого: 51 запрос, 1 request

<Recap lang="ru">
Четыре артефакта, одна дисциплина. Профиль `top -cum` отличает корневой фрейм (огромный cumulative, нулевой рычаг) от настоящего хотспота (высокий flat); сниппет hot path показывает трату на аллокацию, которую предсказал профиль; лог запросов вскрывает N+1 по его повторяющейся single-row форме; отчёт по bundle превращает байты в цену CPU устройства. В каждом случае фикс живёт на собственном слое цены — устрани аллокацию, батчи round-trip'ы, обрежь байты — а не на одну ручку в стороне от того, куда указывают улики. Теперь, когда откроешь профиль, лог запросов или bundle-отчёт, ты знаешь, какую колонку читать первой и к какому слою тянуться — до того как тронешь хоть строчку кода.
</Recap>
