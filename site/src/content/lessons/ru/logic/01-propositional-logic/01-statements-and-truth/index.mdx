<Crux>Высказывание — предложение ровно с одним значением истинности; условие if становится им, как только переменные связаны.</Crux>

Зачем это вам как разработчику: каждый `if`, `while` и тернарник, который вы пишете, — это вопрос рантайма «истинно ли это утверждение?». Разберитесь, что делает предложение по-настоящему истинным-или-ложным, и целый класс тихих багов — значение, которое *выглядит* ложным, но таковым не является, — перестанет заставать вас врасплох в проде.

<Explanation>

## Предложение, обязанное выбрать сторону

**Высказывание** (по-английски *proposition*) — это повествовательное предложение, которое либо истинно, либо ложно: ровно одно из двух, никогда оба сразу и никогда ни одно. Это единственное правило — фундамент всей логики, и оно отсеивает большую часть человеческой речи:

- «7 — чётное число» — высказывание. Оно **ложно**, и это нормально: ложные утверждения остаются полноценными высказываниями. Входной билет — наличие значения истинности; какое оно — вопрос второй.
- «HTTP-запрос вернул статус 200» — высказывание: в реальном мире это либо так, либо нет.
- «Закрой дверь!» — не высказывание. Команду нельзя назвать истинной или ложной; её можно выполнить или проигнорировать.
- «Сервер работает?» — не высказывание. Вопрос запрашивает значение истинности, но сам его не несёт.
- «Эта пицца восхитительна» — пограничный случай. Как сообщение о личном вкусе оно не имеет объективной истинности, и классическая логика его не принимает.

Два значения истинности обычно записывают как **И** и **Л** (или **T** и **F**), а в программировании — `true` и `false`. Логике всё равно, *о чём* высказывание — о серверах, числах или начинке пиццы; её интересует только этот один бит. Именно такая безжалостная редукция делает логику переносимой: одни и те же законы управляют математическим доказательством и правилом файрвола.

<Inset kind="why" lang="ru">
Почему логика настаивает на *ровно одном* значении истинности? Потому что всё дальнейшее — доказательства, эквивалентности, таблицы истинности из следующего урока — работает, отслеживая, как истинность перетекает из малых утверждений в большие. Если бы предложение могло быть одновременно истинным и ложным или ни тем ни другим, эта бухгалтерия рухнула бы: можно было бы «доказать» что угодно. У программирования та же аллергия. Булева колонка, которая может быть `true`, `false` или `NULL`, — знаменитый источник багов именно потому, что третье состояние ломает все допущения, написанные для двух. Когда инженер требует, чтобы флаг был «настоящим булем», он требует статуса высказывания.
</Inset>

## Открытые предложения: почему «x > 3» — ещё не высказывание

Теперь взгляните на предложение «x > 3». Истина или ложь? Сказать нельзя — всё зависит от того, чему равен `x`. Предложение со **свободной переменной** (заполнителем без значения) называется **открытым предложением**, или *предикатом*. Это не высказывание, а *машина для производства высказываний*. Подставьте значение — и оно замкнётся:

- Свяжем `x = 7` → «7 > 3» — высказывание, причём истинное.
- Свяжем `x = 1` → «1 > 3» — тоже высказывание, но ложное.

Присвоение переменной значения называется **связыванием**. Пока в предложении остаётся хоть одна свободная переменная, значения истинности у него нет — так же, как у функции нет возвращаемого значения, пока её не вызвали:

```js
function isBig(x) {
  return x > 3;      // открытое предложение: x свободен, значения истинности нет
}

isBig(7);   // связывает x = 7 → высказывание «7 > 3» → истина
isBig(1);   // связывает x = 1 → высказывание «1 > 3» → ложь
```

Это не метафора, а одна и та же структура. Параметр функции *и есть* свободная переменная; вызов *и есть* связывание. Каждый раз, когда вы пишете `if (count > limit)`, вы создаёте открытое предложение на этапе написания кода и доверяете рантайму связать `count` и `limit` реальными значениями в момент выполнения, превратив его в высказывание, которое можно вычислить. Если одна из переменных так и не получила значения, связывание тихо идёт не туда: в JavaScript `50000 > undefined` вычисляется через `NaN` и даёт `false` — ваше открытое предложение стало высказыванием, только не тем, которое вы имели в виду.

## Ваш if — фабрика высказываний

Каждый `if`, `while` и тернарный оператор в коде — это рантайм, который строит и вычисляет высказывание. Условие — открытое предложение, написанное вами; выполнение связывает переменные; результат обязан схлопнуться в один бит: войти в ветку или нет. Именно на последнем шаге языки расходятся — и именно там родилась авария из пролога.

Строгие языки требуют, чтобы условие было настоящим булем. JavaScript вместо этого **приводит типы**: любое значение втискивается в истину или ложь по правилам truthiness. Непустые строки, ненулевые числа, любые объекты → truthy. Только `false`, `0`, `""`, `null`, `undefined` и `NaN` (плюс `0n`) → falsy. Поэтому:

```js
const isAdmin = "false";   // непустая строка

if (isAdmin) {
  // ВСЕГДА выполняется: Boolean("false") === true
  showRefundsDashboard();
}

// Высказывание, которое вы имели в виду:
if (isAdmin === true) {
  // выполняется только для настоящего булева true
}
```

Условие `if (isAdmin)` действительно вычисляет высказывание — но это высказывание «значение в isAdmin — truthy», то есть утверждение *о значении в памяти*, а не утверждение «этот пользователь — администратор», которое вы имели в виду. Баг — это подмена высказываний. Защита — держать их склеенными: превращать недоверенный ввод (строки конфига, переменные окружения, query-параметры — всё это всегда строки) в настоящие були на границе системы и сравнивать строго, чтобы высказывание, которое вычисляет код, совпадало с высказыванием из спецификации.

<Recap lang="ru">
Высказывание — это повествовательное предложение ровно с одним значением истинности: истина или ложь, никогда оба и никогда ни одно. Команды, вопросы и дела вкуса тест не проходят; ложные утверждения проходят, потому что входное условие — нести значение истинности, а не быть истинным. Предложение со свободной переменной, как x &gt; 3, — открытое предложение: само по себе не высказывание, а шаблон, который становится им после связывания каждой переменной значением — x = 7 даёт истинное «7 &gt; 3», x = 1 — ложное. Код зеркалит это точно: параметр функции — свободная переменная, вызов — связывание, а каждое условие if — открытое предложение, написанное на этапе кодирования, которое рантайм замыкает при выполнении в высказывание и вычисляет, выбирая ветку. Опасная зона — зазор между высказыванием, которое вы имели в виду, и тем, которое строит машина: неприсвоенная переменная всё равно связывается (с undefined, отчего 50000 &gt; undefined через NaN даёт false), а языки с приведением типов вычисляют truthiness, а не смысл, и непустая строка 'false' ведёт if так же уверенно, как true. Отсюда дисциплина: превращайте недоверенный строковый ввод в настоящие були на границе, сравнивайте строго и всегда умейте сказать одним предложением, какое именно высказывание вычисляет ваше условие.
</Recap>
