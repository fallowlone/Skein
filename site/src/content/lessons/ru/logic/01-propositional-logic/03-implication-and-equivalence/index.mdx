<Crux>p → q ложно лишь когда p истинно, а q ложно; ложное p даёт вакуумную истину. Лишь контрапозиция говорит то же самое.</Crux>

<Explanation>

## Единственная строка, где обещание нарушено

**Импликация** `p → q` читается «если p, то q»: p — *антецедент* (условие), q — *консеквент* (обещание). У её таблицы истинности форма, которую стоит запомнить: ложь ровно в **одной** строке.

| `p` | `q` | `p → q` |
|-----|-----|---------|
| И   | И   | И       |
| И   | Л   | **Л**   |
| Л   | И   | И       |
| Л   | Л   | И       |

Лучшая ментальная модель — обещание: «Если сдашь экзамен, куплю тебе мороженое». Когда я *нарушил* слово? Только в одном мире: ты сдал, а мороженого нет — p истинно, q ложно. Сдал и получил мороженое: сдержал. Не сдал, но мороженое всё равно купил: про этот случай я ничего не обещал — не нарушено. Не сдал, мороженого нет: тоже не нарушено. Обещание невиновно, пока не доказано нарушение, а единственное доказательство — «условие выполнено, обещание нет».

Заметьте, чего импликация *не* утверждает: ни причинности, ни связи по смыслу, ни механизма. `p → q` — чистое ограничение на значения истинности, и потому она напрямую компилируется в код. Раз она ложна только при истинном p и ложном q, она эквивалентна `!p || q`:

```js
// Правило: если у заказа есть купон, купон должен быть валиден.
const satisfiesRule = (order) => !order.coupon || isValid(order.coupon);
// «p влечёт q» === «не p, или q» — одно из наиболее полезных кодирований в программировании
```

## Вакуумная истинность: правила ни о чём соблюдены

Две нижние строки таблицы говорят: когда `p` ложно, `p → q` истинно *при любом q*. Это **вакуумная истинность** — правило соблюдено, потому что его ни разу не проверили делом. «Если у заказа есть купон, он должен быть валиден» выполняется заказом без купона; «все единороги в этой комнате зелёные» — истина о пустой комнате. Ничто не сделало утверждение ложным, значит, оно стоит.

Это не философский курьёз — на нём построена ваша стандартная библиотека:

```js
[].every(n => n > 0);          // true — vacuously: no element can fail the test
[].some(n => n > 0);           // false — no element can pass it either

const orders = [];
orders.every(o => isValid(o.coupon));   // true: "all zero orders comply"
```

`every()` по пустому массиву возвращает `true`, потому что «для всех x верно P(x)» — это цепочка импликаций, в которой ни один антецедент не истинен. Код вида `if (items.every(ok)) proceed()` *продолжит работу на пустом списке* — обычно это правильно, иногда это баг, но это всегда должно быть осознанным решением. Новичок из пролога врезался в противоположную сторону: он превратил «если купон, то валиден» в «купон обязан существовать и быть валидным», усилив `p → q` до `p && q`. А это радикально разные высказывания: второе ложно для каждого заказа без купона — ровно это и уложило чекаут.

## Обратное, противоположное, контрапозиция

Из `p → q` можно изготовить три родственных утверждения, и их путаница — одна из старейших ошибок мышления в истории:

- **Обратное** (converse): `q → p` — стрелка развёрнута. **Не равносильно.**
- **Противоположное** (inverse): `!p → !q` — обе стороны отрицены. **Не равносильно** (это обратное в другой одежде).
- **Контрапозиция** (contrapositive): `!q → !p` — развёрнуто *и* отрицено. **Равносильно**: та же таблица истинности, то же высказывание в другом костюме.

Возьмём «если пользователь премиум, он не видит рекламу» (`premium → noAds`). Обратное — «если он не видит рекламу, он премиум» — не следует: бесплатный триал тоже может прятать рекламу. Код, который выводит премиум-статус из отсутствия рекламы, совершает **ошибку обратного** (она же *подтверждение консеквента*) — и она постоянно уезжает в прод в виде логики «этот симптом означает ту причину». Противоположное — «если не премиум, то видит рекламу» — рушится так же и по той же причине. А вот контрапозиция — «если пользователь видит рекламу, он не премиум» — *гарантирована* исходным правилом. Сверьте с таблицей: `p → q` и `!q → !p` ложны ровно в одной и той же строке.

## Guard clauses — это контрапозиция в действии

Контрапозиция — не экзаменационная мелочь: вы пишете её каждый день. Возьмём правило «если мы обрабатываем запрос, он должен быть аутентифицирован» (`process → authed`). Его контрапозиция: «если не аутентифицирован — не обрабатываем». Это предложение *и есть* guard clause:

```js
// Правило:         process → authed
// Контрапозиция:   !authed → !process  — то же правило, переформулированное как поток управления
function handle(req) {
  if (!req.authed) return reject(req);   // охранник: применяем контрапозицию
  if (!isValid(req.body)) return reject(req);
  process(req);                          // здесь доказуемо выполняются все правила
}
```

Каждый ранний return выбивает один случай `!q`, и то, что доживает до низа функции, удовлетворяет всем правилам — плоско, читаемо и логически тождественно пирамиде вложенных if, которую оно заменяет. Наконец, когда импликация работает в *обе* стороны — `p → q` и `q → p`, — утверждения **эквивалентны**, что записывается `p ↔ q` («тогда и только тогда»). Эквивалентность — лицензия на подстановку: заменить условие на эквивалентное (переписка по де Моргану, охранник-контрапозиция) безопасно в любом контексте, а заменить на обратное — баг с таймером замедленного действия.

<Inset kind="why" lang="ru">
Почему «из лжи следует что угодно» определено как истина, а не как ложь или неопределённость? Потому что универсальные утверждения должны переживать нерелевантные случаи. Возьмём «каждое кратное четырёх чётно» — очевидно верно, а формально это импликация: если x кратно 4, то x чётно, для всех x. Проверим x = 3: антецедент ложен. Если бы ложный антецедент делал импликацию ложной, x = 3 опровергал бы верную теорему о кратных четырёх — абсурд: утверждение про тройку ничего и не говорило. Если бы делал её неопределённой, every() по списку с одним нерелевантным элементом тоже стал бы неопределённым. Считать непроверенный случай истинным — единственный выбор, позволяющий правилам квантифицировать по неопрятному миру, отвечая лишь там, где они реально применимы.
</Inset>

<KeyTakeaway>p → q рушится только при истинном p и ложном q; ложное p удовлетворяет его вакуумно — поэтому every() на пустом массиве истинно, а заказы без купона проходят правило о купоне. Эквивалентна лишь контрапозиция ¬q → ¬p; обратное и противоположное — ловушки. Guard clauses — контрапозиции, скомпилированные в поток управления.</KeyTakeaway>

<Recap lang="ru">
Импликация p → q — обещание, ложное ровно в одной строке таблицы истинности: антецедент истинен, консеквент ложен — условие выполнено, обещание нарушено. Она не утверждает причинности, только ограничение на значения истинности, и потому напрямую компилируется в !p || q. При ложном p импликация вакуумно истинна: правило не проверялось, значит, стоит — пустой массив проходит every(), заказ без купона удовлетворяет «если есть купон, он валиден», а комната без единорогов делает всех своих единорогов зелёными. Усиление импликации до конъюнкции (требовать p И q) — другое, куда более сильное высказывание; разница — ровно все случаи, где p не выполняется, и так «исправление недостающей валидации» становится аварией. Из p → q строятся обратное q → p, противоположное !p → !q и контрапозиция !q → !p; равносильна лишь контрапозиция, разделяющая таблицу оригинала, а обратное и противоположное — равносильные друг другу — образуют ловушку подтверждения консеквента: «нет рекламы, значит, премиум» рушится, как только рекламу спрячет другой тариф. Guard clauses обналичивают равносильность: «если обрабатываем, то аутентифицирован» становится ранним выходом «если не аутентифицирован — отклонить», и стопка охранников оставляет низ функции в состоянии, где доказуемо выполняются все правила. Полная эквивалентность p ↔ q — обе стрелки сразу — лицензия свободно подставлять условия; всё меньшее — переписка, которую надо оправдывать строка за строкой.
