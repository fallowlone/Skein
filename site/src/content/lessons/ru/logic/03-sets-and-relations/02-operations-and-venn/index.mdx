## Четыре операции, один универсум

Возьмём два множества над одним сортом значений — скажем, `A = {1, 2, 3}` и `B = {3, 4}`. Существует ровно четыре классических способа их соединить, и каждый определяется правилом принадлежности:

- **Объединение** A ∪ B — элементы из A *или* из B (или из обоих): `{1, 2, 3, 4}`.
- **Пересечение** A ∩ B — элементы из A *и* из B: `{3}`.
- **Разность** A ∖ B — элементы A, которых *нет* в B: `{1, 2}`. Заметьте направление: B ∖ A — это `{4}`, другое множество.
- **Дополнение** — всё, что *не* в A. Эта операция идёт с условием: «всё» нужно сначала объявить. Что лежит за пределами множества ваших пользователей — другие люди? числа? чайники? Дополнение имеет смысл только внутри заявленного **универсума** U — множества всего, о чём идёт речь. Если U — все зарегистрированные аккаунты, то дополнение «подписанных аккаунтов» — это в точности «зарегистрированные, но не подписанные». Нет универсума — нет дополнения.

Каждое определение выше — *правило* принадлежности, и эти правила собраны из связок, знакомых вам по логике высказываний:

- x ∈ A ∪ B означает x ∈ A **или** x ∈ B,
- x ∈ A ∩ B означает x ∈ A **и** x ∈ B,
- x ∈ A ∖ B означает x ∈ A **и не** x ∈ B,
- x в дополнении A означает **не** x ∈ A.

Это самый глубокий факт урока: операции над множествами — не новая теория. Это ИЛИ, И и НЕ, применённые к утверждениям о принадлежности. Каждый закон, который вы выучили о связках, переносится на множества бесплатно.

```python
a = {1, 2, 3}
b = {3, 4}

a | b   # объединение   → {1, 2, 3, 4}   («или»)
a & b   # пересечение  → {3}            («и»)
a - b   # разность     → {1, 2}         («и не»)
b - a   # в другую сторону              → {4}
```

И те же операции возникают всюду, где условие отбирает строки. SQL-запрос `WHERE active AND beta` возвращает пересечение множества активных и множества бета-участников; `filter` с двумя предикатами, соединёнными `&&`, — пересечение, вычисляемое по одному тесту принадлежности за раз:

```js
const inBoth = users.filter((u) => isActive(u) && isBeta(u));   // A ∩ B
const inEither = users.filter((u) => isActive(u) || isBeta(u)); // A ∪ B
const activeOnly = users.filter((u) => isActive(u) && !isBeta(u)); // A ∖ B
```

## Диаграммы Венна: области, на которые можно показать

**Диаграмма Венна** рисует каждое множество кругом внутри прямоугольника (универсума). Два пересекающихся круга режут прямоугольник ровно на четыре области, и каждое значение U живёт ровно в одной из них: только в A, в обоих, только в B, ни в одном. Каждая операция тогда — *выбор областей*: объединение закрашивает три области, пересечение — центральную линзу, разность A ∖ B — левый полумесяц, а дополнение A ∪ B — только наружную часть.

Читайте диаграмму Венна как карту: не спрашивайте «что значит ∩» абстрактно — спрашивайте, *какие области закрашены*. С тремя кругами прямоугольник распадается на восемь областей (каждая комбинация «внутри/снаружи» для трёх множеств), и вопросы вроде «в A и B, но не в C» перестают быть словесными головоломками: это одна область, в которую можно ткнуть пальцем.

## Де Морган, теперь с областями

Логика высказываний дала вам законы де Моргана: не (P или Q) — то же, что (не P) и (не Q). Подставьте вместо P и Q утверждения о принадлежности — и закон станет фактом о множествах: дополнение объединения есть пересечение дополнений:

- *не в (A ∪ B)* — снаружи обоих кругов — равно *не в A* **и** *не в B*.
- *не в (A ∩ B)* — вне линзы — равно *не в A* **или** *не в B*.

Теперь баг из пролога — одна строка алгебры. Хотели: дополнение (отписавшиеся ∪ отбившиеся) — пользователей, не состоящих *ни в одном* плохом множестве. Де Морган говорит: это (не отписан) ∩ (не отбит) — И двух отрицаний:

```js
// Хотели: NOT (отписан OR отбит)
// Де Морган: (NOT отписан) AND (NOT отбит)
const eligible = users.filter((u) => !u.unsubscribed && !u.bounced); // правильно

// Выкатили: (NOT отписан) OR (NOT отбит)
// — истинно для любого, кто отсутствует хотя бы в ОДНОМ плохом множестве,
//   что включает отбитого пользователя, который никогда не отписывался.
const buggy = users.filter((u) => !u.unsubscribed || !u.bounced);
```

На карте Венна правильное множество — единственная наружная область. Выкаченное условие закрашивает всё, кроме линзы, — три области вместо одной, и две лишние области — это в точности люди, получившие письмо, которого не должны были получить.

<Inset kind="mistake" lang="ru">
Надёжный способ поймать промах с де Морганом на ревью: возьмите подозрительное условие и прогоните через него по одному конкретному представителю каждой области Венна — пользователя, который только отписался; который только отбился; который и то и другое; который ни то ни другое. Четыре тестовых значения, четыре области — и неверная связка всегда неправильно классифицирует хотя бы одного. Это быстрее и убедительнее, чем перевыводить алгебру в голове, и работает на условиях куда грязнее двух флагов.
</Inset>

## Подсчёт объединения: включения-исключения

В рассылке 1 200 подписчиков, в бета-программе 300 участников. Какова объединённая аудитория? Не 1 500 — если только никто не состоит в обеих. Каждый человек из линзы посчитан дважды, по разу на круг, поэтому перекрытие вычитается один раз:

|A ∪ B| = |A| + |B| − |A ∩ B|

При 100 людях в обеих группах: 1 200 + 300 − 100 = **1 400** живых людей. Это **формула включений-исключений**, и карта Венна делает её наглядной: |A| + |B| покрывает линзу дважды, так что одно вычитание возвращает каждой области ровно один подсчёт.

```python
newsletter = load_newsletter_ids()   # 1200 id
beta = load_beta_ids()               # 300 id

audience = newsletter | beta
len(audience)                        # 1400 — не 1500
len(newsletter) + len(beta) - len(newsletter & beta)  # 1400, то же число
```

Если вы видели дашборд, где суммы сегментов превышают число пользователей, — вы видели, как формулу включений-исключений игнорируют в продакшене.

## Заблуждение: «разность работает в обе стороны»

Вычитание чисел вас уже предупреждало: 5 − 3 — не то же, что 3 − 5. Разность множеств столь же направленна, и допущение о симметрии прокрадывается в реальный код под видом «диффа двух списков». С `A = {1, 2, 3}` и `B = {3, 4}`: A ∖ B — это `{1, 2}` (что деплой удалит), а B ∖ A — `{4}` (что деплой добавит) — разные множества, отвечающие на разные вопросы. Когда вам действительно нужно «элементы ровно в одном из двух», это отдельная операция — **симметрическая разность** A △ B = `{1, 2, 4}`:

```python
a = {1, 2, 3}
b = {3, 4}

a - b   # {1, 2}     — directional: in a, not in b
b - a   # {4}        — the other direction
a ^ b   # {1, 2, 4}  — symmetric difference: in exactly one
```

Инструмент синхронизации конфигов, вычисляющий только `current - desired`, охотно удалит устаревшие ключи и никогда не добавит недостающие. Спрашивайте, какое направление вы имеете в виду — или оба сразу.

</Explanation>

<Recap lang="ru">
Множества соединяются четырьмя операциями, и каждая — логическая связка над принадлежностью: объединение A ∪ B — это ИЛИ, пересечение A ∩ B — И, разность A ∖ B — И-НЕ, а дополнение — НЕ, законное лишь внутри объявленного универсума U, потому что «всё, что не в A» бессмысленно, пока «всё» не стало множеством. Раз операции — связки, де Морган переносится дословно: дополнение A ∪ B — пересечение дополнений, дополнение A ∩ B — объединение дополнений; именно этот закон нарушил баговый фильтр `!u.unsubscribed || !u.bounced` — нужной областью была единственная наружная часть объединения, а выкаченное условие закрасило три области. Диаграмма Венна — карта, делающая такие баги видимыми: два круга в прямоугольнике режут универсум на четыре области, три круга — на восемь, каждое значение живёт ровно в одной области, и каждая операция — выбор областей, на которые можно показать пальцем. Подсчёт следует карте: |A ∪ B| = |A| + |B| − |A ∩ B|, потому что сумма размеров кругов считает линзу дважды — 1 200 в рассылке плюс 300 в бете при 100 общих — это 1 400 человек, а не 1 500. Разность направленна: A ∖ B и B ∖ A отвечают на разные вопросы, а «ровно в одном» — отдельная операция, симметрическая разность A △ B. В коде: `a | b`, `a & b`, `a - b`, `a ^ b` в Python; предикаты с `&&`, `||`, `!` в фильтре; AND в WHERE — одна и та же алгебра на каждом слое.
