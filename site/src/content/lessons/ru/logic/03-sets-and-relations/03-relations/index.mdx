## Упорядоченные пары: где позиция начинает значить

Множество забывает порядок — `{a, b}` и `{b, a}` — одно множество. **Упорядоченная пара** (a, b) — противоположное обязательство: позиция и есть суть. (a, b) равна (c, d), только когда a = c *и* b = d. Поэтому (1, 2) ≠ (2, 1), хотя `{1, 2}` = `{2, 1}`.

Вы пользуетесь упорядоченными парами постоянно: координата (x, y), пара ключ-значение, строка `(follower_id, followee_id)`. Баг из пролога — в точности баг упорядоченной пары: строка (ana, bob) означает «ana подписана на bob», и чтение её как (bob, ana) молча разворачивает каждую стрелку графа. Система типов не возразит — обе колонки суть id, — поэтому смысл позиций заслуживает комментария, аккуратного имени или того и другого.

## Декартово произведение: сетка всех возможных пар

Для двух множеств **декартово произведение** A × B — это множество *всех* упорядоченных пар (a, b), где a из A и b из B. Представьте сетку: элементы A подписывают строки, элементы B — столбцы, каждая ячейка — одна пара. Подсчёт навязан картинкой: каждая из |A| строк содержит |B| ячеек, поэтому

|A × B| = |A| · |B|

С `A = {1, 2, 3}` и `B = {x, y, z, w}`: 3 строки × 4 столбца = 12 пар — пересчитайте ячейки, тринадцатой нет. Код строит сетку двумя вложенными циклами, а в SQL для неё есть глагол:

```js
const a = [1, 2, 3];
const b = ["x", "y", "z", "w"];

const grid = a.flatMap((m) => b.map((n) => [m, n]));
grid.length;   // 12 = 3 * 4 — каждая комбинация, ровно по одному разу
```

```sql
-- CROSS JOIN — декартово произведение, строки × строки:
SELECT u.id, p.id FROM users u CROSS JOIN plans p;
-- 1 000 пользователей × 5 тарифов = 5 000 строк. Забудьте условие ON
-- в обычном JOIN, и эта сетка взорвётся у вас перед глазами.
```

## Отношение — подмножество сетки

Вот определение, ради которого существует весь урок. **Отношение** из A в B — это *любое подмножество* A × B. Это всё определение — и ровно это и должно означать слово «связаны», чтобы быть точным. Сетка перечисляет каждую пару, которая *могла бы* быть связана; отношение оставляет пары, которые связаны *на самом деле*. Чтобы сказать «a связано с b», проверьте (a, b) ∈ R — вопрос о принадлежности, который вы уже умеете задавать.

Таблица с внешним ключом — это то же определение, записанное на диск. Таблица `follows` над пользователями `{ana, bob, cara}` — некоторое подмножество сетки из 9 ячеек users × users:

```sql
-- follows ⊆ users × users — каждая строка это одна упорядоченная пара из R
INSERT INTO follows VALUES
  ('ana',  'bob'),    -- (ana, bob)  ∈ R : ana подписана на bob
  ('bob',  'ana'),    -- (bob, ana)  ∈ R : bob тоже подписан в ответ
  ('ana',  'cara');   -- (ana, cara) ∈ R : ana подписана на cara
                      -- (cara, ana) ∉ R : cara не подписана в ответ
```

Пустое отношение (никто ни на кого не подписан) и полная сетка (все на всех) — оба законные отношения, две крайности одного и того же выбора подмножества. И `===` на примитивных значениях — тоже отношение: множество пар (x, y), для которых проверка возвращает true.

## Три свойства, сортирующие отношения

Когда отношение живёт на одном множестве (R ⊆ A × A), три вопроса раскрывают его характер. Каждый проверяется пара за парой — хитрость не нужна:

- **Рефлексивность** — связан ли *каждый* x сам с собой? (x, x) ∈ R для всех x из A. «x ≤ x» — да. «x — собственный предок» — нет.
- **Симметричность** — идёт ли каждая стрелка вместе с обратной? Если (x, y) ∈ R, то и (y, x) ∈ R. «Дружба» в приложениях с взаимным подтверждением — да. «Подписан на» — знаменито нет: (ana, cara) без (cara, ana) — обычное дело.
- **Транзитивность** — сцепляются ли стрелки? Если (x, y) ∈ R и (y, z) ∈ R, то и (x, z) ∈ R. «Предок» — да: предок вашего родителя — ваш предок. «Подписан на» — нет: вы не подписываетесь автоматически на тех, на кого подписаны ваши друзья.

Попробуйте **драйв на трёх элементах** — он достаточно мал, чтобы проверить каждое свойство вручную. Возьмём A = `{1, 2, 3}` и R = `{(1, 1), (2, 2), (1, 2), (2, 1)}`:

- Рефлексивно? Нужны (1, 1), (2, 2), (3, 3). Нет (3, 3) → **не рефлексивно**. Одной отсутствующей само-пары достаточно.
- Симметрично? Проверяем каждую стрелку: у (1, 2) есть (2, 1) ✓, само-пары обратны сами себе ✓ → **симметрично**.
- Транзитивно? Сцепляем каждую пару соприкасающихся стрелок: (1, 2) и затем (2, 1) требуют (1, 1) ✓; (2, 1) и затем (1, 2) требуют (2, 2) ✓ → **транзитивно**.

```js
// То же самое, механически — пары как строки «x,y» в Set:
const A = [1, 2, 3];
const R = new Set(["1,1", "2,2", "1,2", "2,1"]);
const has = (x, y) => R.has(`${x},${y}`);

A.every((x) => has(x, x));                                  // false — нет (3,3)
[...R].every((p) => { const [x, y] = p.split(","); return has(y, x); }); // true
A.every((x) => A.every((y) => A.every((z) =>
  !(has(x, y) && has(y, z)) || has(x, z))));                // true
```

Драйв — не игрушка: проверка свойств на малых конечных отношениях — это ровно то, как трезво тестируют матрицу доступа или таблицу связей «дубликат-чего» прежде, чем доверять коду, который предполагает свойство, отсутствующее в данных.

<Inset kind="edgecase" lang="ru">
Рефлексивен ли `===`? Должен бы — каждое значение равно самому себе, — и почти для каждого примитива так и есть. Исключение — `NaN`: стандарт IEEE 754 определяет `NaN === NaN` как false, делая `===` на числах *не рефлексивным*. Эта единственная отсутствующая само-пара ломает реальный код: `array.indexOf(NaN)` никогда его не находит (indexOf использует ===), а `array.includes(NaN)` находит (includes использует SameValueZero, возвращающий само-пару на место). Когда язык предлагает несколько отношений равенства, различаются они ровно такими решениями о свойствах.
</Inset>

## Заблуждение: «каждое отношение — это, по сути, функция»

Функция кажется ментальной моделью по умолчанию: подал x — получил y. Но как множества пар функции — *частный случай*, а не правило. Отношение R ⊆ A × B является **функцией** из A в B, только когда каждый элемент A встречается первой координатой *ровно в одной* паре — один выход на вход, не больше и не меньше. «Подписан на» проваливается мгновенно: ana стоит первой координатой дважды ((ana, bob) и (ana, cara)), а новенький пользователь — ноль раз. Большинство отношений, которые вы храните, — подписки, дружбы, внешние ключи, теги — многие-ко-многим и вовсе не функции. Функциеобразные — это словари: user_id → email (у каждого id ровно один). Следующий урок берёт выученные свойства и строит из них два самых полезных вида отношений: эквивалентности и порядки.

</Explanation>

<KeyTakeaway>Упорядоченная пара (a, b) делает позицию значимой — (a, b) ≠ (b, a). Сетка A × B содержит все |A| · |B| возможных пар, а отношение — любое её подмножество: таблицы подписок, внешние ключи и === суть множества пар. Рефлексивность, симметричность, транзитивность — попарные проверки, а функция — особое отношение с ровно одной парой на вход.</KeyTakeaway>

<Recap lang="ru">
Множество не может сказать «Ана подписана на Боба, но не наоборот» — оно забывает порядок. Упорядоченная пара (a, b) — исправление: позиция значима, и (a, b) равна (c, d), лишь когда совпадают обе координаты. Декартово произведение A × B собирает все возможные пары в сетку ровно из |A| · |B| ячеек — 3 × 4 даёт 12, и забытое условие соединения в SQL вручает вам именно эту сетку. Отношение — любое подмножество сетки: определение, превращающее «связаны» в вопрос о принадлежности, (a, b) ∈ R. Таблицы с внешними ключами хранят отношения строка за строкой; === задаёт отношение своими истинными парами; пустое подмножество и полная сетка равно законны. На одном множестве отношение классифицируют три попарные проверки: рефлексивность (каждая само-пара на месте — у ≤ да, у === нет из-за NaN), симметричность (каждая стрелка развёрнута — взаимная дружба да, подписка нет), транзитивность (стрелки сцепляются — предок да, подписка нет). Драйв на трёх элементах делает проверки механическими, и тем же драйвом проверяют реальные таблицы связей, прежде чем код доверится свойству, которого в данных нет. Функция — не общий случай, а особый: отношение, где каждый вход встречается первой координатой ровно один раз; большинство хранимых отношений — многие-ко-многим. Дальше — эквивалентности и порядки, два великих вида, собранные из этих свойств.
