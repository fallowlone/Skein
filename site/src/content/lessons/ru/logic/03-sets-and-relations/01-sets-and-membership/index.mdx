## Внутри или нет — единственный вопрос

**Множество** — это коллекция, о которой для каждого значения существует ровно один факт: значение является **членом** (его ещё называют *элементом*) или не является. У принадлежности есть собственный символ: x ∈ A означает «x — элемент A», а x ∉ A — что нет. Простейший способ задать множество — перечислить элементы в фигурных скобках: `{1, 2, 3}` — множество, элементы которого ровно 1, 2 и 3.

Поскольку принадлежность — *единственный* факт, который несёт множество, три привычных свойства внутри него просто не существуют:

- **Нет порядка.** `{1, 2, 3}` и `{3, 1, 2}` — одно и то же множество: оба отвечают «да» на одни и те же вопросы о принадлежности.
- **Нет дубликатов.** `{1, 1, 2, 3}` — тоже то же самое множество. Записать элемент дважды — значит не добавить ничего: у «внутри» нет регулятора громкости; значение внутри, как только оно перечислено, и повторная запись не меняет ни одного ответа.
- **Нет количества.** Множество не может сказать, что 1 «встретилась три раза». Кратность — понятие массива; множество знает только список состава.

Два множества **равны** ровно тогда, когда у них одни и те же элементы, — это и есть всё определение тождества множеств. И именно такое поведение поставляется в вашем рантайме:

```js
const clicks = [42, 7, 42, 42, 7];
const unique = new Set(clicks);

unique.size;     // 2 — the members are 42 and 7, nothing else
unique.has(42);  // true   — 42 ∈ unique
unique.has(99);  // false  — 99 ∉ unique
unique.add(7);   // adding an existing member changes nothing
unique.size;     // still 2

new Set([1, 2, 2, 3]).size;  // 3 — dedup IS set semantics
```

Дедупликация — не хитрый трюк поверх `Set`: дедупликация и *есть* семантика множества. Прогон массива через множество задаёт каждому значению один вопрос — «ты уже внутри?» — и отбрасывает каждое «да».

<Inset kind="why" lang="ru">
Зачем кому-то структура, которая столько забывает? Затем, что забывание делает ответы каноничными. Существует ровно *одно* множество с элементами 7 и 42 — поэтому у вопроса «видел ли я это значение?» есть ровно один честный ответ, как бы данные ни поступали. Массив — это журнал: он помнит, что произошло и в каком порядке. Множество — это список состава: оно помнит, что существует. Большинство багов с коллекциями в раннем коде — это вопрос к журналу, заданный как к списку состава (считаем клики вместо пользователей), или наоборот (ждём от множества, кто пришёл первым). Выбор структуры — это выбор вопроса, который ваш код вообще способен задать.

## Множества по правилу — и первое бесконечное множество

Перечисление работает, только когда список можно закончить. Вторая нотация — **задание множества условием** (set-builder): `{x : x чётно}` читается «множество всех x таких, что x чётно». Всё после двоеточия — условие, предикат. Если условие истинно для значения, значение внутри; если ложно — снаружи. Предикат — это в точности *открытое предложение* из раздела о логике высказываний: предложение со свободной переменной, которое становится истинным или ложным после связывания значения. Множество-по-правилу — это открытое предложение в фигурных скобках.

В коде есть обе нотации. Литерал `new Set([200, 301, 404])` — перечисление; функция-предикат — правило:

```js
// You cannot list the even numbers — but you can decide membership:
const isEven = (n) => n % 2 === 0;   // the set {x : x is even}, as a rule

isEven(10);  // true  → 10 is in
isEven(7);   // false → 7 is out

// Over a finite universe, filter materializes the rule into a roster:
[1, 2, 3, 4, 5, 6].filter(isEven);   // [2, 4, 6]
```

Нотация-правило открывает дорогу **бесконечным множествам**. Натуральные числа ℕ — 0, 1, 2, 3 и так далее без конца — нельзя ни перечислить, ни уместить в память, и всё же ℕ — совершенно полноценное множество: для любого кандидата вопрос о принадлежности имеет определённый ответ «да» или «нет». Большего множеству и не нужно. Множество не обязано быть *хранимым* — оно обязано быть *разрешимым* в этом мягком смысле: каждый вопрос о принадлежности имеет один ответ.

## ∈ или ⊆ — одно значение или целое множество

Вот ловушка, в которую попадают почти все. О множествах можно сделать два разных заявления, и у них разные символы:

- **Принадлежность** x ∈ A — вопрос об *одном значении*: есть ли x в составе A?
- **Подмножество** A ⊆ B — вопрос о *двух множествах*: всякий ли элемент A является также элементом B?

Они похожи — оба говорят, что что-то «внутри», — но живут на разных уровнях. Возьмём `A = {1, 2}`:

- 1 ∈ A — **истина**. Значение 1 есть в составе.
- `{1}` ⊆ A — **истина**. Каждый элемент множества `{1}` (он один: значение 1) есть и в A.
- `{1}` ∈ A — **ложь**. Элементы A — *числа* 1 и 2. *Множество* `{1}` — объект другого сорта, и в составе его нет.
- A ⊆ A — **истина**. Каждое множество — подмножество самого себя; ⊆ допускает равенство.

**Пустое множество** ∅ — множество вообще без элементов — делает оба заявления интересными. ∅ ⊆ B истинно для *любого* множества B: чтобы опровергнуть заявление о подмножестве, нужно указать элемент ∅, которого нет в B, а ∅ не даёт вам ничего, на что можно указать. Но ∅ ∈ B почти всегда ложно — это верно, лишь если кто-то явно положил пустое множество в состав. Это же решает классическую головоломку: `{∅}` — *не* пустое множество. Это коробка, в которой лежит одна вещь — пустая коробка. Его размер — 1.

```js
const a = new Set([1, 2]);

a.has(1);              // true  — 1 ∈ a
a.has(new Set([1]));   // false — the SET {1} is not one of a's members

// Subset is a claim BETWEEN sets — you check every member yourself:
const isSubset = (x, y) => [...x].every((v) => y.has(v));
isSubset(new Set([1]), a);   // true — {1} ⊆ a
isSubset(new Set(), a);      // true — ∅ is a subset of everything

new Set().size;              // 0 — the empty set
new Set([new Set()]).size;   // 1 — a box holding an empty box
```

## Тип — это множество значений

Ещё одно место, где вы каждый день пользуетесь множествами без этого слова, — типы. Тип `boolean` — это двухэлементное множество из `true` и `false`, и ничего больше. Объединение в TypeScript вроде `"GET" | "POST"` — множество строк из двух элементов, а вопрос «можно ли передать это значение туда, где ожидается тот тип?» — в точности вопрос о подмножестве: значение типа A подходит всюду, где ждут B, когда A как множество значений является подмножеством B. Следующий урок строится на этом: соединение типов через `|` окажется буквально объединением множеств.

## Заблуждение: «множество помнит порядок вставки»

JavaScript здесь мутит воду, так что наведём резкость. JS-`Set` итерируется в порядке вставки — это сознательное удобство языка, детерминированное и порой полезное. Но это свойство *контейнера*, а не *множества*. Тождество множеств игнорирует его полностью:

```js
const s1 = new Set(["a", "b"]);
const s2 = new Set(["b", "a", "b"]);

[...s1];  // ["a", "b"]  — iteration shows insertion order…
[...s2];  // ["b", "a"]  — …which differs between the two containers

// As SETS they are equal: same members, same membership answers.
const sameSet = s1.size === s2.size && [...s1].every((v) => s2.has(v));
sameSet;  // true
```

Если какая-то логика в программе зависит от того, какой элемент выйдет из множества первым, эта логика использует массив в костюме Set — и сломается в день, когда данные придут в другом порядке. Python делает честную версию видимой: порядок итерации `set` вообще не гарантирован, и при этом `{"a", "b"} == {"b", "a"}` даёт `True`. Равенство по принадлежности — это и есть множество; порядок итерации — случайность контейнера.

</Explanation>

<KeyTakeaway>Множество — это принадлежность и ничего больше: ни порядка, ни дубликатов, ни количества. x ∈ A спрашивает, есть ли одно значение в составе; A ⊆ B — всякий ли элемент A есть и в B: два заявления на двух уровнях. ∅ — подмножество каждого множества и элемент почти никакого, а `new Set` — ровно эта идея в вашем рантайме: массив на входе дедуплицируется, потому что таков смысл принадлежности.</KeyTakeaway>

<Recap lang="ru">
Множество — структура, знающая об одном значении одно: внутри или нет. Принадлежность записывается x ∈ A, её отрицание — x ∉ A, а множество задаётся перечислением — `{1, 2, 3}` — или правилом вроде `{x : x чётно}`, где правило — предикат, открытое предложение, чьи истинные ответы и есть элементы. Поскольку принадлежность — единственный хранимый факт, у множеств нет порядка, дубликатов и количества: `{3, 1, 2}` и `{1, 1, 2, 3}` — то же множество, что и `{1, 2, 3}`, а размер 3 у `new Set([1, 2, 2, 3])` — это определение, исполняющееся в рантайме. Равенство множеств — равенство ответов о принадлежности; поэтому законны и бесконечные множества вроде ℕ: множеству не нужно помещаться в память, нужно лишь, чтобы каждый вопрос о принадлежности имел определённый ответ. Два заявления живут на разных уровнях: x ∈ A — об одном значении, A ⊆ B — о том, всякий ли элемент A есть в B. Одноэлементное `{1}` — подмножество `{1, 2}`, но не его элемент; ∅ — подмножество всего и элемент почти ничего, а `{∅}` — коробка с пустой коробкой внутри, размер 1. Типы дают предпросмотр выгоды: boolean — множество из `true` и `false`, а присваиваемость — вопрос о подмножестве. Когда коду будто бы нужен «первый элемент множества», на самом деле ему нужен массив.
