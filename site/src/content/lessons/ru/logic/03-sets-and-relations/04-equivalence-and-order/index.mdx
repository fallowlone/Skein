## Эквивалентность: рефлексивность + симметричность + транзитивность

Прошлый урок дал три попарных свойства. Отношение, обладающее *всеми тремя* — рефлексивное, симметричное, транзитивное, — называется **отношением эквивалентности**, и это точная версия фразы «считается одинаковым для моих целей». Три свойства — ровно то, чего требует «одинаковость»: всё одинаково с самим собой; если a одинаково с b, то b одинаково с a; если a одинаково с b, а b с c, то a одинаково с c.

Канонический пример: **одинаковый остаток от деления на 3** на целых числах. 7 и 4 оба дают остаток 1 — значит, эквивалентны. Проверим свойства: x всегда делит собственный остаток с собой (рефлексивность); если у x общий остаток с y, то у y общий с x (симметричность); если x совпадает с y, а y с z, у всех троих один остаток (транзитивность). Другие будничные эквивалентности: «одинаковая длина» на строках, «анаграмма» («listen» ~ «silent»), «один и тот же человек после нормализации» на адресах email.

## Выгода: эквивалентность разбивает множество

Вот почему эквивалентности значат больше, чем сумма трёх свойств. Отношение эквивалентности **разбивает** своё множество: режет его на непересекающиеся куски — **классы эквивалентности**, — так что каждый элемент попадает *ровно в один* класс, а два элемента связаны в точности тогда, когда делят класс. Остаток по модулю 3 режет целые числа ровно на три класса:

- класс нуля: `{0, 3, 6, 9, 12, …}`
- класс единицы: `{1, 4, 7, 10, 13, …}`
- класс двойки: `{2, 5, 8, 11, 14, …}`

Ни одно число не лежит в двух классах, ни одно не осталось снаружи — и это гарантируют три свойства, а не везение. Симметричность с транзитивностью заставляют классы заглатывать группы целиком, рефлексивность следит, чтобы никто не сбежал. Стоит отношению «такой же, как» потерять свойство — его классы перестают быть корректно определёнными, и группирующий по нему код начинает выдавать пересекающиеся или дырявые группы.

Вы запускаете разбиения ежедневно. `groupBy` — разбиение, вычисленное по ключу. Хеш-таблица — разбиение на корзины по «одинаковому хешу». Дедупликация оставляет по одному **представителю** на класс и отбрасывает остальное:

```js
// "Same person" on emails = same value after normalization.
const canon = (e) => e.trim().toLowerCase();   // class representative

const emails = ["Ana@Example.com ", "ana@example.com", "BOB@x.dev"];
const classes = new Map();                      // representative → class
for (const e of emails) {
  const rep = canon(e);
  (classes.get(rep) ?? classes.set(rep, []).get(rep)).push(e);
}
classes.size;   // 2 — two real people, three spellings
// Dedup = keep one member per class:
[...classes.keys()];   // ["ana@example.com", "bob@x.dev"]
```

Функция нормализации и *есть* эквивалентность: x ~ y ровно тогда, когда canon(x) === canon(y). Отношение, определённое так — одинаковый выход некоторой функции, — всегда настоящая эквивалентность, потому что === на выходах (NaN в сторону) дарит три свойства бесплатно.

<Inset kind="why" lang="ru">
Почему хеш-корзины считаются классами эквивалентности? Хеш-таблица кладёт x и y в одну корзину, когда hash(x) === hash(y), — а «одинаковый хеш» рефлексивен, симметричен и транзитивен, так что корзины — классы настоящего отношения эквивалентности. Тонкость в том, что эта эквивалентность *грубее* равенства: равные значения всегда делят корзину, но корзина может приютить и неравные значения, случившиеся в коллизии. Поэтому поиск двухступенчатый — хеш находит класс, затем внутри него работает честная проверка равенства. Разбиение делает быстрое сужение; равенство говорит последнее слово. Когда говорят, что хеширование «почти» различает значения, точная формулировка такова: хеш-эквивалентность разбивает универсум на дёшево вычислимые классы, а уточнение до равенства происходит лишь внутри одного маленького класса.
</Inset>

## Порядки: когда отношение ранжирует, а не группирует

Замените симметричность её противоположностью — и получите второй великий вид. **Частичный порядок** рефлексивен, транзитивен и **антисимметричен**: если a связано с b *и* b связано с a, то a и b — один элемент. Стрелки не возвращаются; они ранжируют. Числа под ≤ — привычный случай: x ≤ x, цепочки сцепляются, а взаимное ≤ влечёт равенство.

Сюрприз прячется в слове *частичный*. ≤ на числах — **полный (линейный) порядок**: любые два числа сравнимы — для всяких x, y верно x ≤ y или y ≤ x. Но ⊆ на множествах — частичный порядок, где сравнение может просто *не состояться*: `{1, 2}` и `{2, 3}` — ни одно не подмножество другого. Они не равны, ни одно не «меньше»; они **несравнимы**. Ничего не сломано. Порядок просто частичен, и вопрос «какое из двух идёт раньше?» честно не имеет ответа.

Софт полон частичных порядков в костюмах полных. Баг версий из пролога — один из них: у семантических версий есть отличный задуманный порядок (сравнивать major, затем minor, затем patch — численно), а сортировка JavaScript по умолчанию тихо подставляет другой полный порядок — лексикографический:

```js
const tags = ["1.9.0", "1.10.0", "1.2.3"];

tags.sort();                 // по умолчанию: строковый порядок, посимвольно
// → ["1.10.0", "1.2.3", "1.9.0"]   "1.10.0" < "1.2.3", потому что "1" < "2"

const byVersion = (a, b) => {
  const pa = a.split(".").map(Number);
  const pb = b.split(".").map(Number);
  return (pa[0] - pb[0]) || (pa[1] - pb[1]) || (pa[2] - pb[2]);
};
tags.sort(byVersion);        // → ["1.2.3", "1.9.0", "1.10.0"] — правильный порядок
```

Оба порядка полные; смыслу соответствует только один. Баг не в том, что «сортировка сломана», а в *сортировке по неправильному отношению*. Сортировка всегда ставит вопрос ребром: какой порядок и сравнивает ли он то, что вы думаете?

## Зависимости: частичный порядок, которым вы уже управляете

«Должно выполниться раньше» на задачах — самый инженерный частичный порядок. Миграции, шаги сборки, установка пакетов: `create-tables` обязан предшествовать `seed-data`, а `compile` — `link`, но `lint` и `compile` могут быть искренне несравнимы: ограничений между ними нет. Несравнимость здесь не дефект, а *свобода*: несравнимые задачи можно выполнять параллельно. Когда инструменту нужна одна конкретная последовательность, он расширяет частичный порядок до полного — этот алгоритм называется **топологической сортировкой** и ждёт вас в треке алгоритмов. Один факт возьмите туда с собой: отношение зависимостей с циклом (a раньше b, b раньше a, a ≠ b) нарушает антисимметричность — это вообще не порядок, и корректной последовательности не существует. «Циклическая зависимость» — имя этой математической поломки.

## Заблуждение: «любые две вещи всегда можно сравнить»

Полные порядки приучают интуицию к тому, что сравнение всегда удаётся: возьмите любые два числа — одно меньше. Частичные порядки говорят «нет»: несравнимые пары законны, обычны и осмысленны. Два множества, ни одно из которых не содержит другое. Две задачи без ограничений между собой. Два релиза `1.4.0` и `2.0.0-beta` при командной политике, ранжирующей стабильную и предрелизную линии отдельно. Принудительное сравнение там, где его нет, — реальный класс багов: JavaScript-компаратор, который не может решить, всё равно что-то возвращает, и `Array.prototype.sort` с противоречивым компаратором выдаёт произвольную, зависящую от движка расстановку — молча. Дисциплина зеркалит дисциплину высказываний из начала трека: прежде чем сортировать или сравнивать, произнесите вслух, *каким отношением вы пользуетесь* и полно ли оно на ваших данных. Если оно лишь частично — вы должны коду явный тай-брейк или честное признание, что у некоторых пар порядка нет вовсе.

Из трёх попарных свойств собираются два великих вида отношений. Сохраните все три — рефлексивность, симметричность, транзитивность — и получится отношение эквивалентности, точная форма «считается одинаковым»: одинаковый остаток mod 3, одинаковая длина строки, анаграмма, один email после нижнего регистра и обрезки пробелов. Каждая эквивалентность разбивает множество на непересекающиеся классы — каждый элемент ровно в одном, что гарантируют свойства, — и эта картинка крутится в коде повсюду: groupBy разбивает по ключу, хеш-корзины — классы «одинакового хеша» (грубее равенства, уточняется честной проверкой равенства внутри корзины), дедупликация хранит по одному каноническому представителю на класс. Замените симметричность антисимметричностью — взаимная связь влечёт равенство — и получите порядки, которые ранжируют, а не группируют. Полный порядок сравнивает каждую пару (числа под ≤); частичный законно оставляет пары несравнимыми: ⊆ на множествах, где ни `{1, 2}`, ни `{2, 3}` не содержит другое, и «должно выполниться раньше» на задачах, где несравнимо значит параллелизуемо, а цикл значит, что порядка не существует вовсе, — математическое имя «циклической зависимости». Инцидент с сортировкой версий дистиллирует дисциплину: строковый порядок и порядок semver оба полные, но смыслу отвечает один, и «1.10.0», проигрывающее «1.9.0», — вот как выглядит сортировка не тем отношением. Прежде чем сравнивать — назовите порядок; прежде чем группировать — назовите эквивалентность.
