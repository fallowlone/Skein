## Домино: база и индукционный шаг

Как доказать утверждение о *каждом* натуральном числе — бесконечном числе случаев — за конечное время? **Математическая индукция** отвечает: сделайте ровно две вещи. **База**: покажите, что утверждение верно для первого значения, обычно n = 0 или n = 1. **Индукционный шаг**: покажите, что *если* утверждение верно для произвольного n (это допущение — *индукционная гипотеза*), *то* оно верно для n + 1. Два конечных доказательства — и вывод накрывает бесконечность: утверждение истинно для каждого натурального числа от базы и дальше.

Стандартная картинка — ряд домино. База опрокидывает первую костяшку. Шаг гарантирует, что каждая падающая костяшка сбивает следующую. Если есть и то и другое — падают все, включая костяшку номер миллион, которую никто не трогал. Заметьте, чем шаг является на самом деле: не утверждением, что n работает, а *условием* — n работает → n+1 работает. Вы доказываете условие один раз, для произвольного n, а дальше modus ponens делает остальное — n раз подряд, для любого нужного n.

Несущие обе части. Пропустите базу — и «докажете» чушь: шаг «если n чётно, то n + 2 чётно» безупречен, но стартуя с 1, он порождает только нечётные числа — идеальная цепочка домино, которую никто не толкнул. Пропустите *общность* шага — и получите классическое сломанное доказательство, что все лошади одной масти: рассуждение молча предполагает пересечение двух групп, а оно проваливается ровно при n = 2 — одна перекладина лестницы треснула, и всё, что выше, рушится.

## Сильная индукция: опереться на всё, что ниже

Иногда «сработало для n» — недостаточное топливо для шага. **Сильная индукция** усиливает гипотезу: предположите, что утверждение верно для *всех* значений до n включительно, и докажите его для n + 1. Это важно всегда, когда задача распадается не на «на единицу меньше», а на «сколько-то меньше»: каждое целое больше 1 раскладывается на простые множители (число делится на два множителя *непредсказуемых* размеров — гипотеза нужна для обоих, а не для n − 1); сортировка слиянием корректна (массив длины n делится на половины длины n/2, что гораздо меньше n − 1). Сильная индукция — не другая машина, она доказуемо эквивалентна обычной, — но это естественная форма для **рекурсии**: рекурсивная функция, которая правильно обрабатывает базу и корректна всякий раз, когда корректны её рекурсивные вызовы на *любых меньших входах*, корректна — точка. Этим структурным мышлением вы уже пользуетесь каждый раз, когда доверяете `mergeSort` на половинах, пока пишете merge.

<Inset kind="why" lang="ru">
Почему этот паттерн рассуждения имеет право называться доказательством, а «на стейджинге работало» — нет? Потому что индукция — это приодетый modus ponens, валидная форма из первого урока. Шаг доказывает универсальное условие — для каждого n: P(n) → P(n+1), — а база поставляет P(0). Примените modus ponens один раз: P(1). Ещё раз: P(2). Для любого целевого n цепочка — конечная, полностью валидная дедукция; принцип индукции лишь утверждает всё семейство разом. Тестирование же устанавливает P в разрозненных точках без связывающего их условия — поэтому три прошедших размера ничего не говорят о четвёртом, и поэтому на вопрос ревьюера нет ответа, сделанного из дополнительных прогонов.
</Inset>

## Инварианты цикла: индукция в рабочей одежде

**Инвариант цикла** — утверждение о переменных программы, истинное *каждый раз, когда цикл проверяет своё условие*. Доказательство корректности цикла через инвариант — индукция с переклеенными этикетками: **инициализация** (инвариант верен перед первой итерацией — база), **сохранение** (если он верен в начале итерации, он верен в начале следующей — индукционный шаг), **завершение** (цикл выходит, и на выходе инвариант вместе с ложным условием цикла влечёт нужный результат). Вот доказательство для самого простого цикла, когда-либо доставившего баг в прод:

```js
function sumFirst(nums) {
  let total = 0;
  let i = 0;
  // ИНВАРИАНТ: total === сумма nums[0..i-1]  (первых i элементов)

  // Инициализация: i = 0, total = 0, а сумма нуля элементов равна 0. Верно.
  while (i < nums.length) {
    // инвариант выполняется: total — сумма первых i элементов
    total += nums[i];
    i += 1;
    // total теперь включает nums[i-1]: это сумма первых (обновлённых) i элементов.
    // Инвариант пережил итерацию — сохранение доказано.
  }
  // Завершение: i === nums.length, значит инвариант читается как:
  // total === сумма nums[0..nums.length-1] — сумма ВСЕХ элементов. ЧТД.
  return total;
}
```

Три маленькие проверки — и функция корректна для *любого* массива: длины ноль (цикл не выполняется ни разу; инвариант сам по себе говорит, что total — пустая сумма, 0), длины три, длины миллион. Ни один файл с фикстурами такого сказать не может.

Инвариант — ещё и детектор багов. Возьмите классическую ошибку на единицу: инициализируем `i = 1` — «потому что первый элемент уже как бы учтён в total». Прогоните инициализацию: total = 0, i = 1, но сумма первого 1 элемента — это `nums[0]`, а не 0 — инвариант ложен *ещё до запуска цикла*, и доказательство падает на базе, ровно там, где баг. Пагинация из хука умирает так же: сформулируйте инвариант «строки 0..k−1 выданы ровно один раз», и шаг сохранения откажется проходить для версии, что сдвигает курсор на `pageSize` от *последнего увиденного id плюс один*. Падающее доказательство указывает на строку; падающий тест — на симптом.

## Инварианты на настоящем ревью

Навык, который переносится в четверговое код-ревью, — *формулировать* инвариант, потому что большинство багов в циклах — замаскированные баги инвариантов. Практические эвристики: инвариант обычно описывает, **что означают переменные** («total — сумма всего обработанного», «всё левее `write` — дедуплицировано», «ответ лежит в `lo..hi`»); он обязан упоминать переменную цикла, иначе не свяжет итерации; и он должен делать *оператор return* однострочным следствием на выходе. Бинарный поиск — канонический выигрыш: инвариант «если цель существует, её индекс в [lo, hi)» решает каждую мучительную деталь (цикл — `lo < hi`? присваивать `hi = mid` или `hi = mid - 1`?), которую инженеры иначе решают суеверием. Завершению — своё крошечное доказательство: назовите величину, которая строго убывает на каждом проходе и не может убывать вечно, — `hi - lo` в бинарном поиске, `nums.length - i` в сумме. Цикл с доказанным инвариантом, но без аргумента завершения — правильный ответ, которого вы можете никогда не дождаться. Пишите инвариант комментарием над циклом: следующий читатель унаследует не просто работающий код, а причину, по которой он обязан работать.
</Explanation>

<KeyTakeaway>Индукция превращает два конечных доказательства — базу и шаг с n на n+1 — в гарантию для каждого n; сильная индукция разрешает шагу использовать все меньшие случаи и совпадает по форме с рекурсией. Инвариант цикла — то же доказательство в коде: верен при инициализации, сохраняется каждой итерацией, а на выходе влечёт корректность для входов, которые не перечислит ни один тестовый набор.</KeyTakeaway>

Математическая индукция доказывает утверждение о каждом натуральном числе двумя конечными кусками: базой (утверждение верно при n = 0) и индукционным шагом (универсальное условие — если верно для произвольного n, верно для n + 1), после чего любое конкретное n достигается конечной цепочкой modus ponens; обе части обязательны: безупречный шаг без базы — нетолкнутый ряд домино, а шаг, доказанный лишь на примерах, — ошибка «все лошади одной масти» с трещиной на одной перекладине. Сильная индукция усиливает гипотезу до всех значений вплоть до n — по силе эквивалентна, но естественна для задач, распадающихся на произвольно меньшие части: разложение на простые, сортировка слиянием и любая рекурсивная функция, корректная всякий раз, когда корректны её вызовы на меньших входах. Инвариант цикла пересаживает доказательство в код: сформулируйте, что означают переменные при каждой проверке условия («total — сумма первых i элементов»), затем закройте три обязательства — инициализацию (верен до цикла; база), сохранение (каждая итерация сберегает; шаг) и завершение (строго убывающая величина гарантирует выход, где инвариант плюс ложное условие цикла влекут возвращаемый ответ). Выигрыш перед тестированием категориален, а не количественен: доказательство покрывает пустой вход, вход на миллион элементов и продовые данные, которых не предвидела ни одна фикстура, а проваленное обязательство указывает на виновную строку — инициализируйте i = 1, и инициализация откажет, обнажив ошибку на единицу до первого прохода.
