## Два символа, которые квантифицируют всё

Обычное утверждение говорит об одной вещи: «этот тест прошёл». **Кванторное** утверждение говорит сразу о целой коллекции, и способов ровно два. **∀** (квантор всеобщности, «для всех») заявляет, что свойство выполнено для *каждого* элемента: ∀t P(t) — каждый тест t прошёл. **∃** (квантор существования, «существует») заявляет, что свойство выполнено *хотя бы для одного*: ∃t P(t) — какой-то тест прошёл. Каждое предложение спеки, что вы читали, собрано из этих двух: «все запросы должны быть аутентифицированы» — это ∀; «администратор может переопределить лимит» — это ∃; «у каждого заказа есть хотя бы одна позиция» — это ∀, обёрнутый вокруг ∃.

У кванторов противоположное бремя доказательства. Чтобы *установить* ∀, нужно проверить каждый случай — но чтобы *разрушить* его, достаточно одного контрпримера. Чтобы *установить* ∃, нужен всего один свидетель — но чтобы разрушить его, придётся перебрать всю коллекцию. Эта асимметрия и есть причина, по которой тестирование доказывает наличие багов (один падающий случай рушит «∀ входов код корректен»), но никогда — их отсутствие: никакая конечная стопка зелёных тестов не устанавливает ∀ над бесконечным пространством входов.

JavaScript поставляет оба квантора как методы массива, и чтение их как логики делает намерение проверяемым:

```js
const tests = [];   // glob ничего не нашёл — сьют ПУСТ

tests.every((t) => t.passed);    // true  — ∀: «все тесты прошли»… вакуумно
tests.some((t) => t.passed);     // false — ∃: «хотя бы один тест прошёл»
tests.some((t) => !t.passed);    // false — ∃¬: «какой-то тест упал»

// Закон отрицания в действии: НЕ (все прошли) === (некоторые упали)
const users = [{ admin: true }, { admin: false }];
!users.every((u) => u.admin) === users.some((u) => !u.admin);  // true: ¬∀ = ∃¬
!users.some((u) => u.admin) === users.every((u) => !u.admin);  // true: ¬∃ = ∀¬

// Исправление «инцидента с зелёным баннером» — один дополнительный конъюнкт:
const suiteIsGreen = tests.length > 0 && tests.every((t) => t.passed);
```

## Отрицание кванторов: ¬∀ = ∃¬

Вот где чтение спек ломается чаще всего. Отрицание «у каждого пользователя подтверждённый email» — это **не** «у каждого пользователя неподтверждённый email». Это «у **некоторого** пользователя email не подтверждён» — один контрпример. Формально: ¬∀x P(x) ≡ ∃x ¬P(x), и симметрично ¬∃x P(x) ≡ ∀x ¬P(x). Чтобы отрицать кванторное предложение, *поменяйте квантор и отрицайте внутренность*. Отрицание просачивается внутрь, переворачивая каждый ∀ в ∃ и каждый ∃ в ∀ по пути.

Это механический навык, и он платит ренту ежедневно. «Ни один тест не падает» — это ¬∃t падает(t), что закон переписывает как ∀t ¬падает(t) — «каждый тест не падает». Звучит так же, как «все тесты проходят», и на непустом сьюте это одно и то же. Две формулировки расходятся только на краю — ровно там, где жил инцидент. То же на ревью: когда кто-то пишет `!items.every(isValid)`, а коллега «упрощает» до `items.every(i => !isValid(i))`, он молча превратил *не все валидны* (один плохой элемент) во *все невалидны* (плох каждый). Компилятор не возразит. Закон отрицания кванторов — возразит.

<Inset kind="why" lang="ru">
Почему `.every()` на пустом массиве возвращает true, а не что-нибудь «побезопаснее»? Потому что математике нужно, чтобы ¬∀ = ∃¬ выполнялось *всегда*, без исключений для пустых коллекций. У «все элементы пустого множества фиолетовые» нет контрпримера — нет элемента, который не был бы фиолетовым, — значит, по закону отрицания утверждение обязано считаться истинным. Логики называют это **тривиальной (vacuous) истиной**. Похоже на адвокатский трюк, но альтернатива хуже: будь ∀ над пустым множеством ложным, утверждение «все мои падающие тесты — в модуле платежей» становилось бы ложным в момент, когда вы чините последний падающий тест, и каждой теореме понадобилась бы особая оговорка для пустого случая. Конвенция сохраняет алгебру чистой — и тихо требует от инженеров задавать ∃-вопросы («запустилось ли хоть что-то?») рядом с ∀-вопросами («прошло ли всё?»).
</Inset>

## Порядок кванторов: ∀∃ — это не ∃∀

Когда предложение складывает два квантора, их порядок меняет смысл — иногда на миллионы долларов. Сравните: **∀ сервис ∃ инженер** — у каждого сервиса есть дежурный инженер (возможно, у каждого свой). **∃ инженер ∀ сервис** — существует один инженер, дежурящий по *всем* сервисам (один героический человек, единая точка отказа). Естественный язык прячет разницу — «есть дежурный для каждого сервиса» читается обоими способами, — но формальный порядок фиксирует её: более поздний квантор имеет право *зависеть* от более раннего. В ∀s ∃e инженер e может меняться вместе с сервисом s. В ∃e ∀s один фиксированный e обязан покрыть все s.

Импликация работает в одну сторону: ∃∀ влечёт ∀∃ (если один инженер покрывает всё, то каждый сервис уж точно покрыт), но никогда наоборот. Ограничения базы данных говорят на этом языке буквально: «у каждого заказа есть клиент» (∀o ∃c — внешний ключ) дико отличается от «существует клиент, владеющий каждым заказом» (∃c ∀o — катастрофа в данных). Чтение спек на уровне сениора — во многом привычка спрашивать: *какой квантор идёт первым и чему разрешено зависеть от чего?*

## Чтение спек без логических off-by-one

Кванторные баги в прозе — логический аналог ошибок на единицу, и кучкуются они в предсказуемых местах. **Неявный ∀**: «запросы обрываются по таймауту через 30 с» — все запросы? включая health-check'и? вебхуки? Непроговорённый универсал — место, где прячутся исключения. **Тривиальный ∀**: «все мигрированные аккаунты верифицированы» истинно, когда мигрировало ноль аккаунтов, — каждому ∀-утверждению в отчёте задавайте ∃-вопрос: *а множество было непустым?* **Двойные отрицания над кванторами**: «ни один пользователь без подписки не может экспортировать» — это ∀u (¬подписка(u) → ¬экспорт(u)); прогоните отрицания по закону, и получится «каждый, кто может экспортировать, имеет подписку» — то же утверждение, теперь пригодное для ревью. **SQL**: подзапрос `WHERE NOT EXISTS (...)` — это замаскированный ∀¬, а `NOT IN` с NULL внутри молча возвращает ноль строк, потому что трёхзначная логика ломает чистую симметрию ¬∃ = ∀¬, на которую рассчитывают инженеры. Когда предложение сопротивляется — переведите его в символы, примените ¬∀ = ∃¬ механически и переведите обратно: символы не устают, а проза — да.
</Explanation>

<KeyTakeaway>∀ заявляет каждый случай и умирает от одного контрпримера; ∃ заявляет одного свидетеля и умирает только от полного перебора. Отрицание меняет их местами — ¬∀ = ∃¬, ¬∃ = ∀¬, — а порядок важен: ∃∀ влечёт ∀∃ и никогда наоборот. В коде: .every() — это ∀ (тривиально true на пустом), .some() — это ∃.</KeyTakeaway>

Кванторы — это два способа, которыми предложение говорит о целой коллекции: ∀ («для всех») заявляет свойство для каждого элемента и рушится от одного контрпримера, а ∃ («существует») заявляет хотя бы одного свидетеля и рушится только от полного перебора множества — асимметрия, из-за которой тестирование доказывает наличие багов, но никогда их отсутствие. Отрицание меняет кванторы местами, просачиваясь внутрь: ¬∀ = ∃¬ («не все прошли» значит «какой-то упал», а не «упали все») и ¬∃ = ∀¬ («ни один не падает» значит «каждый проходит») — механическая перезапись, которая ловит ревью-«упрощения» вроде превращения !items.every(isValid) в items.every(i => !isValid(i)), молча меняющего «есть один плохой» на «плохи все». Порядок важен, когда кванторы складываются, потому что поздний может зависеть от раннего: ∀s ∃e (у каждого сервиса свой дежурный) против ∃e ∀s (один человек покрывает всё), и импликация идёт только от ∃∀ к ∀∃. В коде .every() — это ∀, .some() — это ∃, и .every() на пустом массиве тривиально истинен — цена законов отрицания без исключений, — именно так «все тесты прошли» однажды означало «ни один не запускался»; лекарство — пара к каждому ∀-чеку в виде ∃-вопроса tests.length > 0 и пара к каждому универсальному утверждению в спеке в виде вопросов «над каким именно множеством?» и «было ли оно непустым?»
