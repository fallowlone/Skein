<Step n={1}>
**Одна лестница, два способа подняться.**

Вспомните индукцию из блока о рассуждениях: чтобы доказать утверждение `P(n)` для каждого n, вы доказываете **базу** — `P(0)` верно — и **шаг** — *если* `P(n-1)` верно, *то* верно и `P(n)`. Два конечных куска работы — и лестница достаёт до каждой ступени: P(0), значит P(1), значит P(2), значит P(3)…

Теперь положите рядом рекурсивную функцию. Сходство — не сходство; это тождество:

| Индукция (доказываем)           | Рекурсия (вычисляем)                    |
| ------------------------------- | --------------------------------------- |
| База: доказать P(0) напрямую    | Базовый случай: вернуть ответ напрямую  |
| Гипотеза: допустить P(n−1)      | Доверие вызову: f(n−1) корректен        |
| Шаг: вывести P(n) из P(n−1)     | Слой: собрать f(n) из f(n−1)            |
| Вывод: P(n) для всех n          | f работает на любом входе               |

«Прыжок веры» из первого урока блока получает официальное имя: это **индуктивная гипотеза**. Доверяя `factorial(n - 1)` при написании `factorial(n)`, вы делаете ровно то, что делает математик, допуская `P(n-1)` при доказательстве `P(n)`. Индукция доказывает башню утверждений из базы и шага; рекурсия вычисляет башню значений из базы и шага. Одна структура, два взгляда — и выгода практична: всякая рекурсивная функция носит внутри собственное доказательство корректности, которое осталось лишь выписать.
</Step>

<Step n={2}>
**Доказываем sum полностью.**

Выпишем одно от начала до конца — предложениями, которые может проверить новичок. Функция:

```js
function sum(list) {
  if (list.length === 0) return 0;       // база
  return list[0] + sum(list.slice(1));   // голова + меньший себя
}
```

**Утверждение** `P(n)`: для любого списка длины n `sum(list)` возвращает сумму его элементов.

**База — `P(0)`.** Список длины 0 — пустой список. Функция попадает в базовый случай и возвращает 0. Сумма нуля чисел равна 0. Значит, возвращено правильное значение. ✓

**Шаг — из `P(n-1)` следует `P(n)`.** Примем гипотезу: `sum` возвращает правильную сумму для *любого* списка длины n−1. Возьмём произвольный список длины n, где n не меньше 1. Он не пуст, поэтому функция минует базу и возвращает `list[0] + sum(list.slice(1))`. Разберём части. `list.slice(1)` — хвост, список длины n−1, к нему применима гипотеза: `sum(list.slice(1))` — в точности сумма элементов хвоста. Значит, функция возвращает *первый элемент + сумму всех остальных*, то есть ровно сумму всех n элементов. ✓

**Вывод.** По индукции `P(n)` верно для каждого n: `sum` корректна для *всех* списков. Не всех протестированных — всех.

Перечитайте шаг и заметьте, чего вы *не* делали: вы не трассировали внутренний вызов. Вы использовали его корректность как допущение — законно, потому что допущение и есть индуктивная гипотеза, а хвост действительно короче. Доказательство имеет в точности форму кода. В этом глубокая причина, почему рекурсивный код приятно верифицировать: обязательства доказательства — это ветки.

<Step n={3}>
**Цикл носит то же доказательство.**

Большинство продовых сумм — циклы, а не рекурсия. Доказательство испарилось? Напишем цикл:

```js
function sumLoop(list) {
  let acc = 0;
  // инвариант: acc равен сумме первых i элементов
  for (let i = 0; i < list.length; i++) {
    acc += list[i];
  }
  return acc;
}
```

Комментарий называется **инвариантом цикла**: это утверждение, истинное *всякий раз, когда цикл проверяет своё условие*. Доказательство корректности состоит из трёх тактов — и они покажутся знакомыми:

- **Установить.** Перед первой итерацией i = 0 и acc = 0 — сумма первых нуля элементов. Истинно на старте. *(Это базовый случай.)*
- **Сохранить.** Пусть инвариант верен на входе в итерацию: acc = сумма первых i элементов. Тело прибавляет `list[i]`, i становится i+1; теперь acc = сумма первых i+1 элементов. Инвариант выжил. *(Это индуктивный шаг.)*
- **Снять урожай.** Цикл выходит при i = n. Инвариант в этот момент говорит: acc = сумма первых n элементов — весь список. Возвращаем. ✓

Установить, сохранить, снять — база, шаг, вывод. **Инвариант цикла — это индукция в итеративной одежде.** Индукция рекурсии и инвариант итерации — не две техники доказательства, а одна истина в двух синтаксисах. Поэтому перевод рекурсии в цикл (и обратно) ощущается механическим, стоит это увидеть: вы переодеваете то же доказательство.
</Step>

<Step n={4}>
**Завершение: доказательство, которого корректность не даёт.**

Всё выше доказывает нечто тонкое: *если* функция возвращается, ответ верен. Когда пишешь инвариант цикла или индуктивное доказательство, спроси себя: есть ли рядом аргумент о завершении? Без него ты сертифицировал «верно, если закончится» — но не «закончится». Математики называют это **частичной корректностью**. Функция, зациклившаяся навсегда, удовлетворяет ей тривиально — она никогда не вернёт неправильный ответ, потому что никогда не вернётся. Недостающая половина — **завершение**, и у неё свой инструмент: **мера** — величина, которая является неотрицательным целым и *строго убывает* на каждом рекурсивном вызове или итерации. Неотрицательное целое не может убывать вечно; оно обязано упереться в дно, значит, рекурсия обязана достичь базы. Для `sum` мера — длина списка: n, n−1, n−2, … 0. Готово.

Теперь полный разбор пациента из пролога — двоичный поиск по отсортированному массиву с диапазоном кандидатов в полуинтервале `[lo, hi)`:

```js
function search(arr, target) {
  let lo = 0, hi = arr.length;
  // инвариант: если target есть в arr, его индекс лежит в [lo, hi)
  while (lo < hi) {
    const mid = lo + Math.floor((hi - lo) / 2);  // фикс Блоха: без переполнения lo+hi
    if (arr[mid] === target) return mid;
    if (arr[mid] < target) lo = mid + 1;         // отбросить левую половину — мала
    else hi = mid;                               // отбросить правую половину — велика
  }
  return -1;
}
```

**Корректность (инвариант).** Если цель существует, она лежит в `[lo, hi)`. Истинно вначале — диапазон равен всему массиву. Сохраняется каждой веткой: массив отсортирован, поэтому если `arr[mid]` меньше цели, ни один индекс до mid включительно её содержать не может, и подъём `lo` до mid+1 отбрасывает только невозможных кандидатов; симметрично для второй ветки. На выходе с пустым диапазоном инвариант говорит: цель — в пустом множестве, то есть отсутствует, и −1 — честный ответ. ✓

**Завершение (мера).** Пусть мера — ширина `hi − lo`, неотрицательное целое. Каждая итерация либо возвращается, либо поднимает `lo` до mid+1 (mid не меньше lo, значит lo растёт минимум на 1), либо опускает `hi` до mid (mid строго меньше hi, значит hi падает минимум на 1). В любом случае ширина строго убывает — значит, дойдёт до 0, и цикл закончится. ✓

Корректность **плюс** завершение вместе называются **тотальной корректностью**: функция возвращается, и возвращает правильное. Одиннадцать строк, два коротких доказательства — и функция сертифицирована для входов, которые не построит ни один тест.

<Inset kind="edgecase" lang="ru">
Аргумент с мерой — место, где ловятся ошибки на единицу. Замените lo = mid + 1 на lo = mid и прогоните доказательство заново: когда диапазон сузится до ширины 1, mid совпадёт с lo, ветка присвоит lo значение mid — и ширина останется 1 навсегда. Инвариант всё ещё верен (частичная корректность цела!), но мера перестала убывать: бесконечный цикл. Тесты с удачными целями проходят; доказательство падает в одной строке. Когда двоичный поиск виснет в проде, почти всегда это мера, переставшая убывать на какой-то ветке.
</Inset>

<Step n={5}>
**Заблуждение: тесты поддерживают — доказательство покрывает.**

Тестовый набор проверяет конечное число входов: n = 0, 1, 5, 100, ну ещё тысячу от фаззера. Утверждение «sum корректна» квантифицировано по *всем* n — их бесконечно много. Никакая конечная стопка зелёных галочек до него не дотягивается — так же, как список чётных чисел не доказывает, что все числа чётные. Вспомните урок о контрпримерах из блока техник доказательства: один упавший тест *опровергает* всеобщее утверждение навсегда, а миллион прошедших лишь не сумел его опровергнуть. **Тесты поддерживают; доказательство покрывает.** Индукция — единственный инструмент этого блока, касающийся всех n сразу: два конечных шага, бесконечное покрытие.

Но пролог режет в обе стороны, будем честны. Двоичный поиск *был* доказан корректным — и доказательство было верным. Это было доказательство об идеальных целых числах, а `int` в Java — не идеальное целое: на миллиарде элементов `low + high` перевернулся, и молчаливое допущение доказательства лопнуло. Зрелый вывод не «доказательства бесполезны», а вот какой: **доказательство покрывает всё внутри своих допущений — и вы обязаны знать, каковы они.** Тесты встраивают свои допущения молча (малые n, дружелюбные данные); доказательство хотя бы пишет собственный мелкий шрифт — и переполнение исчезает, как только модель учитывает ограниченные int: исправленная строка вычисляет середину, вообще не образуя `low + high`. Доказательство покрывает бесконечное; тесты прощупывают допущения. Сеньоры запускают и то и другое.
</Step>

<WorkedExample lang="ru">
**Докажите тотальную корректность двоичного поиска на отсортированном массиве из 16 элементов.**

Функция использует полуинтервал `[lo, hi)` и вычисляет mid как `lo + floor((hi - lo) / 2)`.

**Часть 1 — Корректность (инвариант).** Утверждение: *если цель есть в массиве, её индекс лежит в `[lo, hi)`*.

- *Установить*: Изначально lo = 0, hi = 16. Утверждение: «если цель есть, её индекс в [0, 16)» — истинно, поскольку каждый индекс 16-элементного массива лежит между 0 и 15 включительно.
- *Сохранить*: Входим в итерацию с выполненным инвариантом; код проверяет `arr[mid]`. Если оно равно цели — возвращаемся немедленно (сохранять не нужно). Если `arr[mid] < target`: массив отсортирован, значит цели нет ни на одном индексе ≤ mid — поднятие lo до mid+1 отбрасывает только невозможных кандидатов. Симметрично: если `arr[mid] > target`, hi = mid отбрасывает индексы ≥ mid. В обоих случаях если цель была в [lo, hi) до итерации, она остаётся в новом, более узком диапазоне. ✓
- *Снять урожай*: Цикл выходит при lo = hi — диапазон пуст. Инвариант говорит: цель в пустом диапазоне — невозможно, значит цель отсутствует, и возврат −1 корректен. ✓

**Часть 2 — Завершение (мера).** Утверждение: цикл всегда заканчивается.

Ширина hi − lo начинается с 16 (неотрицательное целое). Каждая итерация, не возвращающаяся немедленно, либо поднимает lo, либо опускает hi, строго уменьшая ширину. Неотрицательное целое, убывающее на каждом шаге, должно в конце концов достичь 0, при котором lo = hi и цикл выходит.

Для 16 элементов: 16 → 8 → 4 → 2 → 1 → 0. Не более 4 итераций до опустения диапазона. **Тотальная корректность: сертифицировано.**
</WorkedExample>

<Recap lang="ru">
Индукция и рекурсия — одна структура, прочитанная в двух направлениях: индукция доказывает P(n) из P(меньшего), рекурсия вычисляет f(n) из f(меньшего), и четырёхстрочное соответствие точно — база к базовому случаю, индуктивная гипотеза к доверенному вызову, шаг к слою работы, всеобщий вывод к функции, корректной на любом входе. Прыжок веры из начала блока — это индуктивная гипотеза с документами в порядке. Доказательство sum показывает метод: проверить пустой список напрямую, затем для длины n допустить, что хвост длины n−1 суммируется верно, и убедиться, что голова плюс сумма хвоста — вся сумма; внутренний вызов не трассируется никогда, потому что строго более короткий хвост и делает доверие законным. То же доказательство переживает перевод в цикл как инвариант — установить до первой итерации, показать сохранение на каждой, снять урожай на выходе, — так что индукция рекурсии и инвариант итерации суть одна истина в двух синтаксисах. Всё это покупает лишь частичную корректность: верно, если вернулось. Завершение доказывается отдельно мерой — неотрицательным целым, строго убывающим на каждом шаге: длина списка, расстояние счётчика до n, ширина диапазона hi − lo в двоичном поиске, где каждая ветка доказуемо сжимает ширину, а ошибка на единицу вроде lo = mid замораживает её в бесконечный цикл. Корректность плюс завершение — тотальная корректность для всех n, недосягаемая для тестов: они проверяют конечное число входов, а всеобщее утверждение говорит о бесконечном. Тесты поддерживают, доказательство покрывает; и покрывает оно ровно то, что разрешают его допущения — чему девять лет сломанного двоичного поиска научили всех. Пишите доказательство — и пускайте тесты охотиться за его мелким шрифтом.
</Recap>
