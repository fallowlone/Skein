## Сниппет 1 — таймлайн заголовка

```
Cache-Control: max-age=60, stale-while-revalidate=300, stale-if-error=86400
```

```

t=150s  запрос  -> ???
t=600s  запрос, origin вернул 503 -> ???
```

<Recap lang="ru">
Каждый инцидент свежести читается в заголовке, логе или конфиге. Слоёный заголовок — это три вложенных окна: свежее, stale-while-revalidate, stale-if-error — и запрос трассируется по тому, в какое окно попадает его метка времени. Лог edge с растущим origin_inflight по одному ключу — это стадо фоновых обновлений, чинимое single-flight плюс джиттером, а не перезапуском. Клиентский конфиг воспроизводит модель: ревалидация на focus/reconnect работает stale-first, а dedupingInterval коалесцирует параллельные вызовы. И ни один заголовок нигде не делает SWR безопасным на решении об авторизации. Теперь, когда открываешь лог edge и видишь, как origin_inflight ползёт вверх по одному ключу, сразу понимаешь, что произошло — и что перезапуск origin здесь не причём.
</Recap>
