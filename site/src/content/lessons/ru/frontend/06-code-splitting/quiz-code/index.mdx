## Сниппет 1 — где стоит граница

```jsx
// A: импорт на верхнем уровне модуля — бандлится в родительский чанк
import { HeavyEditor } from "./HeavyEditor";

function EditPanel({ open }) {
  if (!open) return null;
  return <HeavyEditor />;
}

// B: dynamic import внутри гейта
const HeavyEditor = React.lazy(() => import("./HeavyEditor"));

function EditPanel({ open }) {
  if (!open) return null;
  return (
    <Suspense fallback={<Spinner />}>
      <HeavyEditor />
    </Suspense>
  );
}
```

## Сниппет 2 — вложенные границы Suspense

```jsx
const Dashboard = React.lazy(() => import("./Dashboard"));
const Chart = React.lazy(() => import("./Chart"));

function Page() {
  return (
    <Suspense fallback={<PageSkeleton />}>
      <Dashboard>
        <Suspense fallback={<ChartSpinner />}>
          <Chart />
        </Suspense>
      </Dashboard>
    </Suspense>
  );
}
```

## Сниппет 3 — prefetch по hover

```jsx
const Settings = React.lazy(() => import("./Settings"));

function NavLink() {
  return (
    <a
      href="/settings"
      onMouseEnter={() => import("./Settings")}
    >
      Settings
    </a>
  );
}
```

<Recap lang="ru">
Три вещи решают поведение разбивки в коде: статический верхнеуровневый импорт всегда бандлится в родительский чанк, поэтому только import() создаёт точку разбивки — и runtime-условие этого не меняет. Вложенные границы React.lazy обнаруживаются последовательно, поэтому каждый уровень добавляет round trip на канале с высоким RTT. А запуск import() заранее (на hover или idle) прогревает кэш чанка, чтобы итоговое монтирование пропустило waterfall и спиннер. Читай, где стоит граница и когда триггерится загрузка, затем сдвигай триггер раньше, а не сливай чанк обратно. Теперь, когда видишь в PR вложенные React.lazy-компоненты, — первым делом проверь, стоят ли эти границы последовательно на критическом пути: если да, попроси preload-хинт или плоскую границу до мержа.
</Recap>
