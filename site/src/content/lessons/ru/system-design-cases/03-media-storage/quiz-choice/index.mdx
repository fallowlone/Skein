<Recap lang="ru">
Сквозная линия всех четырёх разборов — медиа-системы формируются до того, как ты их строишь. **Держи крупные байты вне пути данных сервера приложения** — грузи прямо в объектное хранилище, ссылайся по ключу, отдавай с CDN/data plane — чтобы API остался на пути управления. **Транскодируй** одну загрузку в лестницу сегментированных рендиций, чтобы **adaptive bitrate** подстраивался под меняющуюся сеть каждого зрителя. **Адресация по содержимому** даёт **delta-синк** (двигай лишь изменённые чанки) и **дедуп** (одинаковые чанки хранятся однажды) одним механизмом. **Erasure coding** (10+4 ≈ 1.4× накладных) бьёт 11 девяток куда дешевле 3× репликации для холодных данных, при этом ты всё же реплицируешь малые горячие объекты. **Партиционируй почту по пользователю**, ведь у ящиков нет кросс-юзер-джойнов на горячем пути. И принимай **eventual consistency**, где человек не отличит — вирусный счётчик просмотров логируется и агрегируется, никогда синхронно не инкрементируется в одну горячую строку. Сделай структуру правильно — остальное детали; сделай неправильно — никакой тюнинг не спасёт.
</Recap>
