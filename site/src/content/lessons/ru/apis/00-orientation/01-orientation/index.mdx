<Explanation>

## Контракт, а не код

Когда вы делаете заказ у стойки, вы не идёте на кухню. Вы читаете меню, называете блюдо, платите и получаете тарелку. Вы не видите, как готовят, и вам это не нужно. Меню — это **контракт**: список того, что можно попросить и что вы получите.

API — такое же меню, но для программ. Программа, которая предлагает API (**сервер**), публикует список именованных операций: «дай прогноз», «создай пользователя», «отправь сообщение». Другая программа (**клиент**) вызывает одну из операций и получает результат. Ни одна сторона не видит код другой. Пока обе соблюдают контракт, каждая может менять себя внутри как угодно.

## Запрос и ответ

Один вызов состоит из двух половин, которые идут по сети:

- **Запрос** — клиент говорит, какую операцию он хочет, и даёт нужные детали (какой город, какой пользователь).
- **Ответ** — сервер присылает результат и небольшой статус: получилось или нет.

## Почему контракт — это суть

Поскольку контракт прячет внутреннее устройство, две команды, которые никогда не встречались, всё равно могут строить вместе. Погодная компания может за ночь переписать всю свою систему — ваше приложение продолжит работать, пока «дай прогноз» принимает город и возвращает температуру. Именно эта устойчивость позволяет собирать современный веб из тысяч программ, вызывающих друг друга. Остальной трек — про то, как хорошо проектировать этот контракт: именовать операции, формировать ответы, сообщать об ошибках и не ломать вызывающих при изменениях.

<Recap lang="ru">
API — это контракт между программами: одна сторона (сервер) публикует именованные операции, другая (клиент) вызывает их по сети. Каждый вызов — это запрос туда и ответ обратно, со статусом. Контракт прячет код внутри, поэтому отдельные команды могут строить вместе, и каждая может менять внутреннее устройство, не ломая другую. Остальной трек — про то, как хорошо проектировать этот контракт.
</Recap>
