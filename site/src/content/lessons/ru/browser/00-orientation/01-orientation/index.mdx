## Три вида текста становятся одной страницей

Вы никогда не отдаёте браузеру готовую картинку. Вы отдаёте три файла с обычным текстом, у каждого своя задача:

- **HTML** — содержимое и структура: заголовки, абзацы и сама кнопка.
- **CSS** — внешний вид: цвета, отступы, шрифты, где что стоит.
- **JavaScript** — поведение: что происходит при клике, вводе или прокрутке.

Браузер читает HTML, применяет CSS, выполняет JavaScript и рисует результат на экране. Измените любой из трёх — и страница изменится. Это и есть вся работа, повторённая тысячи раз в секунду.

## По одной задаче за раз

Вот часть, которую новички почти всегда понимают неправильно: ваш JavaScript не выполняется «параллельно» со всем остальным. У браузера одна главная линия работы, и он доводит одну задачу до конца, прежде чем начать следующую: прочитать этот кусок, выполнить тот обработчик клика, обновить экран, потом следующее.

Поэтому медленный кусок вашего кода замораживает всю страницу: пока он работает, ничего другого происходить не может. Кнопка не отвечает, прокрутка застывает, спиннер перестаёт крутиться — потому что единственный работник занят вашей задачей и не может делать два дела сразу. Система, которая выстраивает эти задачи в очередь и выполняет их по одной, называется **событийный цикл (event loop)**, и это первая настоящая тема этого подъёма.

<Recap lang="ru">
Браузер берёт три вида обычного текста — HTML для содержимого, CSS для внешнего вида, JavaScript для поведения — и превращает их в одну интерактивную страницу, по которой можно кликать. Главное: он выполняет ваш код по одной задаче за раз на единственной главной линии работы, поэтому медленная задача замораживает всю страницу. Именно этот факт открывает подъём событийным циклом, а дальше идут рендеринг, движок JavaScript, воркеры, фреймворки и производительность.
</Recap>
