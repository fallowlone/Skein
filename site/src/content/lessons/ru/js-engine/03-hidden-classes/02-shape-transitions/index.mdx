## Переходы — это рёбра в общем дереве

Вспомним однострочную версию из `browser/03-v8-internals/03-hidden-classes`: добавление `x` затем `y` приходит в другой лист, чем добавление `y` затем `x`, так что порядок важен. Теперь механизм. Каждый Map хранит forward-**TransitionArray** с ключом `{имя свойства, attributes}`. Добавление свойства:

1. Ищет ребро `{имя, attributes}` в TransitionArray текущего Map.
2. Если ребро есть, **следует** по нему — никакой аллокации, вы переиспользуете существующий дочерний Map и его (общий) DescriptorArray.
3. Если ребра нет, **создаёт** новый дочерний Map (расширяя DescriptorArray родителя на один дескриптор), записывает ребро и направляет объект на новый Map.

Объекты с одним исходным Map могут разделять пути переходов. Когда путь уже создан, новые объекты с тем же порядком свойств проходят по нему без новых Map. Другой порядок может создать новую ветку; повторение этого порядка тоже использует готовый путь.

```js
const a = {}; a.x = 1; a.y = 2;   // empty -> +x -> +x,y   (создаёт 2 ребра)
const b = {}; b.x = 3; b.y = 4;   // empty -> +x -> +x,y   (следует по ним; 0 новых Map)
const c = {}; c.y = 5; c.x = 6;   // empty -> +y -> +y,x   (новая ветка; 2 новых Map)
```

## Ещё три способа перейти (не только добавление свойств)

Обзор намекал, что переходы приходят лишь от добавления свойств. Это не так. Есть три других триггера, и они кусаются в проде:

- **Смена elements kind.** Запись float'а в массив `PACKED_SMI_ELEMENTS` или создание дырки переводит Map массива в более широкий elements kind (`PACKED_SMI → PACKED_DOUBLE → PACKED_ELEMENTS` и HOLEY-варианты). Односторонне, как и дерево свойств.
- **Обобщение representation поля.** Это главное. Поле стартует узким — скажем, `Smi`. Если позже какой-то экземпляр сохранит значение, которое не помещается (`2.5` или строку), representation поля должен **расшириться** до `Double` или `Tagged`. Но representation — это свойство *Map*, общее для всех экземпляров. Так что V8 не может изменить один объект; он должен обобщить Map.
- **Потеря constness.** Поле может быть помечено `const`, когда экземпляры инициализируют его, но затем не перезаписывают. Начальные значения у разных экземпляров могут различаться. Поздняя запись в существующее поле может сделать дескриптор изменяемым и инвалидировать код, полагавшийся на constness.

Эти изменения затрагивают механизмы форм и feedback V8, хотя набор имён свойств может не измениться. Создастся ли новый Map, обобщится ли дескриптор на месте или инвалидируется оптимизированный код, зависит от конкретного перехода.

## Deprecation и миграция: один из путей расширения

Пусть много объектов разделяют Map `M1`, где `temp` имеет representation `Smi`. Один объект сохраняет `98.6`. V8 требуется representation, способное хранить это значение. Иногда метаданные можно обобщить на месте; схема показывает случай, когда V8 создаёт новый путь переходов и помечает старый Map deprecated:

1. V8 создаёт путь с `temp` в representation `Double` и помечает старый путь deprecated.
2. Существующие объекты пока могут указывать на старый Map. V8 не обходит всю кучу, чтобы сразу переписать их.
3. При доступе, который проверяет deprecated Map, V8 мигрирует затронутый объект на актуальную раскладку и продолжает операцию.

Это механизм реализации V8, а не семантика JavaScript. Расширение representation для этого поля односторонне: чередование целых и дробных значений после расширения не создаёт старый узкий Map заново.

Чтобы исследовать поведение в сборке V8 с нужными флагами, используйте `--trace-generalization` для изменений поля и `--trace-migration` для миграции объектов. Доступные флаги проверьте через `node --v8-options`.


## Почему разные порядки ключей могут стоить дороже

Создание одинаковых наборов свойств в разных порядках может дать несколько веток от одного исходного Map. Повторяющиеся порядки используют готовые пути, но место чтения, куда попадают объекты из разных веток, видит больше Map. Его inline cache может стать полиморфным или мегаморфным, оставляя меньше возможностей для специализации по форме.

Для записи со стабильной структурой инициализируйте поля в одном порядке, выбирая значения по умолчанию подходящего типа. Для действительно динамических наборов ключей может подойти коллекция `Map`. Прежде чем менять модель данных, измерьте горячий путь.

<Recap lang="ru">
Дерево переходов Map позволяет объектам с одним исходным Map переиспользовать путь добавления свойств. Разный порядок может дать разные итоговые Map, а повторяющийся порядок использует собственный готовый путь. Изменения elements kind, representation поля и constness могут повлиять на форму или оптимизированный код без добавления свойства. На показанном пути deprecation V8 создаёт новый Map для расширенного representation, а старые экземпляры мигрируют лениво; другие обобщения возможны на месте. Место чтения с множеством форм может потерять специализированный быстрый путь, но влияние на производительность нужно измерять.
</Recap>
