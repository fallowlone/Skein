## Один тип Number, несколько раскладок

На уровне языка обычные числа JavaScript следуют семантике IEEE-754 double. V8 может выбрать более компактное внутреннее представление, если позволяют **значение и место хранения**. В типичной 64-битной сборке V8 со сжатием указателей тегированный слот в куче занимает **32 бита**. Младший бит различает **Smi** (`0`, целое прямо в слоте) и тегированную ссылку в кучу (`1`). В Smi помещается **31-битное знаковое целое** от −2³⁰ до 2³⁰−1.

Это описание *сжатого тегированного хранения*, а не универсальный размер всех значений JavaScript или машинных регистров. В сборке без сжатия и в оптимизированном коде представление может отличаться. Для самого Smi не нужен отдельный объект в куче; V8 может использовать специализированную целочисленную арифметику, но весь оператор JavaScript `+` нельзя буквально свести к одной инструкции процессора.

Верхняя ветка схемы оставляет `42` внутри тегированного слота. `3.14` в формат целого не помещается. Если дробь нужно хранить в **тегированном** слоте, V8 может положить туда ссылку на **HeapNumber**. У объекта есть поле Map и 64-битное значение IEEE-754. Ссылка и число занимают разные места памяти. Однако из этого **не следует**, что вычисление дроби на каждой итерации создаёт новый HeapNumber: оптимизированный код может держать промежуточные double в машинных регистрах.

## Сырые double в числовых массивах

Нижняя полоса показывает другой путь. Массив с `PACKED_DOUBLE_ELEMENTS` V8 может хранить в наборе слотов с сырыми double. В буфере `Float64Array` элементы тоже представлены 64-битными числами с плавающей точкой. Сам массив или буфер занимает память, но каждому хранимому элементу не требуется отдельный HeapNumber. При переносе значения в обычный тегированный слот обёртка может понадобиться; оптимизированный код иногда избегает этого перехода.

```js
const readings = [1, 2, 3]; // обычно PACKED_SMI_ELEMENTS
readings.push(3.14);        // переход к PACKED_DOUBLE_ELEMENTS
readings.push(4);           // теперь и 4 хранится в double-слоте

const samples = new Float64Array([1, 3.14, 4]);
// Элементы буфера — 64-битные double. Это не утверждение
// о каждом временном значении во время работы с массивом.
```

Переход от массива Smi к double расширяет его способ хранения. Для данного массива это, как правило, односторонний переход; произвольный объект может расширить вид элементов ещё раз — до `PACKED_ELEMENTS`. Меняется **раскладка элементов массива**, а не тип `1` по спецификации ECMAScript.

## Что действительно меняется при выходе за диапазон

Если значение вышло за пределы диапазона сжатого Smi, оно **не может оставаться Smi в таком слоте**. Это не означает автоматический деопт функции, отдельный HeapNumber на каждое арифметическое действие или постоянное замедление. Деоптимизация происходит, если *оптимизированный код опирался на более узкое предположение* и соответствующая проверка не прошла. Итог зависит от машинного кода, места хранения и дальнейшей оптимизации.

```js
function accumulate(values) {
  let total = 0;
  for (const value of values) total += value;
  return total;
}

accumulate([1, 2, 3]);
accumulate([2 ** 30, 1]); // результат за пределами сжатого Smi
```

Второй вызов даёт *гипотезу для проверки*, а не обещание деопта именно этой программы. Важны история прогрева и версия V8. Если участок горячий, измерьте реальную нагрузку, посмотрите профиль аллокаций и трассы оптимизации/деоптимизации: какая проверка действительно не прошла? Не меняйте семантику вычислений только ради представления: `| 0` приводит к знаковому **32-битному** целому, которое всё ещё может выйти за **31-битный** диапазон сжатого Smi; `Math.fround` округляет до float32 и не управляет упаковкой числа.

<Inset kind="edgecase" lang="ru">
`-0` и `NaN` не бывают Smi. Добавление `-0`, `NaN` или дроби в массив Smi может перевести его на double-элементы. Именованные свойства объекта — отдельный путь: согласно текущей документации V8, свойство `kDouble` использует упакованный HeapNumber, который при записи может изменяться на месте; сырые double внутри объекта больше не поддерживаются. Нельзя переносить устройство числового массива на поля объекта.
</Inset>

<Recap lang="ru">
Smi — целое внутри тегированного значения, которому не нужен отдельный объект в куче. В типичных сжатых слотах V8 его знаковый диапазон занимает 31 бит, а младший тег-бит равен 0. Не-Smi число в тегированном месте может быть представлено через HeapNumber с 64-битным double. Но место хранения меняет картину: числовые массивы и буферы Float64Array содержат сырые double, а оптимизированный код может держать промежуточные числа без обёртки. Когда массив расширяется от Smi-элементов к double-элементам, меняется раскладка его хранилища, не смысл чисел JavaScript. Граница Smi — факт о представлении; деопт и стоимость аллокаций нужно измерять отдельно. При исследовании горячего числового участка ищите переход от сырого double к тегированному слоту или проверку нарушенного предположения.
</Recap>
