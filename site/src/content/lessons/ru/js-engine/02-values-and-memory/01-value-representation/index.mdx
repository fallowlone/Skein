## Один тегированный слот, две трактовки

V8 использует **тегированные значения** там, где одна ячейка может хранить разные значения JavaScript. Два главных случая: **Smi** (малое знаковое целое прямо в битах) и **ссылка на кучу** (тегированный указатель на объект). Это описание представления, а не перечень типов JavaScript: строки, объекты и особые значения могут идти путём ссылки.

Ширина зависит от места хранения. В 64-битной сборке со сжатием указателей тегированное поле **в куче V8 занимает 32 бита**: это Smi или смещение внутри области сжатых указателей размером 4 ГБ. При необходимости V8 восстанавливает полный указатель с помощью базы области. Значения в регистрах могут быть шире. Оптимизированный код и специализированное хранение могут использовать и **нетегированные** формы, например число double непосредственно. Поэтому «любое значение JS — одно 64-битное слово» плохо описывает память V8.

## Младший бит различает Smi и ссылку в кучу

Объекты кучи выровнены, поэтому младшие биты адреса можно отдать под теги. Для обычной сильной ссылки младший бит **0** означает Smi, а **1** — ссылку на кучу. Smi хранит целое прямо в слоте, без отдельного числового объекта. Для сжатой ссылки при необходимости восстанавливают указатель и читают целевой объект. Второй младший бит внутри V8 может различать сильные и слабые ссылки; код JavaScript обычно работает с сильными.

```text
сжатый тегированный слот (32 бита)
... биты целого ... 0         → Smi
... смещение в области ... 1  → тегированная ссылка в кучу
```

Развилка нужна, *когда код должен различить представления*. JIT часто может доказать форму значения и пропустить проверку. Это также не всегда одна инструкция и ровно одно разыменование: восстановление указателя, проверки и поведение кэша зависят от операции.

## Путь кучи ведёт к Map

Ссылка может вести к объекту, строке, функции, **HeapNumber** или особому значению. HeapNumber хранит число, не представимое как Smi. V8 также может держать некоторые double без упаковки в оптимизированном коде или подходящих полях и хранилищах элементов; это исключения из схемы тегированного слота.

Любой **HeapObject V8 начинается с поля Map по смещению 0**. Map описывает вид объекта и его раскладку. Для обычного JS-объекта раскладка помогает находить именованные свойства. Загрузка свойства может проверить известную Map и затем прочитать поле по известному смещению. Тегированный указатель, HeapObject и его Map — три разные сущности.

```text
тегированная ссылка → HeapObject
                      +0  поле Map → Map (вид и раскладка)
                      +…  поля или данные конкретного объекта
```

## Особые значения тоже идут путём кучи

`true`, `false`, `null` и `undefined` в V8 представлены особыми объектами **Oddball**. Внутренний **hole** — ещё одно сторожевое значение, встречающееся в разреженных массивах и неинициализированных привязках. Проверка неинициализированной привязки может превратить этот маркер в `ReferenceError`; само чтение его битов не является исключением. В тегированных ячейках эти значения хранятся как ссылки, хотя некоторые из них — примитивы JavaScript.

<Misconception id="mc-typeof-cost">
  <p><strong>«Тег-бит сразу сообщает V8 любой тип JavaScript».</strong> Младший бит различает Smi и ссылку на кучу. Для определения вида объекта V8 может прочитать Map или выполнить более быструю проверку известного объекта. Оптимизированный код иногда пропускает оба шага, если представление уже известно.</p>
</Misconception>

<Inset kind="why" lang="ru">
Зачем сжимать тегированные поля кучи? Полный указатель в 64-битной системе занимает восемь байт, но на объекты в области сжатия V8 можно ссылаться 32-битными смещениями. Сжатие многочисленных тегированных полей экономит память; при необходимости движок восстанавливает указатель. Это компромисс хранения, а не утверждение, что любое значение при исполнении занимает четыре байта.
</Inset>

Восстановленный указатель ведёт к HeapObject, первое поле которого — Map. Специализированное числовое хранение и оптимизированный код могут использовать другие представления.</KeyTakeaway>

<Recap lang="ru">
Тегированное представление V8 различает Smi внутри слота и ссылку на кучу по младшему биту. В 64-битных сборках со сжатием указателей многие тегированные поля кучи занимают четыре байта; сжатая ссылка — это смещение внутри области размером 4 ГБ, которое при необходимости дополняют базой. HeapObject, на который она ведёт, начинается с поля Map по смещению 0: оно ведёт к метаданным о виде и раскладке. `true`, `false`, `null` и `undefined` в тегированных ячейках представлены особыми объектами кучи. Эти правила описывают распространённый путь хранения, но не каждое значение: оптимизированный код и специализированные числовые поля или массивы могут использовать нетегированные формы. В следующих уроках подробнее разберём диапазон Smi, double и тегирование указателей.
</Recap>
