<Crux>V8 может отложить AST и байт-код функции, но PreParser всё равно проверяет синтаксис и сохраняет сведения об областях видимости, нужные внешнему коду.</Crux>

<Explanation>

## Какую работу V8 откладывает

Полный парсер строит **абстрактное синтаксическое дерево** и разрешает сведения, нужные для генерации байт-кода Ignition. Для функции, которая не нужна сразу, V8 может использовать **PreParser**. Он проходит по синтаксису, не строя полное AST этой функции и не компилируя её тело в байт-код. Если функцию позже вызовут, V8 тогда полностью разберёт и скомпилирует её. Это стратегия движка, а не гарантия языка JavaScript: синтаксис и эвристики V8 определяют, что разбирать жадно.

Пре-парсинг дешевле полного разбора, но это всё же настоящая работа. Он проверяет синтаксис и ранние ошибки: функция с некорректным синтаксисом не может ждать первого вызова, чтобы сообщить об ошибке. Он также записывает диапазон исходника и метаданные для внешней функции. «Беглый проход» — полезная интуиция, но **PreParser делает больше, чем ищет закрывающую скобку**.

## Сведения об области видимости, которые нельзя пропустить

Представим внешнюю функцию, возвращающую внутреннюю, которая обращается к `id`. Внутренняя может выполниться после возврата `outer`. V8 должен знать, что `id` нужно сохранить в контексте кучи, а не только во фрейме стека, который исчезнет при возврате.

```js
function outer(id) {
  function inner() { return id; }
  return inner;
}
```

Даже откладывая AST функции `inner`, PreParser отслеживает значимые **объявления и ссылки на переменные**. Это позволяет полному парсеру `outer` корректно разместить переменные и обнаружить конфликты. V8 сохраняет и компактные метаданные размещения, чтобы при позднем разборе `inner` не приходилось снова пре-парсить вложенные тела только ради восстановления решений внешней области видимости.

## Два исхода после первого прохода

Если `inner` **не вызвали**, её полное AST и байт-код могут так и не понадобиться за это исполнение. Если **вызвали**, V8 возвращается к диапазону исходника, полностью разбирает функцию и компилирует байт-код. За эту функцию заплатили и пре-парсингом, и полным разбором, но это **не универсальный штраф 2×**: PreParser дешевле, а затраты зависят от кода и пути компиляции. Ленивый парсинг обменивает часть поздней работы на меньшие начальные затраты времени и памяти для кода, который может не выполниться.

Современный V8 также избегает многократного пре-парсинга одной вложенной функции лишь из-за того, что внешние функции компилируются в разное время. Компактные метаданные первого прохода помогают пропустить вложенные тела при разрешении областей видимости. Это особенно важно для глубоко вложенных бандлов, где повторные проходы раньше накапливали стоимость.

## Когда жадный парсинг может помочь

V8 распознаёт некоторые **возможно немедленно вызываемые функциональные выражения** (PIFE). Выражение в скобках вроде `(function(){…})` намекает, что функцию могут скоро вызвать, поэтому V8 может разобрать и скомпилировать её жадно. Старый инструмент `optimize-js` использовал этот паттерн. Более поздние замеры V8 показали, что после улучшений парсера массовая расстановка таких обёрток даёт гораздо меньший выигрыш; лишняя жадная компиляция расходует память и может ухудшить старт. Прежде чем менять исходник или вывод сборщика ради этой эвристики, измерьте реальный стартовый путь.

```js
(function bootstrap() {
  startApp();
})();

function maybeLater() {
  showOptionalFeature();
}
```

Первая форма даёт парсеру ранний сигнал. Вторая подходит для ленивого разбора с учётом остальных решений V8. Скобки не меняют семантику JavaScript и не гарантируют ускорения.

<KeyTakeaway>Ленивый парсинг откладывает полное AST и байт-код функции. PreParser всё равно проверяет синтаксис и отслеживает объявления и ссылки, нужные внешним областям видимости. Невызванная функция избегает полной компиляции; поздний вызов оплачивает полный разбор. Синтаксис PIFE может подсказать жадную компиляцию, но массовое применение требует измерений.</KeyTakeaway>

<Recap lang="ru">
V8 может пре-парсить функцию вместо немедленного построения полного AST и байт-кода. PreParser проверяет синтаксис и ранние ошибки, записывает диапазон исходника и отслеживает объявления и ссылки на переменные, чтобы внешние области видимости верно разместили захваченные значения. Для `outer(id)`, возвращающей `inner`, это важно ещё до вызова `inner`: `id` должен пережить возврат во внешнем контексте. Невызванной `inner` может не понадобиться полная компиляция; при первом вызове V8 полностью разберёт и скомпилирует её. Второй проход добавляет работу, но его цена не универсальный множитель. Эвристика функции в скобках может сделать вероятный немедленный вызов жадным, а избыточная жадная компиляция расходует стартовое время и память. Следующий урок покажет байт-код, который после компиляции исполняет Ignition.
</Recap>
