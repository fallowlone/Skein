<Hook>
`find` находит файлы по метаданным — имени, размеру, возрасту. Но что если нужно найти файлы по тому, что *внутри* них? Какой исходный файл вызывает `getUserById`? Какой конфиг устанавливает `MAX_CONNECTIONS`? Это работа `grep`: он читает содержимое файлов строка за строкой и выводит каждую строку, совпадающую с шаблоном.

К концу урока ты будешь искать текстовые шаблоны в целых деревьях каталогов, управлять форматом вывода и использовать базовые регулярные выражения с grep.
</Hook>

<Goal lang="ru">
После этого урока ты сможешь запускать `grep -r` для поиска шаблона в дереве каталогов, добавлять `-n` для номеров строк, `-i` для поиска без учёта регистра, `-l` для вывода только имён совпавших файлов и `--include` для ограничения поиска конкретными расширениями файлов. Ты также сможешь писать простые регулярные выражения для grep.
</Goal>

<Step n={1}>
**Базовый `grep`: шаблон затем файл(ы).** grep выводит каждую строку в файле(ах), содержащую шаблон:

```bash
grep "error" app.log           # строки с "error" в app.log
grep "TODO" src/main.ts        # строки с TODO в одном файле
grep "timeout" *.conf          # поиск по всем .conf файлам в текущем каталоге
```

Шаблон по умолчанию — Базовое Регулярное Выражение (BRE). Для Расширенных Регулярных Выражений (ERE) добавь `-E`; для Perl-совместимых — `-P`.
</Step>

<Step n={2}>
**`-r` выполняет рекурсивный поиск в дереве каталогов.** Это флаг, который ты будешь использовать чаще всего в ежедневной работе:

```bash
grep -r "getUserById" src/       # поиск по каждому файлу под src/
grep -r "MAX_CONNECTIONS" /etc/  # поиск по всем конфигам под /etc
```

Формат вывода: `имя_файла:содержимое_строки`. grep следует символическим ссылкам с `-r` только при использовании `-R` (заглавная) в GNU grep; `-r` по умолчанию не следует ссылкам.
</Step>

<Step n={3}>
**`-n`, `-i`, `-l` управляют форматом вывода.**

- **`-n`** — добавляет номер строки перед каждой совпадающей строкой:

```bash
grep -rn "panic" ./logs/     # grep -r -n вместе; показывает файл:номерстроки:строка
```

- **`-i`** — поиск без учёта регистра. Находит `Error`, `error`, `ERROR`:

```bash
grep -ri "error" src/
```

- **`-l`** — выводит только имена файлов, содержащих совпадение (подавляет сами строки). Полезно, когда нужно знать только, какие файлы затронуты:

```bash
grep -rl "deprecated" src/     # какие файлы упоминают "deprecated"?
```

Флаги свободно комбинируются: `grep -rnil "TODO" .` — совершенно допустимо.
</Step>

<Step n={4}>
**`--include` и `--exclude` сужают набор файлов.** Без них `-r` ищет по каждому файлу, включая бинарные. Глоб `--include` сопоставляется с именем файла:

```bash
grep -r "import" src/ --include="*.ts"      # только TypeScript файлы
grep -r "password" . --include="*.{yml,yaml,json}"  # только конфиги
grep -r "debug" . --exclude="*.min.js"      # пропустить минифицированный JS
```

Глоб в `--include` обрабатывается grep, а не оболочкой — бери его в кавычки для надёжности.
</Step>

<Step n={5}>
**Базовые регулярные выражения в grep.** Шаблоны grep — не просто строки, по умолчанию это BRE:

| Метасимвол | Значение | Пример |
|------------|----------|--------|
| `.` | любой одиночный символ | `gr.p` находит `grep`, `grap`, `gr9p` |
| `*` | ноль или более предыдущего | `err.*or` находит `error`, `err0r`, `errXXXXor` |
| `^` | начало строки | `^import` находит строки, начинающиеся с `import` |
| `$` | конец строки | `};$` находит строки, заканчивающиеся на `};` |
| `[...]` | класс символов | `[Ee]rror` находит `Error` или `error` |
| `\b` | граница слова (GNU) | `\berror\b` находит `error`, но не `errors` |

Используй `-F` (фиксированная строка), когда не нужна интерпретация регулярных выражений — самый быстрый вариант для поиска обычного текста.

```bash
grep -rn "^import " src/ --include="*.ts"    # строки, начинающиеся с "import "
grep -rF "process.exit(1)" .                 # буквальная строка, без regex
```
</Step>

<WorkedExample lang="ru">
**Поиск всех использований устаревшей функции в TypeScript-проекте.**

Нужно найти каждый вызов `legacyFetch`, чтобы заменить его:

```bash
grep -rn "legacyFetch" src/ --include="*.ts"
```

Пример вывода:

```
src/api/users.ts:14:  const data = await legacyFetch('/users');
src/api/posts.ts:8:   return legacyFetch('/posts/' + id);
src/utils/http.ts:3:  export function legacyFetch(url: string) {
```

Три файла с номерами строк. Теперь выведем только имена файлов для планирования рефакторинга:

```bash
grep -rl "legacyFetch" src/ --include="*.ts"
```

```
src/api/users.ts
src/api/posts.ts
src/utils/http.ts
```

Передадим в `wc -l`, чтобы подсчитать количество затронутых файлов:

```bash
grep -rl "legacyFetch" src/ --include="*.ts" | wc -l
```

```
3
```
</WorkedExample>

<Inset kind="why" lang="ru">
**BSD grep (macOS) против GNU grep (Linux).** Они разделяют основные флаги (`-r`, `-n`, `-i`, `-l`), но отличаются в деталях:

- `--include` и `--exclude` работают на обеих платформах, но `--include-dir` — только GNU.
- `-P` (Perl-совместимые regex) — только GNU; BSD grep его не поддерживает. Используй `-E` (ERE) для переносимых расширенных шаблонов.
- Цветной вывод (`--color=auto`) работает на обеих, но умолчание отличается.

Для скриптов, которые должны работать на macOS, используй только BRE/ERE (`-E`) и избегай `-P`. Или установи GNU grep через Homebrew (`brew install grep`) и вызывай его как `ggrep`.
</Inset>

<Inset kind="mistake" lang="ru">
**Использование `grep -r` по большому дереву без `--include` захватывает бинарные файлы и работает медленно.** grep попытается прочитать каждый файл — скомпилированные бинарники, изображения, объекты `.git`. Добавь `--include` для ограничения текстовыми расширениями и `--exclude-dir=.git` для пропуска объектов системы контроля версий:

```bash
# Медленно и шумно: бинарные совпадения выводятся как "Binary file X matches"
grep -r "config" .

# Быстро и чисто
grep -r "config" . --include="*.{ts,js,json,yml}" --exclude-dir=.git
```
</Inset>

<Recap lang="ru">
`grep шаблон файл(ы)` выводит каждую строку, совпадающую с шаблоном. **`-r`** расширяет поиск рекурсивно по дереву каталогов; **`-n`** добавляет номера строк; **`-i`** делает сопоставление нечувствительным к регистру; **`-l`** выводит только имена файлов. **`--include="*.ext"`** сужает поиск до конкретных типов файлов — всегда используй с `-r`, чтобы избежать сканирования бинарников и `.git`. Шаблоны grep по умолчанию — Базовые Регулярные Выражения; добавь `-E` для расширенного синтаксиса или `-F` для поиска буквальной строки без regex.
</Recap>
