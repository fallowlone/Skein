<Idea>
Мы рассмотрим четыре небольших, но важных алгоритма:

1. **Линейный поиск** – просмотр списка от начала до конца, пока не найдём цель (или не дойдём до конца).
2. **Бинарный поиск** – многократное деление отсортированного списка пополам, чтобы сузить поиск цели.
3. **Пузырьковая сортировка** – повторный обмен соседних неупорядоченных элементов, пока список не станет отсортированным.
4. **Факториал (рекурсивный)** – вычисление n! = n × (n-1) × … × 1 с помощью функции, которая вызывает саму себя.

Для каждого мы напишем pseudocode, проследим на небольшом примере и проанализируем сложность.
Вид нескольких паттернов рядом помогает выбрать правильный инструмент позже.
</Idea>

<Code>
**1. Линейный поиск**
```
algorithm linearSearch(list, target):
    for i from 0 to list.length - 1:
        if list[i] == target:
            return i
    return -1
```

**2. Бинарный поиск** (требует отсортированного списка)
```
algorithm binarySearch(list, target):
    left ← 0
    right ← list.length - 1
    while left <= right:
        mid ← (left + right) // 2
        if list[mid] == target:
            return mid
        else if list[mid] < target:
            left ← mid + 1
        else:
            right ← mid - 1
    return -1
```

**3. Пузырьковая сортировка**
```
algorithm bubbleSort(list):
    n ← list.length
    repeat n - 1 times:
        swapped ← false
        for i from 0 to n - 2:
            if list[i] > list[i + 1]:
                swap list[i] and list[i + 1]
                swapped ← true
        if not swapped:
            break
```

**4. Факториал (рекурсивный)**
```
algorithm factorial(n):
    if n == 0:
        return 1
    else:
        return n × factorial(n - 1)
```
</Code>

<Trace>
Давайте проследим каждый алгоритм на крошечном входе, чтобы увидеть шаги.

**Линейный поиск** цели 7 в `[3, 5, 7, 2]`:
- i=0: 3==7? нет
- i=1: 5==7? нет
- i=2: 7==7? да → вернуть 2

**Бинарный поиск** цели 6 в отсортированном `[1, 3, 5, 7, 9]`:
- left=0, right=4 → mid=2 → list[2]=5 &lt;6 → left=3
- left=3, right=4 → mid=3 → list[3]=7 &gt;6 → right=2
- left=3, right=2 → цикл завершён → вернуть -1 (не найдено)

**Пузырьковая сортировка** проход по `[3, 1, 4, 2]`:
- Сравнить 3 и 1 → обмен → `[1, 3, 4, 2]`, swapped=true
- Сравнить 3 и 4 → нет обмена
- Сравнить 4 и 2 → обмен → `[1, 3, 2, 4]`, swapped=true
- Конец прохода (swapped=true, поэтому ещё один проход)
Второй проход:
- 1 и 3 → нет обмена
- 3 и 2 → обмен → `[1, 2, 3, 4]`, swapped=true
- 3 и 4 → нет обмена
Третий проход:
- 1 и 2 → нет обмена
- 2 и 3 → нет обмена
- 3 и 4 → нет обмена
- swapped остался false → выйти

**Факториал(4)**:
- factorial(4) → 4 × factorial(3)
- factorial(3) → 3 × factorial(2)
- factorial(2) → 2 × factorial(1)
- factorial(1) → 1 × factorial(0)
- factorial(0) → 1
Теперь разворачиваем: factorial(1)=1×1=1, factorial(2)=2×1=2, factorial(3)=3×2=6, factorial(4)=4×6=24.
</Trace>

<Complexity>
Посчитаем сложность для каждого алгоритма.

1. **Линейный поиск**
   - Время: худший случай мы проверяем каждый элемент → O(n)
   - Лучший случай (цель в первом индексе) → O(1)
   - Память: лишь несколько переменных → O(1)

2. **Бинарный поиск** (отсортированный список)
   - Время: каждый шаг уменьшает пространство поиска пополам → O(log n)
   - Память: итеративная версия использует O(1) дополнительной памяти

3. **Пузырьковая сортировка**
   - Время: худший и средний случаи O(n²) из-за вложенных циклов
   - Лучший случай (уже отсортирован) мы можем прерваться рано → O(n)
   - Память: лишь несколько переменных → O(1)

4. **Факториал (рекурсивный)**
   - Время: делаем n рекурсивных вызовов → O(n)
   - Память: каждый вызов добавляет фрейм стека → O(n) (хвостовая рекурсия не предполагается)
   - Примечание: итеративный цикл даст O(1) памяти.
</Complexity>

<Recap lang="ru">
Изучение этих четырёх алгоритмов закрепляет цикл решения задач: понимаем → pseudocode (или код) → трассируем → анализируем сложность.  
Линейный поиск прост, но сканирует весь список; бинарный поиск намного быстрее на отсортированных данных, но требует предварительной сортировки.  
Пузырьковая сортировка проста для понимания, но неэффективна для больших списков; факториал показывает, как рекурсия чисто выражает математическое определение, хотя и использует дополнительную память стека.  
Распознавание этих паттернов помогает выбрать правильный подход, когда вы сталкиваетесь с новой задачей.
</Recap>
