## 1. Что это

Публичный образовательный сайт по инженерии ПО: `https://fallowlone.com`
(рабочее имя бренда в интерфейсе — **open atlas**). Статический сайт, полностью
двуязычный (EN + RU, паритет 1:1 обязателен), собирается Astro в статический
HTML и раздаётся с Cloudflare Pages.

Не блог и не документация. Это **тренажёр**: у каждого урока есть теория,
диаграмма, практические задания с автопроверкой, интервал-повторение (SRS),
и связность через граф концептов (что во что упирается, что чем открывается).

Целевая аудитория двойная:
- владелец сайта учится по нему сам (это его основной учебный контур);
- сайт открыт публично как учебный ресурс.

Планка глубины: **middle+/senior**. Материал, читающийся как справочник API,
считается недостаточно глубоким; целевой тон — «разбор боевого инцидента».

## 2. Модель контента (главное, что нужно понимать)

Три уровня, снизу вверх:

| Уровень | Что это | Где лежит |
|---|---|---|
| **lesson** (урок) | один узкий сюжет, 1 MDX-файл | `site/src/content/lessons/{en,ru}/<track>/<NN-unit>/<NN-lesson>/index.mdx` |
| **unit** (юнит) | 4–8 уроков, одна тема | запись в `site/src/content/units.json` |
| **track** (трек) | 5–20 юнитов, целый курс | запись в `site/src/content/tracks.json` |

Фактические объёмы (проверено 2026-07-30):

- **44 трека**, **440 юнитов**, **4528 файлов уроков** = 2264 урока × 2 языка.
- Паритет EN/RU полный: нет ни одного трека с расхождением количества.
- **51 проект** (`site/src/content/projects/*.json`), из них часть с рабочим
  «верстаком» (workbench) — исполняемым скелетом кода и авто-проверкой.
- **1540 файлов практики** (`site/src/content/practice/`).
- Треки покрывают: математику и Base CS с нуля, алгоритмы, языки (go, python,
  typescript, js-engine), фронтенд (react, nextjs, browser, frontend,
  react-patterns), бэкенд (backend, node, nest, apis, queues), данные
  (databases, sql-postgres, data-engineering, caching), инфраструктуру (docker,
  ci-cd, aws, deployment, linux, cli, git), распределённые системы, безопасность
  (4 трека), наблюдаемость, производительность, system design, паттерны.

Маршрутизация: `/<lang>/learn/<track>/<unit>/<lesson>/`.

### Формат урока

`lessonType` во frontmatter выбирает скелет: `concept` | `coding` | `topic`.
Уроки линейные (Hook → Goal → Explanation → Visual → WorkedExample → Practice →
Check → Recap) с раскрывающимися вставками `<Inset>`, а не многоуровневые.
Обязательное во frontmatter: `slug`, `lang`, `track`, `unit`, `order`, `title`,
`summary`, `estMin`, `sources` (≥1 URL). Опциональное, но существенное:
`level` (zero|junior|middle|senior), `prereqs`, `mathPrereqs`, `concepts`,
`deepensInto`, `spiral` — из этого строится граф связей и планировщик.

## 3. Технический стек

- **Astro 6.3.5**, `output: "static"`, `build.concurrency: 1` (сериализованный
  рендер: ~4.2k страниц, при параллельном рендере билдер CF на 8 ГБ падал по OOM).
- **Preact 10** (`compat: false`) для интерактивных островов; **не React**.
- **Tailwind 3.4** (`applyBaseStyles: false`) + собственный слой токенов в
  `site/src/styles/tokens.css`. Tailwind — вспомогательный, не основной язык
  оформления; базовая типографика и цвет идут от CSS-переменных.
- **MDX** для уроков, **Shiki** для кода (двойная тема github-light/github-dark).
- **GSAP** для анимации (динамический импорт, только когда есть что двигать).
- Песочницы кода в браузере: **QuickJS (WASM)** для JS, **PGlite** для
  Postgres, **@xenova/transformers** для распознавания речи в English-модуле.
- **ts-fsrs** — алгоритм интервального повторения.
- **bun** — пакетный менеджер и раннер (не npm, не yarn).
- Хостинг: **Cloudflare Pages**, `pages_build_output_dir = "site/dist"`.
  Серверная часть — Pages Functions в `functions/` (сессии, GitHub OAuth,
  метрики в D1, KV-сессии, R2 для веса моделей). Security-заголовки ставит
  `functions/_middleware.ts`.

## 5. Что делает сайт умным (подсистемы)

Это не набор страниц, а связанные механизмы. Ломать по одному нельзя.

1. **Граф концептов** (`content/path/`) — 4700+ концептов, ребра
   внутри и между треками. Из него строятся: планировщик обучения, прогноз
   срока до цели, диагностика пробелов.
2. **Калибровка** (`/calibrate`) — адаптивное байесовское/IRT-размещение
   учащегося, 145 банков вопросов, 4 стадии, express/full-режимы.
3. **Планировщик** (`/roadmap`) — из цели и текущего уровня выдаёт что учить,
   в каком порядке, к какому сроку.
4. **SRS** (`/review`) — FSRS/SM-2, очередь повторений, счётчик «N due» в навигации.
5. **Практика** — типы заданий: `diagnose`, `fix`, `sandbox`, `incident`,
   `design`, code-review, live-debug. Проверка: заполнение пропусков (blanks),
   самопроверка по рубрике, или реальный прогон кода (`exec`).
6. **Прогрессия** — 25 уровней, XP, стрики, достижения, `/profile`.
7. **Готовность** (`/readiness`) — оценка «дошёл ли до senior-планки» с
   требованием доказательств (proven X/N).
8. **Проекты** (`/projects`) — 51 проект с этапами, рубрикой, эталонным решением;
   часть исполняется в браузере и проверяется CI.
9. **English-модуль** (`/english/*`) — отдельный курс английского для инженеров:
   грамматика (122 темы), чтение, письмо, речь (Web Speech / Whisper), словарь ~3.7k.
10. **Глоссарий** (`/glossary`) — термины с всплывающими определениями внутри уроков.

## 6. Контроль качества (что запускать)

```bash
cd site
bun install
bun run lint:src          # предметный линтер контента (секунды) — запускать всегда
bun run test              # vitest (НЕ `bun test`)
bun run verify:samples    # исполняет код-блоки, помеченные ```js run
bun run verify:projects   # прогон верстаков проектов
bun run build             # полный билд + пост-билд линтер
```

**Важно про билд:** полный `bun run build` рендерит ~4.2k страниц и локально
падает по OOM. Практика проекта: проверять изменения через `lint:src` + `test` +
поднятый dev-сервер с увеличенной памятью, а полный рендер оставлять CI:

```bash
NODE_OPTIONS=--max-old-space-size=10240 bunx astro dev --port 4399
# затем curl нужных страниц
```

Обычный `bun run dev` без флага падает по OOM на загрузке коллекции уроков.

Линтер контента (`src/lint/rules/`) проверяет: паритет EN/RU, наличие практики,
наличие источников, заглушки блоков, целостность связей графа, ссылки
retrieval-drawer, бюджеты текста, drill/lab/capstone, утечки CJK, зеркалирование
глоссария, reduced-motion. Он предметный — ошибки авторинга ловит, качество
разметки и вёрстки **не** проверяет.

CI (`.github/workflows/deploy.yml`) гоняет тесты и исполняемые примеры перед
билдом, умеет инкрементальный режим (пересобрать один урок на закешированный dist).

## 7. Как принято работать (сжатые правила)

- Никаких спекулятивных правок: менять только то, о чём попросили.
- Перед новым паттерном искать существующий — их много и они консистентны.
- Двуязычность обязательна: правка контента без пары EN/RU не проходит линтер.
- Токены вместо литералов: цвет/отступ/шрифт брать из `tokens.css`, а не
  вписывать hex или tailwind-палитру (`bg-emerald-50` и т.п.).
- Компоненты импортировать через `~/`.
- Перед финалом: типы, линтер, никаких `console.log` в продакшн-коде.
- Прогресс учащегося живёт в `localStorage` (плюс синхронизация в D1 при
  входе через GitHub) — гость должен работать без аккаунта.

## 8. Известные слабые места (состояние на 2026-07-30)

Полный разбор и статусы: `docs/audit/2026-07-30-markup-audit.md`.
Аудит вёрстки/семантики/доступности проведён 2026-07-30; 19 из 21 находки
исправлены в ветке `fix/markup-audit-2026-07-30`.

**Педагогика (2026-07-30, ветка `fix/markup-audit-2026-07-30`, коммит 913a29e1a):**

- Задания типа «предскажи → раскрой» больше не отдают эталон по одному клику.
  Порядок: записать свой ответ (сохраняется) → сравнить → честно себя оценить.
  Задача засчитывается только при «Попал»; «Частично»/«Не попал»/«Пропустил»
  оставляют её в очереди повторения. Это включилось сразу для 3134 заданий без
  правки контента. Логика в `PracticeSection.tsx` (`CommitReveal`) и
  `practice-state.ts`, поведение закреплено в `e2e/practice-commit-gate.spec.ts`.
- Чек-лист рубрики сохраняется и показывает покрытие (было: чекбоксы без
  состояния, ни на что не влияли).
- **Запускаемых проектов 51 из 51.** У каждого есть машинная проверка:
  `bun run verify:projects` требует, чтобы заготовка падала, а эталон проходил.
  Стеки: 49 bun-ts, 1 python (stdlib `unittest`), 1 go (`go test`). Два вида
  верстака: (1) классический — учащийся реализует ядро логики; (2) грейдер
  артефакта — верстак содержит проверяющий код, а учащийся кладёт свою работу в
  `artifact/` (unit-файл systemd, terraform-план, модель угроз, отчёт CSPM, план
  сети, запись авторизованного тестирования, досье system design, архитектурный
  документ, HTML-страницу).
- E2E больше не тестируют мёртвую pieces-модель: 9/9 зелёные (было 5/8, и
  локально набор вообще не стартовал из-за OOM в `webServer`).

Что осталось открытым:

1. **86 ключей `<Term>` отсутствуют в глоссарии** (≈470 вхождений, трек
   алгоритмов). Подсказка деградирует до простого выделения слова. Линтер
   предупреждает (`src/lint/rules/term-keys.ts`); нужна контентная работа —
   определения EN+RU.
2. **Разнобой breakpoint-ов**: 22 разных значения в медиазапросах (760, 720,
   880, 640, 860, 560, 480, 420, 1099.98…) без системы токенов.
3. **CSP описан дважды** — `site/src/lib/csp.ts` (в `<meta>`) и
   `functions/lib/response.ts` (в заголовке). Сейчас совместимы, но правка
   одного без второго тихо сломает WASM-песочницы или ослабит политику.
4. **~57 инфографик шире 2000px** — читаемы (рендерятся 1:1 с горизонтальной
   прокруткой), но читателю приходится далеко панорамировать; линтер
   предупреждает.
5. Заголовки внутри ссылок-карточек (44 на главной) — осознанный компромисс
   стандартного паттерна карточки.

Полезно знать при правках вёрстки:

- Ширину холста AntV задаёт **шаблон**, а `width` в `renderToString` игнорируется.
  Длинный верхний `desc` не переносится и растягивает холст (у RU-текста сильнее).
  Деревья «N ветвей × M листьев» верстать как `compare-hierarchy-row-*`, а не
  `hierarchy-tree-*`.
- `Infographic.astro` сам выбирает режим: ≤800px — масштабирование в колонку,
  шире — натуральный размер плюс скролл рамки.
- Токены `--muted` и `--muted-2` проходят WCAG AA; `--muted-2` был провальным
  (2.97:1) до 2026-07-30 — не откатывать.

Полезно знать при работе с проектами:

- Новый верстак = `projects-workbench/<slug>/{manifest.json, scaffold/, solution/}`
  плюс `"workbench": true` в JSON проекта. Стек задаётся в манифесте; список
  поддерживаемых — `STACKS` в `scripts/run-project-workbench.mjs` и зеркало
  `WORKBENCH_STACKS` в `src/lint/rules/capstones.ts` (правило проверяет, что файлы
  набора лежат там, где их ищет раннер: `scaffold/test/*.test.ts` для bun-ts,
  корень `scaffold/` для python и go).
- Для python-стека раннер выставляет `PYTHONDONTWRITEBYTECODE=1`: иначе прогон
  заготовки пишет `__pycache__`, а `cpSync` сохраняет mtime, и прогон решения
  подхватывает устаревший байткод.
- В грейдерах артефактов проверяющий код лежит только в `scaffold/`; в `solution/`
  — исключительно правильный артефакт. Иначе появляются две копии логики.
- Каждый грейдер обязан иметь тесты, доказывающие, что он ЛОВИТ конкретные дефекты,
  иначе он со временем начнёт отвечать «всё хорошо» на что угодно.
